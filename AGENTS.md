# GodSystem Repository Workflow

- This repository is the complete GodSystem source and may be cloned to any path. The Git worktree is the development source; any Zomboid `mods` or Workshop directory is only a deployment/test copy and must be rediscovered on the current machine.
- `GodSystem-main` is the sole development source. The old `GodSystem-UI-test` tree is retained under `C:\APPS\Pzmodproject\历史资料\旧版UI测试` for historical comparison only. The current worktree targets Project Zomboid B42.20.4 and is `42.20_3.18.5`: automated checks and Workshop test-copy deployment passed, while in-game acceptance remains open. The rolling ZIP targets the accepted 3.18.4 snapshot; individual SP/host/dedicated-server acceptance items not explicitly reported remain open in the handoffs. Read the current handoff entry and `docs/开发技术支援/README.md` before task-specific history.
- The modular ClientRuntime, ServerRuntime, and UI_Runtime architecture remains in use. Run `tools/tests/run_lua_tests.py` with the test-only `lupa.lua51` VM, `tools/tests/run_kahlua_tests.py` against the target game, and `tools/Test-GodSystem.ps1`; these do not replace target-patch SP/MP game testing.
- Do not use Superpowers skills for this project. Follow this file, the handoff documents, and the bundled `pz-mod-dev` skill directly.
- Equipment authority uses separate SP/MP world ModData keys; never rebuild levels from an item/client snapshot. The newer splash feature and utility generator still require real SP/host/dedicated-server validation; mock Lua and Kahlua tests do not establish native kill statistics, fluid interfaces, world-object sync, or multiplayer anti-cheat behavior.
- Keep Git `main` as the integrated source branch; the user explicitly approved integrating 3.18.5 into `main`. Preserve untested status in documentation: a GitHub push is not Steam publication or game acceptance. Do not reset to the older GitHub baseline.
- Read `docs/GodSystem_DevHandoff_CN/00_继续开发入口.md` and `docs/开发技术支援/工程速查.md` first, then open only the current task's relevant design, official-reference, or history documents. The committed architecture overview is `docs/开发技术支援/GodSystem_工程文档.md`; `.qoder/repowiki/` is local-only.
- Do not guess Project Zomboid APIs. Check the same-version vanilla Lua or decompiled Java first, then official migration material, then same-version reference MOD evidence.
- Before editing, trace the existing call path and define the smallest change and verification target. For bugs, preserve the reported stack trace and add a focused regression when practical.
- For UI work, read the current UI safety lessons in `03_开发经验与踩坑.md`. Main/overlay presentation and safe list primitives live in `GodSystem_UISafety.lua`; equipment lists must retain visible-row culling, geometric bounds, UTF-8 text fitting, and scrollbar synchronization. Test actual drawing coordinates and focus/reopen paths, not only widget creation or row counts.
- Native B42.20.4 `ISButton:setEnable` mutates its color tables. Give controls private copies of theme colors and test enable/disable side effects against the shared palette. Kahlua logs `error()` even inside `pcall`; normal business refusals return codes while preserving rollback. Keep CN/CH IGUI JSON, legacy txt and Lua fallback generated together; do not treat a native English fallback as a successful Chinese translation.
- Inspect `git status`, `git diff --stat`, and the focused `git diff` before committing.
- Run `tools/Test-GodSystem.ps1` before committing. It validates version metadata, the live sandbox schema, generated sandbox translations, module bootstraps, local requires, and UTF-8; run it with `-RequireLuaCompiler` on a machine that has Lua 5.1.
- Develop and verify in Git first. After automated checks pass, copy only packaged runtime files to the Workshop test directory and verify the deployed files. Normally wait for the user's game-test result before pushing a completed feature branch; an explicit request to synchronize a development branch can be fulfilled earlier, while keeping its untested status clear. Never treat a branch push as release acceptance.
- Git commits and tags are the primary development history. Do not create a rolling ZIP for every version unless the user explicitly requests one.
- Current workspace has `GodSystem-main`, `GodSystem-main.zip`, and a `历史资料` directory for obsolete test trees and notes. The historical copies are not development or deployment sources. Create or replace the rolling backup only when the user explicitly instructs it; do not create additional active MOD copies or backup archives during routine work.
- The current workstation keeps one rolling backup at `C:\APPS\Pzmodproject\GodSystem-main.zip`. Do not create, replace, or delete backups without explicit user approval; historical backup paths in old handoffs are not current targets.
- Keep generated CN/CH translations and the ASCII-only Lua fallback synchronized with their UTF-8 YAML source. `sandbox-options.txt` is the live sandbox schema; do not restore the retired `GodSystem_AdminConfig.lua` generator dependency.
- Keep project-specific Codex guidance in this repository. Use `tools/setup/Install-CodexSkill.ps1` on a new device to install the shared `pz-mod-dev` skill.
