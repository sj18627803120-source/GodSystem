# GodSystem 42.20.1.2 模块边界

## 目标

新架构采用轻量内核、独立功能模块和窄接口。新增代码放在各 Lua 作用域的 `GodSystem/` 目录中；旧的 `GodSystem_*.lua` 暂时作为迁移债务保留，不能作为新模块继续扩展。

## 依赖方向

```text
Core ───────┐
            ├─> Platform
            ├─> State ─> Services
            └──────────> Services ─> Features/<功能>

Core + Platform + State + Services + Features ─> Bootstrap
```

约束如下：

| 层级 | 可以依赖 | 不可以承担 |
|---|---|---|
| `Core/` | 仅 `Core/` | 商城、银行、任务、仓库、机器人等业务 |
| `Platform/` | `Core/`、`Platform/` | 具体功能规则 |
| `State/` | `Core/`、`State/` | 游戏事件注册、原始网络命令 |
| `Services/` | `Core/`、`State/`、`Services/` | 具体功能规则和游戏UI |
| `Features/<功能>/` | `Core/`、`Services/`、同一功能目录 | 其他功能的实现、旧 `GodSystem_Core/Server/UI` |
| `Bootstrap.lua` | 所有新架构层 | 具体业务计算 |

Feature 之间不直接 `require`。需要协作时，由 Bootstrap 注入对方公开接口，或通过事件、命令和状态窄接口通信。Feature 从 `context.events`、`context.commands` 和 `context.state` 获取基础能力，不直接接触平台实现。

## 平台边界

只有 `Platform/` 和 `Bootstrap.lua` 可以直接出现：

- `Events.*.Add/Remove`；
- `sendClientCommand`、`sendServerCommand`；
- `OnClientCommand`、`OnServerCommand` 等原始命令入口。

功能模块只能向事件网关订阅，或向命令路由注册处理器。这样可以集中控制生命周期、诊断、协议版本和异常隔离。

## 目录约定

```text
GodSystem/
├─ Core/                  通用结果、诊断、模块注册等无业务能力
├─ Platform/              PZ事件和网络等平台适配
├─ State/                 状态访问与版本化
├─ Services/              可复用的无功能归属应用服务
├─ Features/
│  ├─ Storage/            仓库自身实现与公开接口
│  ├─ Shop/               商城自身实现与公开接口
│  └─ ...                 其他独立功能
└─ Bootstrap.lua          组合根，只负责装配和启动
```

一个 Feature 对外只暴露 `public` 接口；内部文件可继续按 `Domain/Application/Adapters/UI` 拆分，但不能从其他 Feature 直接引用。

## 静态守门

运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\tests\Test-GodSystemArchitectureBoundaries.ps1
```

专项检查会：

1. 输出新架构全部 `require` 依赖清单；
2. 检查层级方向和跨 Feature 依赖；
3. 拒绝新模块引用旧 Core、Server、UI 入口；
4. 拒绝在 Core 放入业务；
5. 限制事件注册和命令网关的位置；
6. 检测新架构内部循环依赖；
7. 列出旧目录中的边界绕行点，但暂时不因此失败。

旧目录债务应按功能逐批迁入。每完成一个功能迁移，再把该功能纳入严格检查；不要用兼容包装把旧单体重新依赖回新架构。
