## 2. 问题现象

42.20 中 GodSystem 普通 UI 和主要业务功能正常，但下列实时绘制全部消失：

- 像素机器人本体（`GodSystem_Companion.lua` → `renderRobot`）
- 机器人粒子和攻击视觉（`GodSystem_CompanionVisual.lua` → `renderParticles`）
- 系统仓库连接模式标记（`GodSystem_StorageContext.lua` → `renderMarkers`）

新档、旧档及调整 Mod 加载顺序均无效，日志没有 GodSystem 绘制红字。

### 共同依赖链

```
Events.OnPreUIDraw
  └─ getRenderer()
       └─ renderer:renderline(texture, ...)
            └─ getTexture("media/textures/mask_white.png")
  └─ ISCoordConversion.ToScreen(x, y, z)
```

**结论**：`OnPostUIDraw` 在 LastStand 和 Tutorial 两种特殊游戏模式中活跃使用。在正常 Survival/Sandbox 模式中是否触发待验证。

#### OnRenderTick（3 处，均活跃）

| 文件 | 行号 | 用途 |

| `client/ISUI/ISServerDisconnectUI.lua` | 76 | 服务器断开 UI |

**结论**：`OnRenderTick` 是 B42.20 中**实际使用的渲染事件**，被多个客户端 UI 组件使用。`ISRemoveItemTool` 中用于 `sqFloor:setHighlighted(true)`，属于世界绘制操作。

#### OnRenderUpdate / OnPostRender / OnPostFloorSquareDraw / OnPostFloorLayerDraw

**Lua 中零使用**。四个事件在 Java 端定义，但游戏本体没有任何 Lua 代码注册它们。

## 4. 绘制依赖核查

### 4.1 `getRenderer()`

| 文件 | 用法 |
|------|------|
| `server/ISBuildingBlueprintManager.lua:39` | `local renderer = getRenderer()` |
| `server/NewSelectionSystem/GridSquareSelector.lua:56` | `getRenderer():render(tex, ...)` |

**结论**：`getRenderer()` 在 server/ 目录中可用，返回有效渲染器对象。GodSystem 在客户端调用 `getRenderer()` 同理可用。

### 4.2 `renderer:renderline` — **关键发现**

**游戏本体 Lua 中零使用**。在全部 `media/lua/` 目录中搜索 `renderline` 返回 0 个匹配。

游戏本体使用的渲染方法：
- `renderer:render(tex, x, y, w, h, r, g, b, a)` — GridSquareSelector
- `renderer:renderRect(x, y, w, h, r, g, b, a)` — ISBuildingBlueprintManager
- `renderer:renderPoly(...)` — ISBuildingBlueprintManager

**结论**：`renderline` 方法在 B42.20 中可能已被移除或重命名。GodSystem 在两个文件中使用了 `renderer:renderline`：
- `GodSystem_Companion.lua:1168`
- `GodSystem_CompanionVisual.lua:205`
- `GodSystem_StorageContext.lua:182`

这是导致绘制消失的**直接原因之一**。

### 4.3 `ISCoordConversion.ToScreen`

定义文件：`server/ISCoordConversion.lua`

```lua
ISCoordConversion.ToScreen = function(x, y, z, cz)
    if cz == nil then cz = 0 end
    local sx = IsoUtils.XToScreen(x, y, z, cz)
    local sy = IsoUtils.YToScreen(x, y, z, cz)
    sx = sx - getCameraOffX()
    sy = sy - getCameraOffY()
    return sx, sy
end
```

- 签名：`(x, y, z, cz)` — 新增第 4 参数 `cz`（默认 0）
- 返回值：`sx, sy`（屏幕坐标）
- GodSystem 调用方式：`ISCoordConversion.ToScreen(x, y, z)` — 3 参数调用，兼容（cz 默认 nil→0）

**结论**：`ISCoordConversion.ToScreen` 存在且签名向后兼容，GodSystem 的 3 参数调用不受影响。

### 4.4 `mask_white.png` 纹理

**游戏目录中不存在此文件**。在 `C:\APP\Steam\steamapps\common\ProjectZomboid` 全目录搜索 `mask_white*` 返回 0 个文件。

游戏本体中 `getTexture()` 的典型用法（`ContainerButtonIcons.lua`）：
```lua
getTexture("media/ui/Container_Cabinet.png")
getTexture("media/textures/Item_Coffin_Plain.png")
```

**结论**：`media/textures/mask_white.png` 纹理文件在 B42.20 中不存在。`getTexture()` 函数本身可用，但对该路径返回 nil。这是导致绘制消失的**直接原因之二**。

GodSystem 中纹理获取代码：
- `GodSystem_CompanionVisual.lua:281`：`cachedTexture = getTexture("media/textures/mask_white.png")`
- `GodSystem_StorageContext.lua:192`：`Context.lineTexture = getTexture("media/textures/mask_white.png")`

## 7. 推荐替代方案

### 7.1 事件替代

**推荐：`OnRenderTick`**

- **理由**：B42.20 中确认被多个客户端 UI 组件使用，触发可靠
- **风险**：`OnRenderTick` 每帧触发，需自行控制频率（GodSystem 当前已有 `requestAnimationFrame` 节流机制，可复用）
- **替代备选**：`OnPostUIDraw`（LastStand/Tutorial 使用，但普通模式待验证）

### 7.2 `renderline` 替代

**推荐方案 A：使用 `renderer:renderRect` 逐像素绘制**

```lua
-- 替代 renderline 的水平线绘制
local function drawHLine(renderer, x1, y, x2, r, g, b, a)
    renderer:renderRect(x1, y, x2 - x1 + 1, 1, r, g, b, a)
end

-- 替代 renderline 的垂直线绘制
local function drawVLine(renderer, x, y1, y2, r, g, b, a)
    renderer:renderRect(x, y1, 1, y2 - y1 + 1, r, g, b, a)
end
```

通用线条绘制（任意角度）：

```lua
local function drawLine(renderer, x1, y1, x2, y2, r, g, b, a)
    -- 使用 renderRect 逐像素模拟 Bresenham 算法
    -- 或直接使用 renderer:render() 配合 1px 纹理
end
```

**推荐方案 B：使用 `renderer:render` 配合 1x1 白色纹理**

```lua
-- 创建 1x1 白色纹理替代 mask_white.png
local whiteTex = getTexture("media/ui/Container_Counter.png") -- 临时借用已有纹理
-- 或
-- 在 Mod 中打包自己的 1x1 白色 PNG
```

### 7.3 `mask_white.png` 替代

**方案 A**：在 GodSystem Mod 中打包一个 1x1 白色 PNG 纹理，使用 Mod 相对路径加载

**方案 B**：借用游戏本体已有的小纹理（如 `media/ui/TargetPos.png`），但颜色偏差需在代码中补偿

**方案 C**：使用 `renderer:renderRect` 完全替代纹理线条绘制（推荐，不依赖外部纹理）

### 7.4 最小改动方案总结

| 组件 | 当前 | 改为 |
|------|------|------|
| 事件注册 | `Events.OnPreUIDraw` | `Events.OnRenderTick` |
| 线条绘制 | `renderer:renderline(tex, ...)` | `renderer:renderRect(...)` |
| 纹理 | `getTexture("media/textures/mask_white.png")` | Mod 内置 1x1 白色 PNG 或 `renderRect` |

## 8. 尚未确认的风险

| 风险 | 说明 |
|------|------|
| `OnPreUIDraw` 实际触发 | 需实机探针确认。可能仅在 debug 模式下触发 |
| `OnPostUIDraw` 普通模式 | LastStand/Tutorial 模式可用，普通 Survival 模式待验证 |
| `renderline` 是否存在 | 静态分析零使用，但 Java 端可能仍保留方法。需实机 `pcall` 测试 |
| `renderRect` 性能 | 替代 `renderline` 后，大量粒子/线条绘制可能影响帧率 |
| 纹理尺寸 | 借用的游戏纹理可能有尺寸限制，需测试 |
| 42.19 差异 | 无 42.19 文件，差异为推断。建议日后对比确认 |
| 多人模式 | 本分析仅针对单人模式，MP 客户端渲染可能需要额外验证 |
