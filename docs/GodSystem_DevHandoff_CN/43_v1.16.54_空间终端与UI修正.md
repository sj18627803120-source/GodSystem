# v1.16.54 空间终端与 UI 修正

## 实现摘要

- `GodSystem.SystemSpaceTerminal` 在物品脚本中同时声明 `BodyLocation` 和 `CanBeEquipped` 为 `GodSystem:GodSystemTerminal`，继续复用 `media/registries.lua` 的独立位置。
- 终端等级恢复为 Lv.1-8，最高容量49；删除未发布旧腰包别名、名称识别和 SP/MP 迁移代码。超过8的本地测试数据直接夹到8，不退款。
- YAML 实时文案统一为“系统空间终端”，重新生成 CN/CH、Items、Sandbox 和 ASCII-only Lua fallback。
- 主 UI 使用统一不可选行表；标题、说明、汇总、空状态和文本行不改变业务选择，也不绘制选中背景。
- 属性第二动作改为“升到下一级”，确认框按共享报价显示等级、XP 和费用，确认后仍由 SP/MP 原结算路径处理。
- 左侧导航先计算可容纳页数，再均衡分配每页项目，并平均使用上下翻页按钮之间的纵向空间。
- 守护和过载爆裂分别使用蓝白、红橙扩散环；特效触发时保存坐标，避免僵尸死亡后丢失。移除不存在的 `ISCoordConversion` Lua 模块引用。

## 根因

- 穿戴错误日志中的 `BodyLocationGroup.isExclusive: first is null` 和 `isMultiItem: location is null` 来自物品没有 `BodyLocation`，不是透明图片或 ClothingItem XML。
- 容量日志明确写出 `over maximum capacity of 50`；Lv.9-12 的 60/75/90/100 从未真正生效。
- 守护原实现没有写入视觉队列；过载只有实际伤害到副目标时才写入视觉队列，所以单目标攻击没有特效。
