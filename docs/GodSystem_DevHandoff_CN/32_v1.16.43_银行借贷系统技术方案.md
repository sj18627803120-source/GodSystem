# v1.16.43 银行借贷系统技术方案

## 目标

在现有银行页中新增借贷功能，定位为“救命钱”和高风险周转工具。玩家可以用借款支付治疗僵尸病毒等大额开销，但逾期会触发强惩罚和追债僵尸。

本方案只描述下一版本开发计划，当前未改运行代码。

## 已确认规则

- 初始额度：2000。
- 成长额度：每有效消费 100 系统币，增加 5 额度。
- 一次性还款：3 游戏天后到期，利息 5%。
- 分期还款：每 3 游戏天一期。
- 3 期：总周期 9 游戏天，总利息 10%。
- 5 期：总周期 15 游戏天，总利息 18%。
- 10 期：总周期 30 游戏天，总利息 30%。
- 逾期超过 10 游戏天触发信用破产。
- 信用破产惩罚采用重惩罚方案：清活期、清背包系统币、冻结贷款、成长额度清零、清空欠款、生成追债僵尸。
- 追债僵尸数量按破产时未还总欠款计算：每 50 系统币 1 只，最多 100 只。
- 追债僵尸从玩家 20 格外随机生成。
- 首版同一时间只允许存在一笔未结清贷款。
- 还款只从银行活期扣，背包现金需要先存入活期。
- 信用破产不清死期存款。
- 玩家死亡不会清空贷款，欠款仍然保留并需要偿还。

## 现有结构

当前银行已有结构：

- 客户端银行数据入口：`GodSystem.getBank()`。
- 客户端银行操作入口：`GodSystem.performBankAction(action, amount, termId, entryId)`。
- 多人服务端银行命令：`Commands.bank(_, _, player, args)`。
- 银行存款字段：`bank.current`。
- 死期字段：`bank.fixed`、`bank.nextId`。
- 死亡惩罚字段：`bank.lastDeathPenaltyHour`。
- 现有消费统计：`data.stats.spentPoints`。
- 当前活期已参与支付：`GodSystem.getSpendableBalance()` 和 `GodSystem.spendCurrency()` 已把活期加到可支付余额中。

借贷应沿用现有银行通道扩展，不新建第二套银行系统。

## 首版范围

首版只允许同一角色/账户同时存在一笔未结清贷款。

原因：

- 分期本身已经覆盖长期贷款需求。
- UI 不需要处理多笔贷款排序和多笔逾期选择。
- 多人服务端验证和破产清算更稳定。
- 后续如果玩家确实需要多笔贷款，可以在数据结构兼容的基础上扩展。

如果后续明确要多笔贷款，建议仍保留“逾期期间禁止新增贷款”。

## 额度计算

不要直接重置 `data.stats.spentPoints`。该字段已经被消费任务等功能使用，不能为了银行贷款清零。

建议新增：

```lua
bank.loanCreditSpentOffset = bank.loanCreditSpentOffset or 0
```

有效消费额度计算：

```text
有效消费 = max(0, data.stats.spentPoints - bank.loanCreditSpentOffset)
成长额度 = floor(有效消费 / 100) * 5
总额度 = 2000 + 成长额度
可借额度 = 总额度 - 当前未还本金
```

信用破产时：

```text
bank.loanCreditSpentOffset = data.stats.spentPoints
```

这样可以实现“成长额度清零”，同时不影响消费任务和历史统计。

## 数据结构

建议扩展 `bank`：

```lua
bank.loan = bank.loan or nil
bank.nextLoanId = bank.nextLoanId or 1
bank.loanFrozenUntilHour = bank.loanFrozenUntilHour or 0
bank.loanCreditSpentOffset = bank.loanCreditSpentOffset or 0
bank.loanBankruptcyCount = bank.loanBankruptcyCount or 0
```

贷款对象：

```lua
{
    id = "L1",
    kind = "single" or "installment",
    principal = 2000,
    createdHour = 1000,
    totalInterest = 100,
    totalDue = 2100,
    paid = 0,
    overdueStartHour = nil,
    bankrupt = false,
    schedule = {
        {
            index = 1,
            dueHour = 1072,
            principalPart = 2000,
            interestPart = 100,
            paid = 0,
        }
    }
}
```

一次性还款可以看成只有 1 期的 schedule。

分期贷款按本金和利息分别均摊，最后一期吃掉取整余数，避免总额因为四舍五入丢失。

## 借款流程

客户端 UI：

1. 玩家选择一次性或分期方案。
2. 输入借款金额。
3. 弹窗确认：借款金额、到账位置、总利息、总应还、还款日期/分期表、逾期破产惩罚。
4. 确认后发送银行命令。

服务端/单人本地：

1. 确认银行功能和贷款功能开启。
2. 归一化银行数据。
3. 检查贷款冻结时间。
4. 检查是否已有未结清贷款。
5. 计算总额度和可借额度。
6. 校验借款金额不超过可借额度。
7. 创建 `bank.loan`。
8. 将借款本金加入 `bank.current`，不生成实体现金。
9. 写入历史并刷新 UI。

借款不应增加 `data.stats.spentPoints`，否则会自己提高额度。

## 还款流程

首版只从活期还款。背包现金需要玩家先点“现金存入活期”。

原因：

- 自动还款不需要递归扫描背包。
- 多人服务端处理简单。
- UI 文案清晰：还款来源为活期。

操作建议：

- `repayDue`：偿还当前已到期/逾期应还金额。
- `payoffLoan`：提前一次性结清。

已到期或逾期的期数按原金额还款。

提前结清：

```text
已到期/逾期期数：本金 + 利息全额
未到期期数：本金全额 + 未到期利息 50%
```

如果活期不足：

- 手动还款直接提示活期不足。
- 自动扣款可以扣到 0，剩余继续逾期。

## 逾期与罚息

任意一期到期未还，记录 `loan.overdueStartHour`。

逾期期间：

- 禁止新增贷款。
- 打开银行、后台同步、银行关键操作时尝试自动从活期扣已到期金额。
- 显示逾期天数和预计破产剩余时间。

罚息建议保留为配置项：

```text
逾期罚息 = min(贷款本金 * 50%, floor(贷款本金 * 5% * 逾期游戏天数))
```

破产时的未还总欠款包含：

- 未还本金。
- 未还正常利息。
- 当前逾期罚息。

## 信用破产

触发条件：

```text
nowHours - loan.overdueStartHour >= 240
```

即逾期超过 10 游戏天。

触发后按顺序处理：

1. 计算破产前未还总欠款 `debtBeforeBankruptcy`。
2. 计算追债僵尸数量。
3. 清空 `bank.loan`。
4. 清空 `bank.current`。
5. 清空背包系统币。
6. 设置 `bank.loanFrozenUntilHour = now + 168`。
7. 设置 `bank.loanCreditSpentOffset = data.stats.spentPoints`。
8. `bank.loanBankruptcyCount += 1`。
9. 写入历史和通知。
10. 尝试生成追债僵尸。

死期存款首版不扣。理由是当前死亡惩罚也只扣活期，死期一直是银行保险性质；如果同时清死期，会破坏之前银行功能的预期。

信用破产才会清空欠款。普通死亡不清空贷款，死亡后欠款继续保留，仍会按原贷款到期、逾期和破产规则处理。

## 追债僵尸

数量：

```text
zombieCount = min(100, max(1, floor(debtBeforeBankruptcy / 50)))
```

落点：

- 玩家周围 20 到 45 格环形区域。
- 优先找可站立地面。
- 不在玩家当前房间内强刷。
- 找不到足够安全点就少刷，不硬塞。
- 建议分批生成，每批最多 10 只，避免一次性卡顿。

参考：

- RaccoonCityB42 服务端示例使用 `addZombiesInOutfit(x, y, z, count, outfit, femaleChance)`。

实施前仍要再检查同版本游戏本体或同版本 MOD 中对落点、楼层、房间和 chunk 加载的处理方式，避免把僵尸刷到不可达位置或玩家脸上。

## UI 方案

银行页保持一个页面，不新增左侧主导航。

银行列表建议显示：

- 顶部摘要：现金、活期、死期本金、贷款额度、当前欠款、冻结状态。
- 活期行。
- 死期档位和死期存款行。
- 贷款额度行。
- 一次性贷款方案行。
- 3/5/10 期分期方案行。
- 当前贷款详情行。

按钮动态复用现有 5 个动作按钮：

- 选活期：存入、取出、转死期、现金存死期、钱币整理。
- 选死期档位：存入、取出、活期转死期、现金存死期、钱币整理。
- 选贷款方案：借款、空、空、空、钱币整理。
- 选当前贷款：还本期、提前结清、空、空、钱币整理。

确认弹窗必须写清：

- 借款到账活期。
- 利息和总还款。
- 每期时间。
- 逾期超过 10 游戏天会清活期、清背包系统币、冻结贷款、清成长额度、生成追债僵尸。

## 多人模式

多人以服务端为准：

- 借款由服务端验证额度并写入 `data.bank.loan`。
- 借款本金由服务端增加 `bank.current`，再同步状态。
- 还款由服务端扣 `bank.current`。
- 破产由服务端清空活期、调用真实货币移除逻辑清背包系统币，并生成僵尸。
- 客户端只负责 UI 展示、输入和发送命令。

单人沿用客户端本地路径，但函数名和逻辑要尽量与服务端一致，避免 SP/MP 行为分叉。

## 自动检查时机

不要在 UI 每帧、列表绘制或鼠标悬停时结算贷款。

建议检查：

- 打开银行页。
- 执行银行关键操作前。
- MP 后台同步时。
- 玩家死亡事件中只做必要同步，不清空贷款，也不额外触发贷款破产，避免死亡和破产惩罚叠在同一 tick 造成不可控体验；欠款会在玩家重生后继续保留。

## 本地化

需要新增 CN/CH/override fallback：

- 银行贷款标题。
- 额度、可借、当前欠款、冻结剩余时间。
- 一次性贷款、3期、5期、10期。
- 借款确认、还款确认、提前结清确认。
- 活期不足。
- 贷款已冻结。
- 已触发信用破产。
- 追债僵尸数量。
- 管理员配置项中文名称和说明。

Lua fallback 仍优先使用 UTF-8 byte escape，避免 PowerShell 显示问题影响文件内容。

## 管理员配置

管理员菜单需要能调整：

- 是否启用贷款。
- 初始额度。
- 消费额度步长。
- 每步增加额度。
- 一次性贷款利息。
- 分期 3/5/10 总利息。
- 每期间隔小时。
- 逾期破产宽限小时。
- 贷款冻结小时。
- 逾期每日罚息。
- 逾期罚息封顶。
- 每多少欠款生成 1 只僵尸。
- 僵尸上限。
- 僵尸最小/最大生成距离。

不建议首版把“是否清死期”开放配置，避免银行规则变复杂。

## 风险与处理

- 刷僵尸接口和落点安全需要再查同版本本体/参考 MOD，不能猜。
- 一次生成 100 只可能卡顿，应分批。
- 贷款清算不要写在 UI 高频刷新路径。
- 不要重置 `data.stats.spentPoints`，否则消费任务可能异常。
- 背包现金清空只应移除 GodSystem 系统币，不应误删其他 MOD 钱币。
- 破产后清空欠款必须写历史，否则玩家会以为钱凭空消失。

## 最终确认规则

- 首版只允许一笔未结清贷款。
- 手动还款只从活期扣，背包现金需先存入活期。
- 信用破产不清死期存款。
- 玩家死亡不清空贷款，欠款依旧要还。

以上规则已确认，可以进入 v1.16.43 实施计划。
