# 待办与设计方向

优先级高：

- 以用户已测试成功的 v1.15.3 作为稳定基线。
- 后续实验版必须从当前稳定目录分出，不要直接覆盖稳定 zip。
- 每次开发前先确认 PZ 版本；当前目标是 B42.19。
- 如果有 B42.19 官方开发手册或官方示例，先参考官方同版本资料。
- 再参考 `C:\Users\Admin\Desktop\PJ\File` 下同版本同类 MOD 的代码、接口和脚本写法。
- 每次发现新知识、坑、接口、测试结论，都写回 `GodSystem_DevHandoff_CN`。
- 检查重复安装旧版导致的误报。
- 继续优化所有页面的动作栏，保证新增按钮不会挤在一起。
- 任务文本和详情文本继续做更稳的换行/滚动。
- 多人模式适配前，先以 `Server Shop\42.19` 为同版本参考，设计服务端权威命令层，不直接在现有客户端逻辑上硬接 MP。

优先级中：

- 多人模式分阶段方案：
- 第 1 阶段：新增 `media\lua\server\GodSystem_Server.lua` 和统一命令模块，只迁移高风险经济操作：商城购买、回收、腰包自动回收、任务奖励/惩罚、家园/临时传送扣费。
- 第 2 阶段：梳理实体系统币在 MP 下的服务端扣除/发放/同步，所有 `AddItem/Remove` 成功后调用对应同步 API。
- 第 3 阶段：将任务状态、解锁状态、升级状态、家园点等按账号持久化策略重新设计；确认用服务端 ModData、玩家 ModData，还是继续保留部分本地数据。
- 第 4 阶段：增加服务器审计日志，记录系统币变化、购买、回收、任务结算、传送扣费/失败、管理员修正。
- 第 5 阶段：开本地/联机服务器专项测试，重点测断线、死亡换角色、重登、多人同时购买/回收、延迟下连点。
- 商城分类继续汉化，减少英文分类残留。
- UI 大改优先用本地 HTML/CSS 原型 + 截图迭代；默认产物放在 `C:\Users\Admin\Desktop\PJ\GodSystem_UI_Prototype`，确认后再按移植规格改 PZ Lua。
- UI 设计工具优先选择可由 Codex 直接稳定控制的本地原型、截图验证、PNG/SVG 资源生成；Figma/Penpot 可作为人工协作工具，但不作为默认开发依赖。
- 如果重构商城/回收，参考 RuinBazaar 的 `Data + VendingManager + UI` 分离结构，但不要复制代码和素材。
- 天赋系统继续前，优先研究 `TraitsPurchaseSystem` 的接口和冲突处理。
- 抽奖解锁的分类价格和提示继续调手感。
- 任务类型扩展：移动距离、锻炼时间、建造、钓鱼、烹饪、探索等。
- 任务追踪 UI 增加折叠、拖动、透明度设置。
- 家园/传送页面增加更清楚的坐标显示和状态说明。
- 如果后续确认 `ISModalDialog` 实例换肤仍不够美观，再新增 GodSystem 专用确认弹窗类；不要全局 monkey patch 原版弹窗，以免影响游戏本体或其他 MOD。

优先级低：

- 安全区清僵尸暂时不做。原因是性能、边界显示、刷怪规则都容易复杂化。
- 僵尸无法进入安全区暂时不做。原因是需要持续干预 AI/寻路或区域逻辑，风险较高。
- 武器模型、贴图后续再做。当前以稳定功能为主。

设计原则：

- 先稳定，再好看，再扩展。
- 能用原版接口就不要模拟底层行为。
- 参考优先级按版本一致性决定；版本一致时官方资料最高。
- 能找到同版本官方/参考 MOD 实现，就先读资料再设计。
- 所有高风险功能必须有确认弹窗。
- 所有花钱功能必须明确显示费用。
- 所有可能失败的操作，失败时不扣钱。
- UI 新增控件必须走统一布局系统。
- 不把第三方参考 MOD 打包进 GodSystem，除非用户明确接受依赖且许可允许。
