# v1.16.61 商城身份与隐藏管理实现

## 基线与范围

- 基线：`fix/v1.16.60-carry-rounding@fb7f527`。
- 开发分支：`fix/v1.16.61-shop-visibility`。
- 设计提交：`f5587c9`；功能提交：`4bfc5aa`。
- 只修改商城身份、上架、购买、隐藏界面及相关多人同步；负重、终端、压缩、机器人、任务和经济数值保持不变。
- 目标游戏版本仍为 Project Zomboid Build 42.19；本版未合并 `main`，也未覆盖稳定包。

## 商品身份和旧存档迁移

- 普通物品产品键为 `fullType`。
- 家具产品键为 `fullType + "@worldSprite=" + worldSprite`，床两组件及不同货架贴图互不混淆。
- 商城配置条目继续通过配置 `id` 购买，同时为只有一个数量为 1 的内置单品建立产品键集合。
- SP `GodSystem.getData()` 与 MP `playerData()` 都调用同一归一化函数：旧记录缺少 `hidden` 时补为 `false`；与内置单品重复的玩家记录删除；相同家具变体重复键合并并保留隐藏意图；不同 `worldSprite` 不合并。
- 迁移只修正商城索引，不修改玩家物品、余额或历史金额，因此不退款。

## 上架和购买事务

- 原回收页单件“仅上架”现在传入具体 `itemId`。SP 和 MP 都按 ID 重新查找物品，并复验所有权、`fullType`、上架资格和真实家具贴图，不再从同类型物品中任取第一件。
- 内置商品、已正常上架商品和已隐藏商品均视为已经上架，不再收费。隐藏商品会提示到“隐藏管理”恢复。
- 单件上架先按活期/现金真实来源扣费，再提交新记录；提交失败按原来源退款，不留下免费记录。
- 商城购买继续使用配置 `id` 或 `unlocked_<variantKey>` 稳定定位。隐藏记录即使通过过期行发起购买也会被服务端拒绝。
- 家具通过实例级 `ReadFromWorldSprite()` 创建，加入背包后再次核对 `worldSprite`；创建、贴图核验或多人同步调用失败时移除本次发放物，扣币发生在全部发放成功之后。

## 隐藏管理

- `unlockedShopItems[variantKey].hidden` 是持久字段。玩家操作只切换该字段，不能删除已经提交的上架记录。
- 商城原“删除解锁”按钮改为“隐藏解锁”；玩家上架商品右键增加“隐藏该商品”；内置商城商品没有隐藏入口。
- “隐藏管理”弹窗只显示当前玩家的上架记录，不含内置商品。支持分类、全部/上架中/已隐藏状态及名称、`fullType`、分类、`worldSprite` 文本搜索。
- 筛选和搜索只遍历已同步记录，并只在打开、筛选、搜索或商城状态变化时重建；不扫描背包，不添加逐帧或分钟级商城扫描。
- 隐藏商品从商城主页、分类和搜索中排除；抽奖候选仍直接读取全部 `unlockedShopItems`，不会因隐藏而退出奖池。

## 多人兼容

- 新命令：`setShopItemHidden { variantKey, hidden }`。服务端只访问该玩家自己的持久数据，重复设置同一状态不重复写历史。
- 旧 `removeUnlocked` 命令保留，但只委托 `setShopItemHidden(..., true)`，不会删除记录。
- 每次隐藏状态结果都会回传完整服务端状态；两名玩家的数据以现有账户键隔离。
