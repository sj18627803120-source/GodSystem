# 多人传送备用路径

2026-09-16，用户明确要求无在线管理员时采用其他办法传送，继续保持纯 Lua。基于已发布 42.20_3.9 的当前开发目录修订，尚未部署、发布、提交或替换备份。

有可用权限执行者时仍走原版管理员指令。没有执行者时检查 EnableTeleportFallback（默认 true）：开启则把明确标记为 approvedClient 的请求发送给申请者本人；关闭则沿用无人执行的拒绝提示，不预扣费用。

目的地来自服务端存档。客户端只在用户名匹配、坐标合法、角色存活且不在车内时通过 B42JavaCalls 的显式 teleportTo 调用执行；补齐原生 userdata 桥接方法。该消息仅从现有 S2C 入口处理，旧的无标记直接位移消息仍拒绝。最近 64 个回执防重复移动。

后续用户要求：管理员路径也允许失败后切换备用。管理员发送失败、明确失败回执或 15 秒未到达时，若角色仍在线存活且开关开启，切换一次备用路径。沿用同一份预扣、目的地和原始返回点，不再次扣款；更换阶段请求 ID，移除旧执行者回执映射，并给备用阶段单独 15 秒。备用发送失败、失败回执或超时后退款，不循环尝试。会话改变或死亡直接取消。检查到达优先于失败/超时，避免已经到达却重试或退款。

ACK 成功不代表交易完成；服务端观察到位置后才计消费。失败按原银行/现金来源退款，断线退入账号银行。旧回执会被忽略，但已经提交到原版服务器的指令无法从 Lua 撤回；极端延迟下原版移动仍可能晚到，不能承诺完全杜绝迟到位移。

边界：同补丁 IsoGameCharacter.teleportTo 负责坐标和落点调整，但没有 GameServer.sendTeleport 的反作弊状态处理。本方案提高无管理员时的可用性，不承诺防踢。没有提升角色权限、关闭反作弊或增加原生依赖。备用方法以实际服务器测试为准。

自动验证：Lua 5.1 编译与回归、实际 Network 回调/原生 userdata 形态桥接测试、Kahlua 回归、静态/文本生成检查。覆盖管理员优先、开关关闭不扣费、无管理员备用发送、错误执行者回执拒绝、ACK 后继续等待位置、重复请求、超时退款及断线退款。

用户测试：管理员在线时回家/临时点/返回各一次；管理员离线并开启兜底后重测，观察是否踢出和重复扣费；关闭兜底后无人执行应拒绝且不扣费。被踢或超时后核对退款，保存服务器反作弊原因以便继续排查。
