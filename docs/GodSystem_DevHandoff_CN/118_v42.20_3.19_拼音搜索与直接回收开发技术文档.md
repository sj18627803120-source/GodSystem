# v42.20_3.19 开发技术文档：拼音搜索与外部物品直接回收

日期：2026-09-28。状态：方案，尚未实施。基线为 `42.20_3.18.5` 工作树，目标游戏为 Project Zomboid B42.20.4。3.18.5 的实机验收状态仍按交接 117 记录。

## 一、目标与已确认规则

1. 神级系统内所有**搜索用途**的输入框保留原有中文、英文、完整类型匹配，同时支持无声调全拼和首字母。例如“垃圾袋”可由 `lajidai`、`ljd` 找到。数量、价格、改名和备注输入框不是搜索框，不改其含义。
2. 手动回收玩家正常可访问的外部物品时，直接由权威端从原来源回收并结算；不先搬入背包，也不保留原版搬运等待时间。范围包括地面散落物、世界容器、尸体容器和车辆容器。背包回收继续保持现有业务规则。
3. 保留回收资格、价格、每日限制、非空容器确认、回收并上架／只上架、操作回执与旧存档身份。客户端提供意图和定位线索，物品及访问权由服务端重新核验。

## 二、Everything 技术的适用边界

voidtools Everything 首次从 NTFS MFT 建立文件索引，再用 USN 日志跟踪文件变化。这解释了它的本机文件搜索速度，但 MFT／USN 不包含 Project Zomboid 运行期的商品、物品名称或玩家容器状态，不能直接接入 MOD 搜索，也不能解决回收交易问题。参考：[voidtools 对 MFT／USN 的说明](https://www.voidtools.com/forum/viewtopic.php?t=12779)、[官方使用说明](https://www.voidtools.com/en-us/support/everything/using_everything/)。GitHub 上的 [ES](https://github.com/voidtools/ES) 与 [everything_sdk3](https://github.com/voidtools/everything_sdk3)是查询 Everything 的工具／IPC 封装，并非供 MOD 使用的物品索引器。

本版借鉴的原则是：**目录构建时生成检索键，搜索时只比较已有键；源数据变化时定向失效。** 不安装 Everything，不访问 NTFS 底层接口，不增加玩家或服务器的外部程序依赖。

## 三、现有目录审查与复用边界

| 模块 | 当前职责 | 本版处理 |
|---|---|---|
| `GodSystem_ItemCatalog.lua` | 枚举脚本物品；物品配置、范围筛选及转换关系候选框已共用同一客户端实例 | 在分批构建及名称更新时生成拼音索引，不为各窗口再建完整物品表 |
| `GodSystem_ShopCatalog.lua` | 整合已配置／已解锁／管理员强制上架商品，处理类别、变体、排序、当前页与价格展示 | 保留独立目录，建商品行时生成展示字段的拼音索引；不强制加载全物品目录 |
| `GodSystem_ShopListingStore.lua` | 多人商品目录的分块传输和原子快照；区分“未知”和“确实未上架” | 保留独立传输状态，不和商城展示目录合并 |
| `GodSystem_LotteryItemCache.lua` | 在 SP／服务端提取类型、标签、抽奖资格并持久化 | 保留独立缓存及存储；不从客户端搜索目录同步整表给服务端 |
| `GodSystem_EconomyPolicy.lua` | 按经济版本缓存权威报价 | 不与搜索缓存合并；搜索结果绝不授权价格或交易 |

`ItemCatalog` 与抽奖缓存都可能调用 `getAllItems()`，但字段、运行端、有效期和持久化规则不同。尤其多人客户端与专用服务器无法共用一张 Lua 表。**不合并业务表**；先复用无业务状态的脚本物品读取／文本规范化能力，并测量实际构建成本。抽奖缓存命中已有本地文件时，也不会每次完整重建。

另有两个值得专项验证的现状：`ItemCatalog.Shared` 没有在多人会话重置时明确清空，若 Lua 环境持续存在，变体列表可能沿用上一会话；`ShopListingStore.step()` 从队列首位反复 `table.remove(..., 1)`，会搬移余下元素。两者先加生命周期及规模测试，再决定是否在本版做最小修正；不得借拼音功能重构商品同步协议。

## 四、拼音检索实现

### 数据与共享接口

- 开发阶段从**固定版本**的 [Unicode Unihan](https://unicode.org/reports/tr38/)生成精简的“汉字码点 → 默认普通话读音”Lua 表，去除声调。记录数据版本、输入 SHA-256、生成命令，并保留 [Unicode 数据许可](https://www.unicode.org/copyright.html)声明。游戏运行时只读取打包的 Lua 表，不联网、不运行 Python、不扫描配方。
- 新增共享纯 Lua 5.1 模块，提供 `buildIndex(fields)`、`normalizeQuery(query)`、`matches(index, query)`。索引包含各字段的原文小写、连续全拼、连续首字母；**各字段独立匹配**，避免两个无关字段拼接成虚假命中。ASCII 不区分大小写，拼音查询可忽略空格。无效 UTF-8 或未收录汉字保留原有文本搜索，不抛错。
- 多音字先采用 Unihan 默认读音；对实际出现的常见物品名增加小型词组覆写。不要宣称任意多音词均可检索。查询和索引都不写入存档。

### 接入和失效

- 覆盖商城、终端回收、范围筛选、技能、说明书、隐藏商品、管理员物品配置、转换风险列表及来源／产物候选框。逐一替换各处直接 `string.find` 的搜索匹配，但保持原有结果范围、分类和排序。
- `ItemCatalog` 每次分批添加行时生成拼音键；显示名称因语言变化而刷新时同步重建对应键。`ShopCatalog` 每次生成商品行时生成键，继续遵守每步最多 50 条、约 2 毫秒的现有预算；价格和钱包变化只失效报价，不重建检索键。
- 抽奖候选、价格缓存和多人商品同步表不承载拼音键。相同名称的转换可在共享模块内做**会话级、有上限的按需复用**；不能为了复用而触发全物品目录构建或保留无限输入缓存。先测量行内索引的成本，再决定复用缓存上限。
- 多人的转换风险列表目前在服务端过滤，服务端使用同一共享匹配规则；客户端仍发送原查询。其余纯展示搜索留在客户端，不增加逐键网络消息。绘制函数不做转写或索引构建；输入停止约 250 毫秒后执行筛选。

先对 100／500／2000／5000 条目录记录建索引、筛选和翻页时间、每次处理条数及内存变化。若预计算后的线性筛选满足现有交互预算，本版**不引入倒排索引**；倒排索引只在相同数据的实测表明筛选仍明显卡顿时另行设计。

## 五、外部来源直接回收

### 当前问题路径

`GodSystem_RecycleContext.lua` 对外部物品先创建 `ISInventoryTransferAction`，队列结束后 `Context.execute()` 只在玩家背包索引中找选中 ID；服务端 `recycleSelectedInternal()` 也只查背包。故“物品已捡起，但随后未回收”与现有实现相容。尚缺玩家当次多人日志，不能把具体竞态定为已复现根因。

### 请求和身份

- 保留旧 `itemIds` 协议及旧指纹，确保背包操作和既有回执兼容。新请求设 `selectionVersion = 2`，按来源分组发送来源种类、地块坐标、必要的车辆部件／嵌套容器定位线索，以及该组物品 ID；支持一批中混合背包和多个外部来源。不要把整件物品或客户端价格发往服务端。
- 服务端按来源附近的已加载对象重新找**同一物品 ID**，并确认它仍位于请求时的来源。地块、部件、容器路径仅用于缩小查找，不能代替身份或访问权核验。重复 ID、超出协议边界、来源歧义或加载失败均在修改前拒绝。
- 新版指纹规范化来源及物品 ID，纳入模式、非空容器确认和内容签名；超过现有 2000 件阈值时沿用有界流式双哈希。相同操作 ID 和相同请求返回原回执；复用操作 ID 改变来源或内容时拒绝。旧指纹字节格式及旧长回执惰性转换保持原样。

### 权威验证与提交

服务端先完整预检整批：玩家在线、同楼层且可触及；来源仍存在；世界物品、容器、尸体或车辆部件能由服务端确认；安全屋及锁定／移除权限允许；选中物品仍在原处；非空容器内容签名、资格、价格和上架模式重新计算。任一身份或权限失败时**整批不修改**，并返回具体原因。不能用客户端当前打开的容器界面代替服务端权限判断。

交易顺序为持久化 `processing` → 全量预检 → 按来源移除并逐件核验缺席 → 发放系统币和必要上架结果 → 持久化 `done` 回执 → 同步结果。普通容器、车辆容器和地面世界对象分别采用同补丁已验证的移除与同步接口；记录原容器／地块、物品实例和必要的装备状态，用于逆序原位恢复。发钱、移除或同步过程异常时，只有确认原物品及账户恢复成功才能报告普通失败；状态无法确定则记为 `unknown`，不能允许自动重复结算。两名玩家争同一件物品时，后提交者必须因原位复核失败而不能再获款。

**原生接口门槛：**实现前先在 B42.20.4 核实 `getWorldItem`、地面移除与原位恢复、容器／车辆同步及访问权检查可由 Kahlua 稳定调用。某类来源若无法证明权限、原位恢复或 MP 同步安全，该类不启用直接回收，记录具体阻碍；不以直接删物品加钱冒充已完成。

1. 记录现有目录／搜索基线与外部回收调用路径；验证上述原生方法和各来源的正常访问判断。
2. 实现固定版本拼音数据生成器及共享匹配器，接入已共享的全物品目录，再接入商城、其他短列表和服务端管理员关系搜索。
3. 实现新选择协议、来源定位和各来源移除／恢复适配器；SP 与 MP 共用结算规则，保留旧背包路径和回执兼容。
4. 加专项测试：全拼、首字母、中英文名称、多音词、模组物品、语言切换、跨会话目录；背包／地面／世界容器／尸体／车辆／嵌套容器／混合选择；选中后移动、距离变化、锁定、安全屋、重复请求、断线、失败回滚与双人争用。
5. 记录 1／200／201／1000／10000 件回收及 100／500／2000／5000 条目录的调用量、耗时和消息量。稳定空闲状态不新增世界扫描或网络消息；展示缓存不参与授权。
6. 完成 Lua 5.1 编译、Kahlua 行为回归、`pwsh tools/Test-GodSystem.ps1`、CN／CH／EN 与 fallback、本地化生成和包结构检查。统一版本为 `42.20_3.19`，更新说明书、版本记录与交接入口。自动检查及关键接口验证通过后部署 Workshop **测试副本**并逐文件核对，等待 SP／房主／专用服实机验收；不发布、不提交 Git、不覆盖已验收备份。

自动测试不能代替原生对象恢复、权限或多人同步验证。玩家原报告的具体失败原因仍需发生当次的日志或可复现步骤才能最终确认。
