# v42.20_3.1 汉化、任务沙盒与功能入口修复

日期：2026-09-05。版本保持 `42.20_3.1`，仍为未发布开发版。

## 本轮目标与结论

1. GodSystem 自身补齐全部脚本物品的 CN/CH 名称与 Tooltip，不再依赖其他汉化 MOD 恰好补全系统币或抽奖券。
2. 任务沙盒设置改为真实参与运行时计算；每日数量、同时上限、刷新费、统一时限基准、奖励倍率和罚金倍率均有明确行为。
3. 沙盒关闭功能后，主 UI 对应页面或子功能块隐藏；底层操作仍保留功能开关复验。

## 汉化修复

- YAML 补齐 `GodSystem_Items.txt` 中 18 个物品的名称，以及脚本引用的全部 13 个 Tooltip；保留内部 `StorageController` 的名称与说明，因此生成结果当前为 19 个 ItemName、14 个 Tooltip。
- 重新生成 CN/CH `ItemName.json`、`Tooltip.json`、旧式 `Items_*.txt`，并由同一生成器同步 `GodSystemFallbackItems` 的 ASCII 十进制字节回退。
- 生成器现在直接解析物品脚本。以后出现“脚本新增物品或 Tooltip、YAML 未补”的情况会直接失败。
- `Test-GodSystem.ps1` 同样逐项检查 CN/CH JSON，避免只在作者本机因第三方汉化覆盖而看起来正常。
- CN 与 CH 继续生成相同的简体中文内容，这是项目既有的双语言代码兼容策略；没有修改游戏语言或第三方汉化 MOD。

## 任务沙盒修复

旧实现把 `upgrades.maxActiveTasks/dailyTaskCount` 当绝对值保存，并用它们托底沙盒基础值，所以把沙盒数量调低不会生效。现改为：

`实际上限 = min(代码最大值, 沙盒基础值 + 新购买升级增量)`

- 新结构使用 `maxActiveTaskBonus`、`dailyTaskBonus` 和 `taskLimitSchema=2`。
- 需求方明确不需要保护旧存档任务升级，因此首次读到旧绝对字段时直接把两个新增量重置为 0，不猜测旧值中哪些来自购买、哪些来自旧沙盒值。
- `DailyTaskCount=0` 表示不生成待接任务；`MaxActiveTasks=0` 表示不能接取。之后购买的对应升级仍可在沙盒基础上每级加 1。
- `RefreshTaskCost` 下一次手动刷新立即使用新费用。
- 所有模板时限按 24 小时基准整体平移：24 保持原模板值，沙盒每增减 1 小时，每个新任务的模板时限也增减 1 小时；存活任务不会被压到低于自身目标。
- 每日数量、时限基准、奖励倍率、罚金倍率或任务开关变化会改变生成令牌；即使仍是同一天，也会保留进行中任务并重建未接任务。已接任务的既有时限、奖励和罚金不被改写。
- MP 客户端收到服务端运行配置后，不再因打开 UI 或读取本地数据而用本地 `SandboxVars` 覆盖服务端快照。
- 任务关闭时停止生成、自动领取和 SP 超时判定；MP 命令继续由服务端拒绝，击杀同步仍可正常发放击杀币但不推进任务。

## 功能入口隐藏

- 主导航分别绑定 `EnableTasks/Shop/Recycle+RangeRecycle/Bank/Teleport/Traits/Attributes/Companion/Equipment`。
- 当前页面被服务端快照关闭时，主窗口自动切换到第一个仍可见的普通页面，避免留下空白或可操作的隐藏页。
- `EnableBankLoan=false` 时隐藏贷款汇总、当前贷款和贷款方案；`EnableBankInvestments=false` 时继续隐藏三档理财账户。
- 快捷窗只显示仍启用的回家/返回或存现金操作；银行与传送都关闭时隐藏快捷入口并关闭已打开的快捷窗。
- 任务关闭时隐藏任务页和任务追踪器；商城关闭时关闭单独打开的隐藏商品管理窗。
- `EnableAutoLoaderShop` 继续通过商品自身 `featureKey` 隐藏装填机商品，不影响已经持有的装填机。
