# v1.16.47 修复组件与耐久强化核心

## 版本边界

- 基于用户已测试正常的 v1.16.46 开发。
- 新增两件一次性道具，不改现有商店、回收、任务、银行、传送和天赋规则。
- `系统修复组件` 默认售价 300，`耐久强化核心` 默认售价 1200，均直接进入初始商店并排除出抽奖。

## B42.19 耐久接口结论

同版本游戏本体确认：

- `getCondition()` / `getConditionMax()` / `setCondition()` / `setConditionMax()` 负责物品实例的主体耐久。对 B42 组合武器而言，这一层也承担握把/主体耐久。
- `hasHeadCondition()` 为真时，可用 `getHeadCondition()`、`getHeadConditionMax()` 和 `setHeadCondition()`处理独立刀头、斧头或锤头耐久。
- `hasSharpness()` 为真时，可用 `getSharpness()` 和 `setSharpness()`处理锋利度；原版管理面板将其范围定义为 0 到 1。
- 未在 B42.19 本体中确认到稳定的 `setHeadConditionMax()` 公开调用，因此本版不提高头部耐久上限。
- `OnBreak.lua` 可能在武器断裂时删除原物品并生成头部、握把等部件。原物品已不存在时，修复组件不会凭空重建武器。

- `media/lua/shared/Items/OnBreak.lua`
- `media/lua/client/ISUI/AdminPanel/ISItemEditPanel.lua`
- `media/lua/server/Vehicles/Vehicles.lua`

## 实现结构

- `GodSystem_Maintenance.lua`：共享能力检测、状态快照、修复、强化、验证和回滚。
- `GodSystem_MaintenanceContext.lua`：库存右键菜单、确认弹窗和单人事务。
- `GodSystem_Network.lua`：多人发送 `useMaintenanceItem`，携带消耗品 ID、目标 ID 和 action。
- `GodSystem_Server.lua`：服务端重新验证真实消耗品、当前主手物品和 ID，执行共享事务并同步物品字段。

修复规则：

- 主耐久恢复至主耐久上限。
- 存在头部耐久时恢复至头部上限。
- 存在锋利度时恢复至 1.0。
- 目标已满、右手为空、接口不支持或执行失败时不消耗道具。

强化规则：

- 最大主耐久增加 2。
- 当前主耐久增加 2，但不超过新上限。
- `3/10` 强化后为 `5/12`。
- 不修复头部耐久和锋利度，不增加头部耐久上限。
- 不设玩法次数上限，只保留 Java 整数溢出保护。

## 商店与抽奖

- 两件道具加入 `GodSystemConfig.ShopItems` 的工具分类。
- 两件 fullType 同时写入实际物品购买价表，确保 `getItemBuyPrice()` 返回 300/1200；仅填写 `ShopItems.price` 不足以覆盖现有购买价调用链。
- 加入 `AutoShopBlacklist`，避免回收后生成重复的解锁商城条目；仍允许正常回收出售。
- 新增 `LotteryBlacklist`，单人 `gsLotteryAddCandidate` 和多人 `lotteryAddCandidate` 都必须执行该表。
- 现有管理员物品覆盖仍可按 fullType 调整价格与启用状态。

## 本地化与资源

- YAML 源扩展为同时维护 UI 键、`ItemName_*` 和 `Tooltip_*`。
- 生成器同时更新 CN/CH `IG_UI`、旧式 CN/CH `Items`、B42.19 官方格式 `ItemName.json` / `Tooltip.json` 和 ASCII-only Lua fallback。
- 两张 32x32 透明 PNG 由 `generate_godsystem_maintenance_icons.py` 可重复生成。
