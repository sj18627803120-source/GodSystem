## 最终定价顺序

```text
物品 fullType / 当前实例
        │
        ├─ 定价表有精确价格 ──────────────┐
        │                                  │
        └─ 没有精确价格 → 系统识别分类价 ─┤
                                           ↓
                         检查单物品转换规则
                         ├─ 无转换：保留上方参考价
                         ├─ 确定产物：产物回收合计 × 1.10
                         │              与参考价取较高值
                         └─ 动态且无法确定产物：
                              ├─ 有精确价格：保留精确价格并提示未验证
                              └─ 无精确价格：与 550 风险底价取较高值
                                           ↓
                               最后应用管理员覆盖
```

关键边界：

- 未收录第三方物品的完整实例回收价仍固定为 1，破损或剩余量状态可以继续折价但不会产生负值。
- 普通未知 Mod 物品没有检测到转换时，商城价按系统分类表处理，例如食品 80、材料 90、工具 220、武器 600，不再统一 550。
- `Base.MoneyBundle` 有明确的一对多转换，100 张钞票回收合计为 100，加入 10% 余量后自动售价保持 110。
- 只有一个被消耗来源的 Recipe 才进入拆包分析。多材料合成不会把每个原料误标为可拆包风险物。
- 物品脚本自身的 `getLuaCreate` 仅表示创建回调，不证明该物品能被拆开，因此不再单独触发 550。
- 动态单物品转换仍显示“未验证”。如果该物品已经有精确定价，保留精确定价且不套用通用 550；管理员仍可根据实机产出调整。

## 管理员界面

`管理 → 物品经济配置` 保留搜索、分页和详情。以下七组按钮全部从“每点一次循环到下一个值”改为“点击后展开所有选项，直接选择”：

1. 分类筛选。
2. 安全状态筛选。
3. 商城状态筛选。
4. 覆盖状态筛选。
5. 当前物品商城模式。
6. 当前物品回收模式。
7. 当前物品抽奖模式。

当前值在菜单中带勾选。筛选、搜索和分页仍只处理打开窗口时缓存的已加载物品脚本，不增加逐帧、周期性或背包扫描。

以后同类 UI 规则固定为：超过两个互斥选项时优先使用菜单、列表或弹窗直接选择，不再使用反复点击循环。

## B42.20 最小实测

1. 打开 `管理 → 物品经济配置`，依次点击七组选择按钮；每次应一次显示完整选项，选中后立即更新，不需要反复点。
2. 找一个未进入精确定价表的食品、材料、工具和武器，确认商城价分别接近分类参考价，完整物品回收均为 1，详情不显示 550 动态底价。
3. 购买并拆开 `Base.MoneyBundle`：商城价应为 110，拆出 100 张 `Base.Money`，全部回收得到 100。
4. 如果已安装带动态开箱/拆包的第三方 Mod，检查一个真实单物品动态 Recipe：没有精确定价时应显示未验证并使用至少 550；有精确定价时只提示未验证，不强制抬到 550。
5. SP 新档和 42.20.1.8 旧档各执行一次普通回收、回收并上架、仅上架、腰包回收和终端回收，金额与详情一致且无红字。

7. 商城购买、仅上架和智能回收连续点击或重试时，不得重复扣费、发物或发币。
