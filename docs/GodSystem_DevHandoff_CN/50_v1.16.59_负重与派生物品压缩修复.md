# v1.16.59 负重与派生物品压缩修复

## 范围

- 开发分支：`fix/v1.16.59-carry-compression`。
- 基线：`fix/v1.16.58-terminal-runtime@3b1de14`。
- 只修人物负重升级无法应用、部分物品重量无法压缩两项问题。
- 不增加容量绕过、专用存入菜单、空间仓库、UI 功能或经济调整。

## 人物负重

### 根因

`setMaxWeightDelta()` 写入成功后，`getMaxWeight()` 暂时仍可能返回人物更新前缓存的整数最终值。v1.16.58 在同一个 Lua 调用中立刻要求最终值精确命中，因此会把有效写入判定为 `verificationFailed` 并回滚。

### 修复

- 继续用 `maxWeightDelta` 保存 GodSystem 自身加成，不写 `maxWeightBase`。
- 移除自身上次倍率后，以 `floor(maxWeightBase × (1 + 外部倍率))` 计算外部基础。
- 目标倍率仍是 `外部倍率 + 等级×2 / maxWeightBase`。
- 倍率写入后调用实例 `setMaxWeight(外部基础 + 等级×2)` 刷新当前整数最终值，再读回验证。
- 任一步失败都恢复原倍率和原最终值，不扣币、不保存新等级。
- 旧错误三级 `98` 仍通过旧标记识别自身错误倍率，校准为原基础加 6。

## 派生重量物品

### 根因

普通物品的 `setActualWeight(x)` 与 `getActualWeight()` 通常一致；`HandWeapon` 会重写有效重量读取，木板属于该路径。v1.16.58 把 setter 输入和有效读回当作同一个值，因此会记录 `actualWeightMismatch` 并恢复。

### 修复

- 压缩元数据版本从 1 升到 2。
- 分别保存原始有效重量、原始 setter 输入、最后有效重量和最后 setter 输入。
- setter 输入优先从实例 `getWeight()` 读取，只在不可用时读取脚本定义的原始重量；脚本定义从不写入。
- 目标有效重量仍为 `原有效重量 × (1 - 压缩率)`。
- 先扣除 setter 输入之外的派生重量，再写实例；若读回仍有差异，按误差最多校正三次。
- 无法达到目标或低于 0.01 时恢复该件并跳过，不影响其他物品。
- 取出、回滚和终端清理使用保存的原 setter 输入与原有效重量恢复。
