# 42.20.2.3 沙盒提示格式修复

## 根因

`GodSystem.EconomyConversionSafetyMargin` 是 `double` 沙盒选项。CN/CH 的生成沙盒提示原来包含普通 ASCII `%`：

```text
默认 0.10，即 10%。
```

B42.20.1 原版在 `DoubleSandboxOption.getTooltip` 中把提示交给 Java `String.formatted`。`%` 后面的中文句号被当成格式转换字符，因此抛出 `UnknownFormatConversionException: Conversion = '。'`。堆栈落在 Vanilla 只代表原版显示层抛错，输入数据来自 GodSystem。

## 修复

- 版本：`42.20.2.3`。
- 本地化生成器在写入 CN/CH `Sandbox.json` 的 tooltip 时把普通 `%` 转为 `%%`，Java 格式化后仍显示一个 `%`。
- 普通 UI 翻译源和 Lua fallback 不改，避免玩家界面显示双百分号。
- 新增 `Test-GodSystemV422022.ps1` 断言，要求 CN/CH 经济 tooltip 包含 `10%%`，且不允许出现未转义 `%`。
- 不修改经济报价、管理菜单、协议、存档或其他运行逻辑。

## 自动验证

- 先在修复前运行回归，CN 沙盒百分号断言按预期失败。
- 生成器运行成功，CN/CH `Sandbox.json` 仅产生目标 tooltip 差异。
- `Test-GodSystemV422022.ps1` 及 `tools/Test-GodSystem.ps1` 通过。
- Lua 5.1、编码、本地化、参考研究和 `git diff --check` 通过后再同步 Workshop。

## 实机测试

1. 完全退出游戏后重新启动，进入新建或服务器设置页面。
2. 打开 GodSystem 的“经济设置”，悬停或查看“转换安全余量”提示；应正常显示 `10%`，不出现红字。
3. 继续打开其他 GodSystem 沙盒设置，确认整数、布尔和双精度选项提示均能正常显示。
4. 进入 SP 后打开系统面板，确认商城、回收、任务和终端基础入口仍可用。
5. MP 时由管理员打开服务器设置并让普通玩家加入，确认双方都无同类格式红字。
