# v1.16.58 终端减重与压缩实机反馈修复

## 范围与结论

- 开发分支：`fix/v1.16.58-terminal-runtime`。
- 基线：`feature/v1.16.57-carry-recycle@65a0d78`。
- 只修现有系统空间终端，不实现召唤式或跟随式空间仓库，不修改全局物品脚本重量。
- 目标游戏版本仍为 Project Zomboid Build 42.19；B42.19 SP/MP 实机通过前不得作为稳定发布版。

## 实机反馈与代码根因

### 减重升级满级仍为 50%

v1.16.57 只对 `terminal:getInventory()` 返回的内层 `ItemContainer` 调用 `setWeightReduction()`。终端物品本身是 `InventoryContainer`，人物装备负担路径还会读取外层物品的减重属性；物品脚本默认值为 50，因此只改内层不能保证人物负担采用升级值。

v1.16.58 对以下四组值都执行写入后读回核验：

- 外层终端容量与内层内容容器容量。
- 外层终端减重与内层内容容器减重。

任一容器属性无法写入或读回不一致时，升级保持事务失败且不扣费。升级页同时显示目标值和外层实际值，避免仅凭保存等级判断功能已生效。

### 多物品压缩失败且没有红字

旧流程使用保护调用写实例重量，单件异常不会产生游戏红字，但会使 `applyTerminal()` 返回失败，购买事务随后恢复快照。因此玩家只看到“物品多时升级失败”，无法知道是哪件物品不兼容。

新流程将容器属性失败与物品实例失败分开：

- 容器属性失败仍整笔取消，不扣费。
- 某件物品已有第三方自定义重量时跳过。
- 某件物品的实例写入异常或读回不一致时恢复该件并跳过，其余物品继续处理。
- 最近一次校准最多保存 5 条物品 ID、`fullType` 和原因；升级页显示处理、跳过、失败总数，点开状态行查看诊断。

### 新放入物品没有变化

实例重量写入顺序改为：

1. `setCustomWeight(true)`。
2. `setActualWeight(target)`。
3. 读回实际重量与自定义标记进行核验。

这样避免启用自定义重量标记时游戏重新载入脚本默认重量、覆盖刚写入的压缩值。SP 的 `OnContainerUpdate` 不再立即递归全库存，而只设置待校准标记；玩家更新的低频路径在约 60 tick 周期处理，并保留 300 tick 兜底。常规周期只比较顶层数量及首尾实例 ID 的常数级签名，不进行每帧递归扫描。MP 继续由服务端每 300 tick 权威校准并同步实例状态。

## 安全边界

- 只修改真实 `InventoryItem` 实例，禁止访问或改写共享 `ScriptItem`。
- 原重、原自定义标记、终端所有者和压缩版本继续写入实例 `modData`，移出终端时恢复。
- 遍历深度仍限制为 32，批次大小仍为 32；诊断详情上限为 5。
- 空间仓库路线没有进入本版代码。只有 B42.19 实机证明实例重量无法可靠影响终端容量或人物负担时，才重新评估场景容器方案。
