# 42.20_2.5 负重公式与重连修复

## 状态

- 目标游戏：Project Zomboid B42.20.2。
- 版本候选：`42.20_2.5`。
- 分支：`codex/fix-42.20_2.4-optional-java-method`。
- Mod ID：`GodSystem_CN`；Workshop ID：`3773949382`。
- 当前仍是本地测试候选，不合并 `main`，不覆盖稳定发布包。

## 本轮范围

1. 医疗收尾删除 B42.20.2 不兼容的 `setBandaged` 调用及对应桥接入口；其他医疗红字（`ReturnValues.put(...)`、`Thumpable.Thump(...)`）不在本轮范围。
2. MP 客户端在 `OnConnected` 和 `OnDisconnect` 重置 hello、待回包和状态标记，重连后重新握手并请求服务端状态。
3. 人物负重按 B42.20.2 本体公式重新应用：

   ```text
   nativeCapacity = max(0, floor(maxWeightBase * getWeightMod()) - strengthMoodles)
   nativeFinal = floor(nativeCapacity * nativeMaxWeightDelta)
   desiredFinal = nativeFinal + carryCapacityLevel * CarryCapacityPerLevel
   targetDelta = desiredFinal / nativeCapacity
   ```

   `strengthMoodles` 读取 HUNGRY、THIRST、SICK、BLEEDING、INJURED 五类 Moodle。应用时记录原版倍率和 GodSystem 写入标记，重复校准不会叠加；旧 `GodSystemCarryApplied*` 标记继续迁移。`setMaxWeight()` 只用于即时刷新和写后校验，不能作为持久事实。
4. 现有 60 ticks 玩家更新边界复用同一 `reconcile`：SP 本地、MP 客户端（收到服务端状态后）和 MP 服务端权威校准。升级页显示实时本体最终值、实际加成和最终负重。

本版不修改空间终端“减载”清理逻辑，也不处理前述两个未确认的医疗错误。

## 实机测试清单

### SP

- 新角色或备份存档：负重 Lv.1、Lv.2 升级，记录升级前后原版负重上限、系统页“基础/实际加成/最终负重”和实际物品栏上限。
- 分别在 neutral、Strong、Weak 状态下升级或刷新；改变饥饿、口渴、恶心、流血、受伤 Moodle，等待数秒后确认本体变化被保留且系统加成仍为等级对应的 `+2`。
- 退出、重新进入和角色死亡后确认等级、费用记录和最终上限不丢失、不重复叠加；升级失败或余额不足不扣费。

### MP 主机与远程玩家

- 主机和远程玩家各做一次负重升级、刷新和 Moodle 变化；确认服务端最终值与客户端页面一致。
- 连接后在收到首个服务端状态前不要把本地旧数据当权威；断线重连后确认 hello 重新发送、状态重新到达、负重再次校准。
- 服务器重启后重连，重复检查等级、实际最终上限、系统页显示和费用；确认没有重复扣费或重复叠加。

### 医疗与边界回归

- 执行感染检查、伤势治疗和病毒治愈，确认本轮不再出现 `setBandaged` 的 `No implementation found for function`。
