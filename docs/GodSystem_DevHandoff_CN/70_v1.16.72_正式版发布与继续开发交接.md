## v1.16.72 正式版包含内容

### 系统自动装填机

- 新物品 `GodSystem.SystemAutoLoader`，商城默认售价 1000、重量 0.5。
- 每台装填机按弹药 `fullType` 保存独立数字账本，每种默认上限 2000；管理员可配置 100-10000。
- “存入全部散装弹药”扫描人物主库存和嵌套容器，只接受 B42 注册标签 `ItemTag.AMMO`，跳过收藏弹药。
- 手动装填只处理随身独立弹匣，使用 `magazine:getAmmoType():getItemKey()` 匹配对应弹药，不修改枪械内置弹仓。
- 多台装填机按同弹种余额从低到高消耗；快速换弹动作队尾追加一次自动装填。
- 界面可查看账本、手动装填和一次取出 1-500 发；缺失 MOD 的弹药记录保留但不可取出。
- SP 使用共享本地结算；MP 由服务端按真实物品 ID、类型、容量和会话状态重新验证。

### 仓库正式行为

- 核心宿主本身也是普通网络容器；安装不要求家具为空，不再把储物格容量锁为 0。
- 旧 v1.16.70 容量锁宿主会一次性恢复原容量，同时保留有效核心身份。
- 仓库页为人物库存、网络仓库、详情三栏，支持人物主库存、已装备/手持容器和钥匙圈来源。
- 支持折叠组、Ctrl/Shift 多选、一个/一半/全部存取、当前来源“存入全部”和装备失败恢复。
- 人物长列表使用逐行 stencil 并在每行后 `clearStencilRect()`；重建时重置滚动状态，缩放后同步滚动条几何。
- 连接模式绿色表示核心宿主、蓝色表示已连通普通容器、红色表示已标记但未连通容器。
- 开启连接模式后立即刷新，之后每 5000ms 只刷新连通摘要；不会周期性重建仓库物品索引。
- 系统快捷栏末尾提供动态“开启/关闭连接模式”按钮。
- B42.19 Kahlua 不提供全局 `next()`；分类白名单路由使用 `pairs()` 判断是否存在规则。

## 下一位 Codex 的固定流程

1. 从 GitHub 拉取 `main`，确认 `git describe --tags --exact-match` 为 `v1.16.72`，或明确从该标签分支。
2. 阅读上述入口与当前任务相关文档，先查现有接口和调用链，不要猜 B42 API。
3. 为新版本建立独立分支；不要直接修改 `main` 或本地 Workshop 副本。
4. 修改前保存用户的实机堆栈和复现步骤；缺陷优先补最小运行时回归。
5. 先在 Git 工作树修改并运行统一测试，通过后才同步 `Contents`、`workshop.txt`、`preview.png` 到本地 Workshop。
6. Workshop 同步后做逐文件 SHA-256 比较；实机确认前不推送为正式基线。
7. 用户确认发布后，再合并 `main`、创建版本标签并更新本目录交接记录。

## 已知边界

- “正式版”由用户已发布并确认作为稳定基线；自动测试不能替代未来游戏补丁、第三方 MOD 或高并发服务器环境的回归。
- 自动装填机和仓库均保存真实实例/账本状态；后续协议变化必须保留旧存档字段和操作 ID 幂等语义。
- 不要恢复 v1.16.69 自制 Moveable 控制器、v1.16.70 容量锁宿主或旧 `safeAll` 存入路线。
- 不要把仓库索引、人物递归库存扫描、价格表重建或网络刷新放入逐帧 UI 绘制路径。
- 不要使用标准 Lua 存在但 Kahlua 缺失的全局函数作为运行时前提；新增调用必须以 B42.19 本体或实测为证据。
