# v1.16.53 空间终端、属性、车辆与同伴特效实现

## 实现范围

- `GodSystem.SystemSpaceTerminal` 使用 `GodSystem:GodSystemTerminal` 独立穿戴位置和透明 ClothingItem。旧前/后腰包只作兼容迁移类型，Lv.9-12 容量为 60/75/90/100。
- `GodSystem_Attributes.lua` 统一负责技能枚举、状态读取和报价。SP 在客户端结算；MP 通过 `attribute` 命令由服务端重新报价、扣款，并使用 B42.19 原版管理界面已验证的无倍率 `player:getXp():AddXP(perk, amount, false, false, false, false)` 后调用 `SyncXp()`。
- `GodSystem.SystemVehicleRepairModule` 售价 5000，排除抽奖和自动上架。`GodSystem_VehicleRepairContext.lua` 提供车辆右键确认，SP/MP 复用 `useMaintenanceItem`。
- 同伴数据新增 `effects.shock/corrosion/mark/chain/blast`。价格依次为 1000/2000/4000/8000/16000，全部应用同伴价格倍率并严格顺序解锁。

## 权威边界

- MP 属性只信任技能索引、模式和输入，服务端重新解析 XP 曲线与费用。
- MP 属性按稳定玩家标识与全局唯一 `opId`，在服务器 `ModData` 中持久化最近 64 个操作结果，状态包含 `processing`、`done` 和 `unknown`；服务器重启后遗留的 `processing` 会转为 `unknown`。每个 ID 绑定购买参数指纹，客户端只对参数完全相同的超时请求复用原 ID。扣款逐个验证实体系统币确实离开原容器，退款失败时把未恢复的等值金额兜底转入活期。
- 属性写入后按实际 XP 差额结算。`SyncXp()` 失败时保留已完成交易并写入 `attributeSyncPending`，下次 `hello` 重试同步，避免退款后留下免费 XP。
- MP 车辆修复验证真实模块 ID、车辆 ID、楼层和 4 米距离或乘坐关系；先耗材，再调用 `vehicle:repair()`，复查失败返还模块。
- 同伴仍为纯单人功能，不新增协议。普通直击可触发特效；灼蚀、连锁和爆裂只走统一伤害函数，不触发二次特效。
