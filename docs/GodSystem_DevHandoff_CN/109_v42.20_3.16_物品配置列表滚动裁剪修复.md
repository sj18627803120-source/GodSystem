## 根因

- 原生 `ISScrollingListBox:doDrawItem`（B42.20.4 `media/lua/client/ISUI/ISScrollingListBox.lua` 行 304-324）**第一步就是视口裁剪**，行 309：
  `if (y + self:getYScroll() + self.itemheight < 0) or (y + self:getYScroll() >= self.height) then return y + item.height end`。
- 本窗口覆盖了 `doDrawItem`，但两个自定义 painter 都**没有这层裁剪**：对任意 `y` 直接 `drawRect` / `drawText`。滚动时越过列表上下边界的行照常绘制，而 3.15 把预设行放到了列表正上方（y=30-58，列表 y=108），溢出内容正好压在预设下拉与两个按钮上。
- 同类问题本 mod 早有记录：`client/GodSystem_UISafety.lua` 的 `S.drawTextRow`（行 102-137）行 112 注释明确写着 "Geometric containment also protects against nested stencil leakage"——即项目已知嵌套 stencil 会泄漏，约定用**行绘制几何钳制**兜底。终端、转换风险等列表都走这条安全层，物品配置窗口是少数仍用手写 painter 的窗口，所以它成为唯一暴露该缺陷的地方。
- 补充确认：`S.installList`（行 43-46）只把 `prerender` 换成 `prerenderList`（同步滚动条几何后调原生 prerender），**不裁剪行绘制**，因此装了 `installList` 也不能替代本轮的 painter 钳制。

## 修复

`client/GodSystem_ItemEconomyUI.lua`，两处 painter 改为与 `S.drawTextRow` 同构的几何钳制：

1. `drawCatalogItem`（行 348-372，物品目录，行高 42）
   - `nextY = y + list.itemheight`、`scroll = list:getYScroll()`；
   - `top = math.max(y + scroll, 0)`、`bottom = math.min(nextY - 1 + scroll, list.height)`；`bottom <= top` 时**一次绘制调用都不发**，直接 `return nextY`；
   - 背景色与选中高亮只画在 `top - scroll` 起、高 `bottom - top` 的可见带内（部分可见的行被裁到边界，不再越界）；
   - 两行文字（label `y+4`、fullType `y+22`）仅在**完全可见**（`textY + scroll >= 1 and textY + scroll + fontHeight <= list.height - 1`）时才入队，避免小数滚动位置下字形跨边泄漏。
2. `self.detail.doDrawItem`（行 120-131，右侧详情，行高 20）
   - 同一模式：`math.min(nextY - 1 + scroll, list.height) <= math.max(y + scroll, 0)` 时直接返回；文字 `y+3` 完全可见才绘制；警告红字判定移入可见分支，不可见行不再解析颜色。

约束遵守：不改 stencil、不改控件层级与 z 序、不改列表几何与 `itemheight`、不改选中/滚动/`setOnMouseDownFunction` 回调；`return nextY` 与原生一致，累计滚动高度不受影响。
