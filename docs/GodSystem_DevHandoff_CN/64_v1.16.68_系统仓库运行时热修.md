# v1.16.68 系统仓库运行时热修

## 实机反馈

B42.19 单人实测确认 v1.16.67 存在五项问题：

1. 控制器显示为“奥兹博士游戏机”。
2. 系统仓库页点击“使用说明”后右侧为空。
3. 地面控制器执行收回时提示控制器不存在。
4. 连接模式让容器持续红色闪烁。
5. 已经放入连接容器的物品不显示，并在 `ISScrollingListBox.lua:508` 出现 `__lt not defined for operand`。

## 已确认根因

- 控制器脚本使用了 `ItemType = base:moveable` 和 `WorldObjectSprite = recreational_01_16`，原版 Moveable 生命周期把它识别为街机家具，覆盖了 GodSystem 自己的物品身份和显示名。
- `GodSystem_UI.updateDetail()` 没有处理系统仓库说明行的 `storageInfo` 类型，选中后落入空详情分支。
- SP 客户端直接调用共享管理器时只传 `controllerX/Y/Z`，`Manager.resolveController()` 当时只读取 `x/y/z`；MP 服务端会先归一化参数，因此该问题主要暴露在 SP。
- 仓储列表重建后立即使用 `item.index` 恢复选择；该字段要等原版列表首次 `prerender()` 才生成，当前值为 `nil`，随后原版用它做小于比较并报错。
- 旧连接模式直接调用场景对象的高亮接口，原版渲染会重复闪烁红色，不适合作为仓库网络标识。

## 修复实现

- 控制器改回独立的 `GodSystem.StorageController` 普通物品，保留自己的中文名和类型；地面外观只通过 `WorldStaticModel = CarBatteryCharger` 提供，落地继续使用原版库存“放置物品”。
- 世界对象发现、网络令牌、右键打开和收回继续读取真实地面物品实例，不再把街机家具身份作为控制器身份。
- 客户端参数同时携带 `x/y/z` 与 `controllerX/Y/Z`，共享管理器也兼容两套字段，SP 与 MP 使用同一解析结果。
- 主 UI 增加 `storageInfo` 详情分支；“使用说明”会在右侧显示完整说明。
- 仓储分组与容器管理列表恢复选择时使用当前循环数字索引，不读取未渲染行的 `item.index`。
- 连接模式只在进入模式、网络状态变化、手动刷新和标记操作后扫描一次并缓存节点坐标；每帧只绘制缓存的简单小菱形，绿色表示与当前控制器连通，蓝色表示已标记但未连通。关闭连接模式立即清空缓存。
- 新增 v1.16.68 Lua 运行时测试：构造真实 `GodSystem.StorageController` 地面物品、相邻已标记木箱及箱内已有 `Base.Plank`，验证物理发现、索引任务和最终快照均包含该木板。

## 兼容说明

- 首次控制器免费、找回固定2000系统币、网络令牌、容器标记和真实物品存放规则不变。
- 不自动删除或迁移 v1.16.67 已经变成普通街机身份、且缺少 GodSystem 令牌的旧对象。无法证明身份的对象可能是真实游戏家具，自动清理会误删玩家建筑。
- 已保存完整 GodSystem 网络身份的旧地面实例仍按现有令牌解析；无法识别的旧实例需要通过系统页找回控制器，容器网络标记和箱内物品不会被删除。

## B42.19 实测门槛

- 背包名称必须为“系统仓库总控制器”，原版放置到地面后不能变成“奥兹博士游戏机”。
- 地面右键可打开和收回；保存退出、重进、原版拾取再放置后仍能访问同一网络。
- “使用说明”右侧有完整文字。
- 连接模式只有绿色/蓝色小符号，不闪烁红色；退出页面后符号消失。
- 相邻已标记容器中的既有物品可以显示、筛选、存入和取出。
- 不再出现 `ISScrollingListBox.lua:508` 的 `__lt not defined for operand`。
- 冰箱/冰柜多容器、普通箱柜、堆叠箱子分别验证；MP 还需验证远程客户端、服务端重启和两人并发取出。

未完成上述实测前，v1.16.68 仍是修复测试分支，不合并 `main`，不覆盖稳定包。
