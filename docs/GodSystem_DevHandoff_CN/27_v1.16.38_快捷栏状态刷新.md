# v1.16.38 快捷栏状态刷新

## 背景

v1.16.36 将快捷悬浮窗改成直接动作栏，只保留回家、返回、卖腰包、存现金四个常用动作。玩家实测发现：设置家园或产生返回点后，快捷栏里的“回家/返回”按钮不会立刻出现，必须关闭并重新打开快捷栏。

## 根因

`GodSystemShortcutWindow:createChildren()` 只在窗口创建时调用一次 `getActions()` 并生成按钮。`getActions()` 本身能读取最新的 `home.home` 和 `home.returnPoint`，但窗口打开后没有任何刷新入口，所以家园/返回点状态变化不会反映到已有按钮上。

## 实现

- 版本升级到 `1.16.38`。
- `GodSystemShortcutWindow.RefreshIntervalMs = 5000`。
- 快捷栏打开时立即 `refreshActions(true)`。
- 快捷栏 `update()` 每 5 秒调用一次 `refreshActionsIfDue(false)`。
- 刷新只构建动作签名并比较 `action:label` 列表；签名未变化时直接返回，不重建按钮。
- 签名变化时移除旧按钮并重新添加新按钮。
- 周期刷新不请求服务器 state，也不扫描背包大列表，只读本地 `GodSystem.getHomeSystem()` 状态和固定动作定义。

## 后续规则

对“打开后状态可能变化”的小窗口或状态栏，不要只依赖 `createChildren()` 的一次性 UI 生成。优先使用低频、轻量的状态签名刷新；不要在 `prerender()` 或高频绘制路径里做服务器同步、价格表重建或递归背包扫描。

## 验证

- `Test-GodSystemV11638.ps1` 检查 5 秒刷新间隔、签名比较、`update()` 刷新入口和版本一致性。
- 后续应在游戏内手测：打开快捷栏，设置家园、传送生成返回点、清除返回点，观察“回家/返回”按钮是否在 5 秒内自动出现或隐藏。
