# v1.16.57 负重升级与智能回收设计

## 版本目标

本版从 `feature/v1.16.56-companion` 的 `4d2a77a` 创建
`feature/v1.16.57-carry-recycle`，只增加玩家负重升级并改善原版物品栏右键批量回收。
不修改空间终端容量、回收价格、商店价格、存档主体结构、同伴逻辑或稳定发布包。

## 永久负重升级

- 在系统升级页增加 `carryCapacity`，等级保存到 `data.upgrades.carryCapacityLevel`。
- 每级增加 2 点玩家负重。下一级价格为
  `ceil(2000 * 1.5 ^ currentLevel)`，没有玩法等级上限；非有限数或超出安全整数时停止报价。
- 升级行显示当前基础、系统加成、最终负重、等级和下一次费用。
- 只使用 `getMaxWeightDelta()` / `setMaxWeightDelta()` 写入增量，不覆盖
  `maxWeightBase`。运行时记录 GodSystem 自己已应用的贡献，重复刷新时先移除旧贡献再应用新贡献。
- 等级永久保存。单人进入、角色创建和升级成功时自动应用；多人由服务端账户数据恢复，
  在 `hello`、升级、刷新和客户端状态同步时应用。死亡、重生、读档和重连不需要再次购买。
- 负重升级行提供“刷新加成状态”。刷新不扣币、不升级，并且必须幂等。
- 持续覆盖同一负重增量字段的第三方 MOD 不在保证范围内；手动刷新用于重新校准和诊断。

## 多人和事务

- `upgradeSystem` 增加 `carryCapacity` 类型；多人服务端独立计算等级、价格、余额和最终状态。
- 新增 `refreshCarryCapacity` 命令，进入关键命令互斥链，但不产生经济变更。
- 负重购买先试应用新等级，再扣费并保存；扣费失败恢复旧等级加成，避免扣币后无效果。
- `upgradeSystem` 与 `recycleSelectedItems` 增加持久操作 ID。操作 ID 绑定规范化请求指纹；
  相同请求超时重试复用旧 ID，服务端返回缓存结果，不重复扣费或发放收益。
- 事务辅助函数挂到 `GodSystemServer` 命名空间，避免增加服务端主 chunk 的顶层 local。

## 智能右键回收

- 菜单先逐件分类，只要存在符合当前模式的实例就允许执行；不符合的实例显示为跳过。
- 普通回收允许处理已上架类型，只跳过保护物、钥匙、黑名单、零价值和不可回收物。
- 回收并上架、仅上架跳过已上架、不可上架和不可回收物；已上架物品不会被偷偷回收。
- 只把符合条件的外部容器物品转入玩家库存。非空容器确认、收益和上架费用只统计符合条件实例。
- SP/MP 执行时再次分类。资格变化可以跳过；实例消失、所有权变化、容器签名变化或真实删除失败
  仍按事务异常处理并回滚。全部跳过时不收费、不删除、不发币。
- 结果提示包含处理数量、跳过数量、收益或费用；客户端预筛数量只用于显示，不参与服务端经济结算。
