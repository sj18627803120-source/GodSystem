# v1.16.34 抽奖奖池过滤实现

## 目标

本版只修复独立抽奖奖池，不扩大到商店、回收、上架、价格表生成等全经济系统清理。发布说明也只能按“抽奖奖池修复”描述。

## 实现

- 新增 `42/media/lua/shared/GodSystem_ItemEligibility.lua`，提供 `GodSystem.isEconomicItemAllowed(fullType, context)`。
- 抽奖上下文传入 `"lottery"`，找不到 `getScriptManager()` 或 `FindItem(fullType)` 时失败关闭，避免脚本未加载或物品不存在时继续进入奖池。
- 使用同版本 B42 脚本字段优先判断：`getObsolete()`、`isHidden()`、`getDisplayCategory()`、`isBodyLocation(ItemBodyLocation.ZED_DMG/WOUND/BANDAGE)`。
- `BodyLocation` 过滤只读脚本字段和枚举，不用 `fullType` 粗暴匹配 bandage/wound，因此真实 `Base.Bandage` 可以保留，隐藏的 `Base.Bandage_*` 会被排除。
- 明确排除 `Base.ZedDmg_` 前缀、`Base.TestHotDrink`、`Base.TestMug`、`Base.TestWaterMug`、`Base.Animal_Item_Dummy`，并仅对官方 `Base.*` 做保守 internal 名称兜底。

## 接入点

- 客户端 `GodSystem_Core.lua`：独立抽奖候选池 `gsLotteryAddCandidate()` 接入，旧 `getShopLotteryCandidates()` 兼容路径也接入。
- 服务端 `GodSystem_Server.lua`：`lotteryAddCandidate()` 接入。多人最终发奖前的候选池由服务端过滤。
- 管理员单物品 `lottery` 开关仍保留，但它只能继续禁用/启用普通候选，不能强行把隐藏、废弃或内部物品放进奖池。

## 后续注意

如果未来要处理“商店/回收/上架也不显示 debug 或内部物品”，需要另开版本并明确扩展调用范围，不能把 v1.16.34 的抽奖修复宣传成全经济系统过滤。
