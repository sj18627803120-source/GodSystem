## 仓库路由的确定行为

容器设置从家具共用一份改为每个真实 `ItemContainer` 储物格独立保存。冰箱冷藏格、冷冻格或其他多格家具可以分别设置角色与优先档。

角色直接使用 GodSystem 当前 `Storage.categoryOf(item)` 的分类结果。玩家在系统里看到物品属于“材料”，路由就把它当作材料；本版不另建第二套更复杂的物品识别规则。

普通物品的排序固定为：

1. 与物品系统分类完全相同的容器角色。
2. 通用容器。
3. 同一角色内比较最低、低、普通、高、最高五档。
4. 同档时，较早设置该储物格的容器优先，保证已有网络顺序稳定。
5. 仍相同时使用稳定连接 ID，保证结果可复现。

易腐物固定按以下顺序：

1. 真实可用且通电的冷藏/冷冻储物格。
2. “易腐”角色容器。
3. 已断电的冷藏/冷冻储物格。
4. 通用容器。

目标容器满载、原生拒绝物品或事务前复验失败时，才继续尝试下一条可用路线。MP 仍由服务端重新分类、排序并移动真实实例，客户端显示和预测不参与最终结算。

旧存档第一次读取时按以下规则迁移：

- `auto`、`noAuto` -> `general`。
- `liquid` -> `drink`。
- 数字优先级 0-20/21-40/41-60/61-80/81-100 -> 最低/低/普通/高/最高。

迁移设置写回具体家具 ModData，并在首次创建时同步，不增加周期扫描。

## 名称与界面

- 管理页和右键设置菜单共用同一储物格设置。
- 容器显示先尝试 B42 原版 `IGUI_ContainerTitle_*` / `IGUI_Container_*` 本地化，再回退到家具记录名或储物格类型。
- 分类、状态、角色和优先档统一使用 GodSystem 中文本地化。
- 已删除旧允许/拒绝分类编辑入口，避免出现“界面能设置、实际路由又被另一套规则覆盖”的双重行为。

## 手动整理

仓库管理页新增“开始整理/停止整理”。整理根据当前角色和优先档重新放置当前已加载物理连通块中的物品。

安全和性能边界：

- 只读取连接容器直属物品，不递归改动嵌套容器内部。
- 最大记录 20,000 件；达到上限时结果标记不完整。
- 每次 tick 最多处理20条或约2毫秒。
- 每个物品复用现有单件转移、来源复验、目标复验和三级恢复事务。
- 易腐物按剩余腐烂时间从长到短处理，降低目标冷柜先被临近腐烂物填满后无法腾挪的概率。
- 理想目标已满时，最多尝试搬开8件尚未处理的阻挡物；没有安全缓冲容器就跳过，不强行移动。
- 整理运行中锁定索引刷新、存入、取出、连接修改、角色/优先级修改、核心领取/安装/取回和管理限制修改。
- 关闭 UI 不终止整理；主动停止、完成或失败后返回统计。已完成任务记录五分钟后自动清理。
- 不注册逐帧全仓扫描、分钟扫描或后台自动整理。
