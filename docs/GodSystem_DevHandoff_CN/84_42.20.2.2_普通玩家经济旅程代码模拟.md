# 42.20.2.2 普通玩家经济旅程代码模拟

## 测试目标

从普通玩家实际会经历的顺序验证统一经济策略，而不是只单独调用定价公式。本测试不修改经济业务代码，使用真实的经济策略、管理员配置、商城变体和操作 ID 模块，外层仅模拟人物余额、背包和物品实例。

运行入口：

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\tests\Test-GodSystemV422022.ps1 -Root (Get-Location).Path
powershell -ExecutionPolicy Bypass -File .\tools\Test-GodSystem.ps1
```

## 玩家旅程与结果

1. 玩家进入游戏并查看物品报价：
   - 已知普通物品存在有效回收价。
   - 破损且剩余量较低的同类物品回收价低于完好物品，且最低仍为 1。
   - 未收录第三方物品回收价为 1；没有拆包风险时按系统识别分类给出商城参考价。
   - 只有识别到单物品动态拆包、但无法确定产物且没有明确价格时，自动商城价才应用 550 风险底价。
2. 玩家把背包中指定实例的 `Base.MoneyBundle` 仅上架：
   - 自动售价为 110，上架费为 55。
   - 相同操作 ID 重试不会再次扣费。
   - 相同操作 ID 改成另一个物品实例会被拒绝。
   - 指定实例不存在时不会扣费。
   - 隐藏后普通商城列表不再显示，隐藏管理仍能找到；解除隐藏后恢复。
   - 普通斧和破损斧实际回收所得与报价详情完全一致。
3. 玩家购买、拆包并回收捆扎钞票：
   - 购买 1 个捆扎钞票扣除 110 并只发放 1 件。
   - 相同购买请求重试不重复扣费或发物。
   - 拆包生成 100 张 `Base.Money`。
   - 回收 100 张钞票得到 100；完整循环净损失 10，无法盈利。
   - 相同回收请求重试不重复发币。
4. 玩家余额不足或处理第三方物品：
   - 超出余额的购买不扣币、不发物。
   - 未收录第三方物品实际回收得到 1。
5. 模拟玩家断线重连：
   - 已完成购买和回收记录重新读取后仍为完成状态，能够回放结果而不重复执行。
6. 管理员调整经济配置：
   - `MoneyBundle` 覆盖为 120 后，玩家报价立即显示 120，同时安全底价仍为 110。
   - 配置快照重新应用后覆盖仍存在。
   - 恢复自动定价后重新回到 110。

## 管理员物品配置面板模拟

- 使用 208 个模拟已加载物品打开真实 `GodSystem_ItemEconomyUI.lua`，首页限制 200 行，第二页显示剩余项目。
- 分类、安全状态、商城状态、覆盖状态、商城模式、回收模式和抽奖模式均一次打开完整菜单，选择目标后直接生效，不再反复点击循环。
- 按 `fullType` 搜索 `Base.MoneyBundle` 后只保留目标行，选中后能回填现有价格和管理员备注。
- 管理员价格低于转换安全底价时，详情区域生成危险套利警告。
- 一次保存同时提交商城售价、回收价、分类、商城状态、回收状态、抽奖状态和备注。
- “恢复自动定价”清除目标覆盖；保存和恢复后都会刷新转换索引及报价缓存。
- 没有准确 `worldSprite` 的通用家具不能被强制加入商城。
- 内部或危险物品保持只读，保存按钮禁用。
- 多人保存与恢复命令均确认经过服务端管理员身份检查。
- 窗口关闭后从 UI 管理器移除，没有保留失效窗口实例。
