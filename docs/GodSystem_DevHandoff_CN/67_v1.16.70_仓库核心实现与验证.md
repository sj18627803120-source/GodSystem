# v1.16.70 仓库核心实现与验证

## 交付范围

本版从 `fix/v1.16.69-custom-controller@151b0fc` 建立
`fix/v1.16.70-storage-core`，只改系统仓库控制入口、相邻网络持久化及其
SP/MP 事务。未修改穿戴式空间终端、负重、机器人、商城、任务或经济数值。

当前结果仍是 B42.19 功能测试版，不合并 `main`，不覆盖已发布的 v1.16.63
稳定包。

## 已实现机制

- 内部 fullType 继续使用 `GodSystem.StorageController` 兼容旧存档，但脚本物品
  已改为 `base:normal` 的“系统仓库核心”，不再带 Moveable、世界贴图、静态模型
  或容量属性。
- 只有已经标记为网络容器、全部储物格为空、距离与权限合格的固定家具可以安装
  核心。多储物格家具逐格验证。
- 安装事务先保存各储物格的索引、类型和原容量，再通过原生
  `ItemContainer:setCapacity(0)` 写入并读回；全部成功后才消耗精确核心实例并
  提交网络状态。失败会恢复原容量且不消耗核心。
- 核心宿主保留网络容器标记，只参与同层四方向和同格堆叠的拓扑发现，不生成
  任何可索引 link，因此索引、智能分流、批量存入和取出都不会使用宿主储物格。
- 右键宿主可打开仓库或免费取回核心。取回时逐格恢复安装前容量，清除核心宿主
  状态并返回一个带同一有效网络令牌的核心，普通网络标记不删除。
- 每套网络首次领取免费；核心遗失或强制找回固定收费 2000。新令牌提交后旧核心
  失效。已加载旧宿主立即恢复容量；未加载宿主写入 `pendingCoreUnlock`，在区块
  加载、右键解析或仓库索引时恢复。
- 家具对象 ModData 保存核心令牌、网络 ID、稳定对象 ID 和原容量；全局仓库
  ModData 保存宿主坐标、对象 ID、状态与待解锁记录。`getGridSquare()` 返回
  `nil` 时只视为区域未加载，不会清除宿主或标记。
- `LoadGridsquare` 只检查刚加载格子的现有对象，不做周期全图扫描。有效宿主重新
  校准为 0 容量；过期或移动到新坐标的宿主恢复原容量，活动网络转为遗失状态。
- v1.16.69 背包旧控制器在状态同步时转换成普通核心并清除 `movableData`；旧世界
  控制器对应网络获得免费核心，能精确加载定位的旧对象被移除，未加载对象保留
  一次性精确清理记录。
- 连接模式关闭系统主窗口、独立仓库窗口或切换页面后继续保持；只有手动关闭、
  退出世界或断线时结束。标记只使用绿色核心宿主和蓝色普通网络容器。
