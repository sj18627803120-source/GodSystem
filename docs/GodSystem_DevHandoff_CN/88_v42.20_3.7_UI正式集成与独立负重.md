## 负重根因与实现

旧代码仅在购买／手动恢复时写值，没有覆盖新角色对象与周期恢复；当其他 MOD 将基础值 14 改为 15 时，旧推断会把 15 当外部基线，再叠 3 级的 6，错误写到 21。

共享 `GodSystem_CarryCapacity.lua` 现在分开维护账号等级、当前角色对象会话与实际基础值：

1. 每级仍花费 2000 币，增加 2 点 **基础** 负重。原版基础是 8；3 级基础为 14，最终上限由原版力量、身体状态和特质倍率计算。状态页分别显示系统基础加成、当前基础、实际上限和运行状态。
2. 账号 `upgrades.carryCapacityLevel` 权威保存，明确的 0 也优先于物品／角色标记。仅 SP 缺失等级字段时接受历史角色标记迁移；MP 不从客户端或角色标记重建等级。
3. 独立模式不需要 UCWF。新对象从当前原生基础开始，只移除能证明属于自身的旧加成；来源不明的数值改写保持原值并返回 `externalConflict`。已知基线重置在 30 秒内允许两次恢复，第 3 次进入 `resetCooldown`；30 秒后尝试一次，若再次被重置则依次等待 60／120／240／300 秒，之后最多每 5 分钟一次。连续观察到自身目标值保持 60 秒后清除重试历史。冷却到期不允许把未知值当作新基线。
4. 同装 UCWF 时仅注册 `GodSystem.CarryCapacity` 的公开基础 modifier，resolver 返回自身等级的 `add`；不复刻或打包 UCWF，不覆写它的方法。UCWF 统一计算其他来源。CapWeight 开启且已到 50 时拒绝新购买，既有等级仍保留。
5. 仅在应用变化时调用游戏 `BodyDamage.UpdateStrength()` 刷新缓存；空闲维护无原生 setter／重算。UCWF 使用自己的延迟 worker，GodSystem 最多等待三个 tick 后再传输完成的聚合值；回滚时重新绑定待完成状态，避免永久停在“等待重算”。
6. SP 接入 OnGameStart、OnCreatePlayer 及已有 1 秒维护门。新会话自动预约 3 秒后的补充核验，SP 创建／游戏开始事件也可重新预约；由已有维护门消费，不增加常驻逐帧 worker。独立模式仅额外刷新一次原生最终缓存；UCWF 模式额外请求一次框架重算，以纳入较晚初始化的 modifier。遇到未知改写时保留待核验状态，不绕过保护。服务器通过独立 1 秒 OnTick 门遍历在线玩家，因为本补丁远程玩家不触发 OnPlayerUpdate；不扫描背包。全量状态包含负重快照，之后仅状态变化时推送 `carryState`。
7. MP 校验玩家 ID、角色会话 token、递增 revision、整数与有效数值。客户端独立模式只投影批准的等级；UCWF 模式只应用服务器聚合值一次，不再叠自身 bonus。未知客户端直接改写也暂停覆盖。死亡重生／重连重新握手清除旧会话。
8. 购买先应用核验，扣费失败恢复购买前基础、最终缓存、delta、自身标记和会话；服务端原有操作 ID 去重保留。不能应用时不扣费、不增加等级。未知 Java 异常及外部标量改写仍需具体诊断，不承诺兼容所有直接写值的 MOD。

## 本补丁原生证据

直接核对本机 `projectzomboid.jar` 中的 `IsoGameCharacter`、`IsoPlayer` 与 `BodyDamage`：

- `maxWeightBase` 默认 8；基础／最终值 setter 是直接赋值，基础值不是最终缓存。当前 JAR 未发现该基础字段的持久化／网络传输引用。
- `BodyDamage.UpdateStrength()` 按基础 × `getWeightMod()`、身体状态扣减、`getMaxWeightDelta()` 更新最终值；本实现调用原函数，不复制公式到业务模块。
- `IsoPlayer` 对服务器远程玩家的提前返回位于 OnPlayerUpdate 之前，因此服务端负重采用有时间门的 OnTick。
- UCWF 官方公开来源：<https://github.com/MusicManiac/UnifiedCarryWeightFramework>；验证引用其 42.19 目录的 2.1 API 实现，在本机 B42.20.4 原生接口上运行。版本目录名本身不是当前补丁可用性的证据。

探针 Java 是本项目原创测试夹具，真实继承游戏负重 setter/getter 并调用原生 UpdateStrength；只替代角色构造、力量、moodles、ModData 和事件。不启动世界、不加载玩家存档。游戏 JAR、编译器、反编译输出与 UCWF 源码均不进入 MOD 包或版本控制。
