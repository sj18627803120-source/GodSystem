### 溅射强化

- 注册键 `splash`，等级 1–10；旧装备记录没有该字段时读取为 Lv0，不改档案。
- 每级造成武器最小与最大**基础伤害平均值**的 10%，Lv10 为 100%。目标补丁的 `OnHitZombie` 不提供该次命中的实际伤害；文案已明确此口径不包含技能、疲劳等命中修正。
- 每次有效挥击首次命中僵尸后，以该目标命中位置为中心，在同楼层半径 2 内选最近最多 5 只其他僵尸。中心目标与本次挥击全部直接命中的僵尸排除；不检查墙和门。不响应挥空、推搡、踩踏、徒手和枪械。
- 复用挥击账本，等待挥击完成后再搜索，避免误伤后续才直接命中的目标。SP 使用本地 authority；MP 由服务端命中事件采集并选目标，客户端不提交目标或伤害。
- 临时 worker 每次最多处理 64 个步进、时间预算约 2ms、待处理上限 32；仅遍历附近已加载格子，工作完成/取消后移除 OnTick 监听；空闲状态没有新增扫描或网络消息。实际单次原生调用耗时不受 Lua 时间片中断。
- 非致死时仅降低生命。致死时先 `setAttackedBy(player)`，再调用 B42.20.4 的原生 `Kill(weapon, player)` 入口，依靠原生死亡路径处理尸体、归属与同步；没有采用直接设零生命，没有手工增补击杀统计。
- 本地 B42.20.4 API/游戏 jar 存在对应 `Kill(HandWeapon, IsoGameCharacter)` 签名；官方 API 页面也列出该重载：[IsoGameCharacter](https://projectzomboid.com/modding/zombie/characters/IsoGameCharacter.html)。Kahlua harness 不加载游戏对象，因此自动测试不能证明真实击杀统计、击杀任务进度和 MP 死亡同步。这些是本版实机验收门槛；若原生路径未能正确登记/同步，停止该效果后报告，不用直接扣到 0 的方案掩盖问题。
- 沙盒 `EnableEquipmentSplash` 默认开启。关闭后隐藏培养入口、拒绝报价并停止伤害，已培养等级保留；配置 token 变化会使旧报价失效。费用、成功率和失败降级沿用已有强化逻辑。
- 装备列表行与 Tooltip 显示等级、比例、范围、目标上限；Tooltip/手册明确平均基础伤害口径。CN/CH/EN、沙盒及 Lua fallback 由 YAML 生成。

## 2026-09-23 审查反馈修复（同版 3.17）

用户只读审查发现：`GodSystem_EquipmentCombat.lua` 通过 `I.value` 获取 `getCurrentSquare`、`getMinDamage`、`getMaxDamage`，但 `GodSystem_B42JavaCalls.lua` 未注册对应显式调用。真实 Java userdata 无法走 Lua 表的备用路径，结果是首次命中时无法记录溅射中心/伤害基准，溅射不会入队。原测试只用 Lua 表，因此漏检。

修复与证据：

- 在 Java 调用桥为这三个方法增加显式冒号调用。目标 B42.20.4 `projectzomboid.jar` 的 `HandWeapon.class` 含 `getMinDamage` / `getMaxDamage`，`IsoGameCharacter.class` / `IsoZombie.class` 含 `getCurrentSquare`；官方 API 也列出相应接口。但仅凭字节码和模拟测试不能代替实机可调用性。
- 顺着同一 `weaponOK` 路径检查，发现 `isPerformingShoveAnimation`、`isPerformingStompAnimation`、`isShoveStompAnim` 三项也缺少 Java 调用桥。它们在目标补丁 `IsoGameCharacter.class` 中存在，现已显式注册，避免真实玩家对象绕过推搡/踩踏排除。冻结逻辑原有直接调用这些方法；本次仅补装备桥。
- `tools/tests/splash_runtime_spec.lua` 将武器、僵尸和玩家模拟为 Java userdata（禁止桥的 Lua 表回退）。补桥前测试以 `getCurrentSquare=nil` 确实失败；补桥后验证三个读取值、挥击完成后溅射入队，以及推搡/踩踏三种状态均阻止入队。原有最近五只、直接命中排除和临时监听移除测试继续通过。
- 这是未实机验收的 3.17 修订，不另升版本号。依然需要 SP、房主联机和专用服务器验证原生击杀归属、任务进度及同步。

## 实机验收清单

1. **转换风险窗口**：打开“转换风险”，列表滚动到顶部/中间/底部，再快速拖动滚动条；确认两列表内容不越过上下边界，不覆盖编辑区、搜索框或底栏，选中和点击仍准确。用小/标准/大终端字号各检查一次。
2. **溅射基本伤害**：绑定近战武器，培养 Lv1。让武器基础最小/最大伤害容易观察，在空地对单个站立僵尸挥中；检查附近合格目标受约 10% 平均基础伤害。逐级确认 Lv10 为 100%。需考虑原版伤害浮动/状态变化；此强化并不读取该次直击伤害。
3. **目标规则**：一击直接打中多个僵尸；所有直击目标不得再受溅射。让附近有超过 5 只目标，确认仅最近 5 只受伤。确认同层半径外、另一楼层目标不受影响；墙/门不阻挡。挥空、推搡、踩踏、徒手、枪械不触发；同一次挥击最多触发一次。
4. **死亡统计（必须）**：用致死溅射分别测试单人、房主联机、专用服务器；每个被溅射致死目标只增加一次正常玩家击杀统计，并推进原版/本 Mod 击杀任务一次；其他客户端看见一致的死亡状态，尸体正常生成。任何模式统计为零/重复或客户端不同步都应暂停验收并反馈。
5. **开关与兼容**：沙盒关闭后入口隐藏、旧等级保留、重新开启等级恢复；旧绑定装备缺少 `splash` 时显示 Lv0。确认冻结与冲击仍能同时运行，无异常击中循环或重复伤害。
6. **稳定性**：密集僵尸中快速连续挥击、切换武器/解绑/重连/玩家死亡；失效/已死/离开范围目标不再受伤，队列满时不崩溃，停止战斗后没有持续后台工作。

若任何溅射致死结果违反第 4 项，先记录模式、日志和是否有其他战斗/死亡类 MOD，再停止 3.17 实机验收；不要备份或发布。若整体测试通过，再按用户指令备份/发布流程处理。
