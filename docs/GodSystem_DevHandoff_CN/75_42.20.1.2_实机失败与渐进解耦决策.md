## 2. 实机结论

自动化检查通过后，B42.20 SP 实机仍然出现系统性故障，不是单点报错。

已确认的代表性问题包括：

- 启动期报错 `attempted index: build of non-table: null`，出现在 `Kernel.create()` 入口链。
- 仓库右键与回收上下文报错 `canContextRecycleItem` / `linkRoleAccepts` 为 `nil`。
- 任务系统首次刷新顺序错误，页面出现空白或无任务。
- 仓库界面、人物库存列表、容器链接状态和存入路由在实机中多次表现为不可用、空白或错位。
- 用户复测结论是“多数功能无法使用”，已经超过单个接口或单个 UI 回调能解释的范围。

这说明当前 `42.20.1.2` 的问题集中在启动顺序、PZ 全局环境、状态投影、UI 适配和旧运行路径替换的整体耦合上。继续在该版本上打补丁，风险高于收益。

## 3. 已做过的局部修复

这两个提交只修补了局部错误，没有改变整体结论：

- `03dd30e`：修复 `GodSystemConfigSnapshot` 导出名错误。
- `8c5fa99`：修复终端健康检查递归复制和任务首次刷新顺序。

即使加入这些热修复，实机依然无法恢复到可发布状态。

## 4. 决策

`42.20.1.2` 冻结为经验版本，不再推进为正式版。

后续开发从 `42.20.1.1` 稳定基线开始，按渐进解耦方式重来：

- 保留当前真实运行路径中的旧 client / server / protocol / runtime 组合。
- 先抽取纯共享能力，例如结果结构、操作 ID、只读诊断和局部工具函数。
- 一次只迁移一个垂直功能，避免同时替换启动内核、协议、UI 投影和全部功能模块。
- 每个功能先做真实 SP 新档、旧档验证，再做 MP 验证；通过后再删除对应旧路径。
- 新旧路径并存时，先保证稳定和可回滚，再收敛旧代码。
