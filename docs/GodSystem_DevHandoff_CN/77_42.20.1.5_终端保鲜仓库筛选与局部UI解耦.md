## 2. Scope

- `GodSystem_PageSections.lua` is a client-only local helper for active page section and per-section saved state. It does not call the server or mutate business data.
- The terminal page has `items`, `upgrades`, and `services` sections. The task page has `tasks` and `taskExtensions` sections. Their scroll, stable selection, and detail state use the existing `GodSystem_ListState` helper and include the active section in the list context.
- The warehouse category button keeps left-click cycling. Right-click now opens the full `Storage.Categories` menu and changes only `self.category`; search, state, source, MOD, container status, and sorting filters remain unchanged.

## 3. Terminal Food Service

- `GodSystem_TerminalFood.lua` owns food eligibility, cooling level, service balance, elapsed online settlement, expiry reporting, and food-instance reports for synchronization.
- Cooling levels are `1250 / 3250 / 7000` system coins. They apply `ItemContainer:setAgeFactor()` with factors `0.5 / 0.25 / 0.125`, corresponding to the target 2 / 4 / 8 preservation multipliers.
- Freshness service requires cooling Lv.1. Packages are 1 day for 100, 10 for 900, 20 for 1600, and 30 for 2100 system coins. The balance cannot exceed 365 game days.
- Settlement affects only first-level terminal `Food` instances that are not rotten and are not the protected internal relief item. It never recursively scans nested bags.
- The service continues to consume balance while the terminal is missing, but restoration is skipped until the terminal is recovered. Cooling level and remaining service stay in player data.
- The server uses the existing player-update throttle, terminal synchronization, transaction ledger, operation ID, refund path, and result protocol. A new active player session resets the service clock before settlement so persisted pre-session time is not charged. A long observed gap also resets instead of charging, prioritizing no overcharge.

## 4. API Evidence And Release Gate

- B42.20 decompiled `ItemContainer` confirms `getAgeFactor()` and `setAgeFactor(number)` exist. The implementation verifies the readback after applying the factor.
- This confirms the callable container API, not the measured in-game spoilage multiplier. Before any push, Workshop upload, merge, or stability claim, test equal foods in a normal bag, normal container, and terminal at cooling Lv.1 / Lv.2 / Lv.3 in SP and MP.
- If the actual food behavior is not the intended 2 / 4 / 8 result, leave cooling and freshness un-released. Do not replace it with an unverified software aging workaround.
