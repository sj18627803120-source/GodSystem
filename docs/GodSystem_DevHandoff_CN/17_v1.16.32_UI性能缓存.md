# v1.16.32 UI 性能缓存记录
## 背景

收到玩家反馈：背包里有数千枚子弹、钉子、螺丝，数百块木板和大量杂物时，打开商店后持续卡顿，点击要点多次，切页延迟 2-3 秒。

这类背包规模属于非常规玩家，但暴露的问题是真实的：GodSystem 有若干 UI 高频路径会递归扫描玩家主背包和所有子背包。

## 根因

- `GodSystemFloatingButton:prerender()` 每帧调用 `GodSystem.getCurrencyTotal()`。
- `GodSystemWindow:drawTopStatusBar()` 每帧计算现金和银行摘要，间接触发实体系统币扫描。
- 回收页和腰包页每次重建列表都会扫描真实库存并逐件计算回收价值。
- 多人客户端的 `GodSystemNetwork` 对 `getCurrencyTotal()` 的包装原本先调用原始本地扫描，再回退服务端余额，导致多人显示余额也可能扫全背包。

## 修复原则

- UI 高频绘制路径不能直接递归扫描背包。
- 显示用余额、银行摘要、回收分组、腰包分组使用短缓存。
- 买卖、扣钱、回收、银行、腰包等真实操作仍重新读取真实物品或等待服务端验证，不用缓存结果做结算依据。
- 多人显示余额优先使用服务端 state 中的 `data.balance`，避免客户端显示层扫全背包。
- 本次按用户要求不修改传送逻辑。

## 改动

- `GodSystem_Core.lua`
  - 新增 `GodSystem.inventoryCache`。
  - 新增 `GodSystem.invalidateInventoryCaches(reason)`。
  - 新增 `GodSystem.getCachedCurrencyTotal(maxAgeMs)`。
  - 新增 `GodSystem.getCachedBankSummary(maxAgeMs)`。
  - 新增 `GodSystem.getCachedInventoryRecycleGroups(maxAgeMs)`。
  - 新增 `GodSystem.getCachedWaistSpaceRecycleGroups(maxAgeMs)`。
  - 在发币、扣币、整理钱币、银行存取、死期操作、发物品、回滚物品、回收、腰包回收等改变库存或余额的路径后失效缓存。
- `GodSystem_UI.lua`
  - 浮动按钮和顶部状态栏改用缓存余额/缓存银行摘要。
  - 回收页和腰包页改用缓存分组结果。
  - 手动刷新或关键操作后主动失效缓存。
- `GodSystem_Network.lua`
  - 多人 `getCurrencyTotal` 包装改为优先读取服务端 `data.balance`，只有没有 state 时才回退原始扫描。
  - 收到服务端 state 后失效显示缓存。

## 后续开发规则

- 不要在 `prerender()`、状态栏绘制、鼠标悬停详情、窗口缩放、列表行绘制中调用 `getCurrencyTotal()`、全背包扫描、回收分组、价格表全量重建或服务器刷新。
- 列表分页只限制渲染数量不等于限制计算数量。商品、回收、腰包、管理页如果数据量大，应缓存筛选/分组结果。
- 如果玩家反馈“打开某页面后整个游戏都卡”，优先检查该页面是否在每帧或频繁重建时扫全背包。
