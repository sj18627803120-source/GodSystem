## 2. 本轮目标与结果

本轮没有增加大型玩法，也没有修改经济数值和主要 UI 操作。核心结果是把原先由大型 Core、客户端网络总文件和服务端总文件共同承担的业务，改为显式装配的纵向模块：

```text
启动与装配
├─ PZ 平台适配
├─ 稳定共享服务
├─ 独立功能模块
├─ 统一用例与 SP/MP 执行
├─ 视图模型与动作适配
└─ 统一 UI 外壳和诊断
```

达到的结构约束：

- 核心只负责依赖装配、启动顺序和生命周期。
- 功能模块不直接修改其他功能模块的内部表。
- 依赖由 `create(dependencies)` 显式注入，不使用全局服务定位器隐藏依赖。
- 所有业务结果统一为 `{ok, code, data, operationId, moduleId}`。
- SP 与 MP 使用同一用例；SP 走本地执行器，MP 走精确版本协议和服务端执行器。
- 模块健康检查只读，不修复数据、不发物品。
- 一个模块启动失败时只停用该模块及明确依赖项，并保留可复制诊断信息。

## 3. 模块清单

### 启动与运行

- `GodSystem/Bootstrap.lua`：模块注册、依赖验证和启动。
- `GodSystem/Composition.lua`：唯一依赖装配入口。
- `GodSystem/Runtime/Kernel.lua`：运行时内核。
- `GodSystem/Runtime/UseCaseDispatcher.lua`：统一动作分发。
- `GodSystem/Runtime/Coordinator.lua`：玩家进入、死亡、时间推进、断线等跨模块流程。
- `GodSystem/Runtime/Protocol422012.lua`：`42.20.1.2` 精确协议表。
- `PZClient`、`PZServer`、`ClientGateway`、`RemoteClient`、`ServerBridge`：SP/MP 执行和请求恢复。

### 平台与共享服务

- `GodSystem/Platform`：PZ 事件、命令、ModData、库存、角色、场景对象、仓库、终端、装填机等接口适配。
- `GodSystem/Services`：时间、随机数、通知、操作 ID 和防重复账本。
- `GodSystem/Core`：统一结果、模块注册和诊断记录。
- `GodSystem/State`：模块状态存储与 `42.20.1.1 → 42.20.1.2` 迁移。

### 功能模块

- Wallet、Bank、Tasks、Shop、Recycle。
- Attributes、Upgrades、Medical、Home。
- Terminal、Storage、AutoLoader、Maintenance。
- Companion、Admin、System。

每个功能边界拥有自己的规则、用例、状态切片、健康检查和所需平台端口。

### UI

- `UI/Facade.lua`：页面唯一业务入口。
- `UI/ReadModel.lua`：只读投影。
- `UI/ActionAdapter.lua`：商城、任务、回收、升级、维护、机器人等动作映射。
- `UI/StorageAdapter.lua`、`UI/AutoLoaderAdapter.lua`：仓库和装填机专用动作。
- `UI/ShellAdapter.lua`：窗口偏好和 UI 生命周期。
- `UI/DiagnosticsViewModel.lua`：普通诊断与高级复制报告。

旧 UI 文件暂时保留现有绘制和页面布局，但业务写入已经全部经过上述适配器。

## 4. 关键行为

### 状态迁移

- 只读入 `42.20.1.1` 旧数据。
- 按模块转换、校验和提交。
- 迁移可重复执行，不重复发币、扣币或生成物品。
- 单模块迁移失败时保留旧数据，停用对应模块，并在诊断页记录失败阶段和原因。

### 多人请求

- 客户端和服务端必须同为 `42.20.1.2`。
- 同一路由已有请求等待时拒绝覆盖，返回 `actionPending`。
- 超时或断线后，相同参数重试会复用请求 ID、操作 ID 和指纹。
- 服务端按玩家隔离完成结果缓存，重复请求返回第一次结果，不重复扣费、发物或移动物品。
- 迟到的成功回包可以完成原请求并清除待重试记录。

### 生命周期

- 玩家进入、创建、死亡、时间推进和断线由 Coordinator 统一分发。
- 银行在线理财使用真实 `hours=1` 小时推进。
- 玩家断线时刷新并移除该玩家运行时会话。
- UI 偏好和机器人快捷按钮偏好通过明确协议保存，不再直接改投影表。

### 诊断

普通页显示：

- 当前版本、SP/MP、迁移结果。
- 各模块健康状态。
- 等待中的命令。
- 最近一次问题。

高级报告显示：

- 模块、阶段、依赖链、操作 ID、协议版本、时间和错误代码。
- 原始错误堆栈。
- 可直接复制给开发者。

刷新诊断只执行只读 `health()`。

1. 备份一个 `42.20.1.1` 存档并加载，查看诊断页迁移是否全部成功。
2. 新建 SP，依次打开全部页面，完成每类功能的一次最小操作。
3. 测商城购买/隐藏、回收、任务、银行、负重升级和医疗，确认只结算一次。
4. 测空间终端、仓库连接/存取/整理和自动装填。
5. 测机器人显示、跟随、攻击、守护、灵视和关闭重开。
6. 启动 MP，两名玩家分别操作经济与仓库，测试断线重连和服务器重启。
7. 出现问题时复制诊断页高级报告和对应红字，不用恢复旧运行文件。

## 9. 已知技术债

- `client/GodSystem_Core.lua` 仍保留较多旧 UI 所需的读取、格式化和展示辅助函数；它已经不再注册旧业务生命周期，也不再作为商城、任务、仓库等写操作执行入口。
- 现有 UI、物品栏右键和场景右键仍是 PZ 事件入口，所以架构检查会把这些外壳列为严格目录外的迁移债；业务写入已由模块适配器接管。
- `GodSystem_RecycleContext.lua` 的菜单预估仍使用旧 Core 的纯读取/资格辅助；最终交易由 `recycle.execute` 服务端重新验证，因此不会以菜单预估结算。后续可把该预估提取为共享只读分类服务。

这些项目不应通过恢复旧协议或旧服务端总文件解决。下一步应逐个缩小展示外壳，并保持每次修改可独立验证。

## 10. 继续开发规则

- 主代理负责架构、存档、经济、MP 事务、整合和最终验证。
- 机械搜索、文档、测试脚手架和只读审查可以交给子代理，但不能让子代理决定架构。
- 新功能先在对应 Feature 内增加规则和用例，再声明所需平台端口，最后接入 UI。
- 不允许 UI 或 Context 直接写 ModData、发业务命令或修改模块内部表。
- 不允许 Feature 直接 `require` 另一个 Feature 的实现。
- 新的共享能力必须至少被两个模块真实复用。
- 下一正式版完成并验证后，删除一次性 `Migration422011`，不要让迁移永久累积。
