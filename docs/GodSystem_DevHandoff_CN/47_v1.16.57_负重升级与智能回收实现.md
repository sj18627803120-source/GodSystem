## 永久负重升级

新增共享模块 `GodSystem_CarryCapacity.lua`，负责等级归一、价格、安全整数保护、状态读取和幂等应用。等级保存在 `data.upgrades.carryCapacityLevel`，旧档默认 0；每级增加 2 点，下一次费用按 `ceil(2000 × 1.5^当前等级)` 计算，不设置玩法等级上限。达到非有限数或安全整数边界后停止报价，不能产生负价格、无限价格或免费购买。

模块只调用 `getMaxWeightDelta()` / `setMaxWeightDelta()`。每个角色对象记录 GodSystem 上次应用的贡献和当时增量，刷新时先从当前增量移除自己的旧贡献，再加入目标等级贡献；基础负重由最终负重减去已确认应用的 GodSystem 贡献得到，因此力量、职业、特征和其他正常修正仍保留。升级页显示基础、加成、最终值、等级和下一级费用，且只有负重行显示“刷新加成状态”。

SP 在进入世界、创建角色、重生和购买成功时应用；MP 服务端在 `hello`、购买和刷新时按账户等级应用，客户端只在收到有效服务端状态后恢复页面和本地角色状态。死亡只清角色对象上的运行时标记，不清永久等级。

购买先试应用新等级，再扣除系统币并写入等级、`spentPoints` 和历史；余额扣除失败会恢复旧等级贡献。多人不信任 UI 报价，服务端按真实等级重新计算费用。

## 操作 ID 与事务防重

新增服务端小模块 `GodSystem_TransactionOps.lua`，避免继续增加 `GodSystem_Server.lua` 的顶层 local 数量。它为以下命令保存处理中、完成或未知状态，并将完成结果限制在每名账户、每种命令 64 条：

- `upgradeSystem/carryCapacity`：指纹绑定升级类型。
- `recycleSelectedItems`：指纹绑定模式、物品实例 ID、非空容器签名和是否确认销毁内容。

客户端关键命令超时后保留操作 ID；60 秒内重试同一指纹会复用旧 ID。服务端命中完成缓存时直接回传原结果，不再次扣费、删除或发放收益；同 ID 不同指纹拒绝执行；重启后发现遗留 `processing` 时转为 `unknown`，避免无法判断旧操作结果时盲目重做。

`refreshCarryCapacity` 不改变经济，但被加入状态等待和关键命令互斥链，连续点击不会并发执行或用旧状态覆盖新状态。

## 智能右键回收

`GodSystem_RecycleContext.lua` 在创建菜单时按模式逐件分类，只要至少一件合格就启用操作，菜单和提示显示可处理数/跳过数。只把合格的外部容器、地面或车辆物品转入玩家主库存；非空容器确认和签名也只覆盖合格实例。

- 普通“回收”：允许回收已经上架的类型，只跳过保护物、钥匙、黑名单、零价值和不可回收物。
- “回收并上架”与“仅上架”：跳过已上架、不可上架或不可回收物，已上架物品不会被后台继续回收。
- “仅上架”：仍按唯一 `fullType` 收费，重复实例不重复计费。

SP 和 MP 执行端会重新逐件验证。资格变化只增加跳过数并继续；物品消失、所有权变化、容器签名变化或真实删除失败属于事务异常，整批取消并恢复已移除物品。全部跳过时不收费、不删除、不发币。最终经济金额只由执行端的真实合格集合计算，客户端预筛数量只用于显示。
