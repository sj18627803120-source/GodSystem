# v1.16.60 负重实际测算与压缩说明

## 范围

- 开发分支：`fix/v1.16.60-carry-rounding`。
- 基线：`fix/v1.16.59-carry-compression@4b5c01a`。
- 保留当前实机负重等级、价格、扣费和倍率写入行为。
- 只调整负重展示/结果测算与终端压缩兼容性说明。
- 不继续强制修正每级 `+2`，不把实际效果写死为 `+3`，不继续扩大压缩兼容范围。

## 负重展示与升级测算

- 升级页不再显示理论 `等级×2`，改为 `实际加成＝当前最终负重－排除 GodSystem 后记录的基础负重`。
- 页面格式为：`当前基础（X）｜实际加成（+Y）｜最终负重（Z）｜等级（L）｜下一级（C）`。
- SP 购买前保留当前最终负重；现有倍率成功写入后读取 Java float 回传值，按与当前角色状态最匹配的整数模型计算预计最终负重，并与购买前值相减得到“测算本次增加”。
- 成功提示格式为：`负重能力已升级到 Lv.L｜测算本次增加 +N｜预计最终负重 Z`。
- 测算结果只用于展示，不参与价格、余额、等级、存档或服务端经济结算。
- MP 不信任客户端测算作为权威结果；升级通知提示以同步后的升级页实际值为准。

## 性能边界

- 没有新增 `OnPlayerUpdate`、`OnTick`、分钟事件或定时器。
- 没有扫描玩家库存、背包、地面或车辆容器。
- 页面进入/刷新时通过现有 `populateUpgrades()` 调用读取一次常数个角色字段，随后复用列表行文本。
- SP 购买、读档、重生和 MP 状态同步继续复用已有应用入口，没有新增后台轮询。

## 终端压缩说明

终端页面新增固定说明：

> 压缩说明：并非所有物品都支持压缩；特殊重量物品或其他 Mod 修改过重量的物品可能无法压缩，系统会自动跳过不兼容物品。

该说明来自 UTF-8 YAML 源，并生成 CN、CH 和 ASCII-only Lua fallback。压缩算法、跳过规则和已知兼容范围本轮不变。

## 实机门槛

- 连续升级至少三级，对比成功提示的测算结果与下一次打开页面时的实际结果。
- 测试不同力量、职业或其他负重修正下，基础/实际加成/最终值是否自洽。
- 确认页面停留时没有持续刷新、卡顿或库存扫描。
- 确认终端兼容性说明可见，且长文本不会遮挡升级按钮。
