# 42.20.1.7 任务扩展购买按钮修复

Status: published with `42.20.1.7`. Automated verification, Workshop synchronization and user real-game feedback are recorded in `80_42.20.1.7_正式发布与继续开发交接.md`; retain this document for the focused defect and regression rationale.

## 1. 问题与原因

用户实测发现，任务页的“任务扩展”分区中，选择“提高最大任务数量”或“提高每日任务数量”后，主按钮仍可能显示普通任务页的“接取”，但点击后的升级功能实际生效。

旧实现只在任务扩展分区初始化时把按钮标题写为“购买升级”；后续详情或延迟刷新对该分区采取早退，因而可能遗留前一次普通任务选择写入的“接取”标题。

## 2. 修复

- `GodSystemWindow:updateTaskPrimaryButton()` 现在在当前分区为 `taskExtensions` 时主动写入“购买升级”。
- 即使分区状态被一次延迟刷新读取为旧值，只要当前选中项是 `kind="upgrade"`，也会主动写入“购买升级”。
- 普通可接取、进行中、可领奖、失败和已领奖任务的按钮逻辑不变。
- 不修改任务升级的现有本地/多人结算、价格、任务模板、任务数据或网络协议。

## 3. 自动验证

- `Test-GodSystemV422016.ps1` 先验证旧实现缺少升级行强制标题，再验证当前实现同时覆盖任务扩展分区和升级行。
- 继续运行 Lua 5.1 编译与完整 `tools/Test-GodSystem.ps1` 回归。

## 4. 简单实机测试清单

1. 打开任务页，切换到“任务扩展”，分别点选“提高最大任务数量”和“提高每日任务数量”。底部主按钮必须显示“购买升级”，不能显示“接取”。
2. 先在普通任务页选中一个可接取任务使按钮显示“接取”，再切换任务扩展并选中两种升级，按钮仍必须立即变为“购买升级”。
3. 购买任一升级后，任务扩展分区、当前行和滚动位置不应回到首项；任务数量和扣除的系统币应正确更新。
4. MP 下两名玩家各完成一次升级，连续点击或重连后不应重复扣费；普通任务的接取、放弃和领奖按钮仍应正确显示。
