## 存档、协议与回滚边界

新增世界 ModData 键 `GodSystem_Equipment_SP_v1` / `GodSystem_Equipment_MP_v1`（schemaVersion=1）；物品键 `GodSystemEquipment`，角色键 `GodSystemEquipmentCharacter`。根包含 worldId、accounts、records、localProfiles；每账号含当前角色、已解锁槽、slot → equipment UUID 映射、revision 和最多 64 条交易回执。装备记录保存原始属性、各属性等级、代次、真实 ID 及最后可靠损耗。

旧银行、任务、商品和网络命令保持兼容；新增 `equipmentSync` / `equipmentAction`，返回 `equipmentState` / `equipmentItem` 及原结构化 `result`。MP 客户端只接收本人档案和服务端单物品属性，不作为价格、等级或归属的权威来源。SP 仍复用原有世界钱包／任务统计，只将装备档案按本地玩家隔离；扣现金时临时选择具体玩家的库存，调用结束／异常后立即恢复原解析器。

保存操作意图、付款来源和实例快照，核验成功后提交。同步失败不撤销已提交收益；遗留 processing 变为 unknown，不自动重发物品或重复扣款。真实物品存在时不使用旧耐久快照覆盖它。原生存档不是跨文件数据库事务，不承诺断电零丢失。

成功与完整回滚均推进账号修订号，防止旧回执淘汰后重新执行。完成回执只留结果／费用／抽取记录，不继续保存回滚用的完整培养副本；unknown 则保留快照等待核对。解绑保留不含培养等级的退役身份记录，用于旧实体恢复基础属性。现金退款创建失败时等额转入原有银行并明确提示。

unknown / 身份冲突必须核对真实物品、实际银行现金及回执后人工处理，不提供自动清除锁定、从客户端修复档案或盲目重发功能。测试故障时应记录账号、operationId、装备 UUID、代次与真实 ID，不能直接删除整个装备 ModData 表后再次付款。

## 原生证据

规划阶段读取本机 projectzomboid.jar 的 42.20.4 字节码与原版 Lua：InventoryItem.save/load、HandWeapon 属性 getter、CombatManager、IsoGameCharacter.calculateCombatSpeed、SyncHandWeaponFieldsPacket，以及 ISUpgradeWeapon / ISReloadWeaponAction / OnBreak。

ConditionMax 不作为新强化目标；Condition 保存为单字节。主体、头部与锋利度的自然磨损共享耐磨参数。最大伤害 getter 含锋利度派生计算，必须反解原始值。普通重量 setter 不控制 HandWeapon 实际重量，ReloadTime 不控制原版换弹动作速度。Java 方法存在不代替 Kahlua/SP/MP 实测。

本轮补查：

- `InventoryItem.getOnBreak / setBroken / setHeadCondition`：零耐久可能再次触发拆解回调；存活的普通零耐久枪械可修理，有破坏性 OnBreak 的零耐久实体暂停直接修理，避免失败回滚时再次拆解。
- `HandWeapon.getAllWeaponParts / getHitChance / getRecoilDelay / setBaseSpeed`：明确使用原生签名。带小数后坐力配件的整数截断不可逆，因此该情况下不开放后坐力培养，其他可验证属性不受影响。含配件实际精准达到上限时禁止继续付费。
- `SyncItemFieldsPacket.setData / processClient / processModData`：原生同步包含主体、头部、锋利度。仅付费修理／找回及相应失败恢复请求发送耐久字段；普通装备切换／页面同步仅发自有属性消息，避免把后台同步变成损耗覆盖。耐久同步抛错后保留 pending 标记重试。
- 原版 `ISUpgradeWeapon.complete`、`ISRemoveWeaponUpgrade.complete` 保留原逻辑，装备倍率在配件运算边界剥离／重算；`ISFixAction.complete` 后更新已知实体。磨刀位于配方路线，包裹 `ISCraftAction.complete` 与 `ISHandcraftAction.performRecipe`，不猜测不存在的磨刀事件。
- `GameWindow.save(boolean)` 的 OnSave 在 `GlobalModData.save()` 之前触发。保存前刷新已知装备辅助快照；不每次强化强制保存全世界。

## 2026-09-04 第二轮实测：红线、英文、交易错误及成长反馈

### 已确认的根因及修复

1. 装备按钮直接共享 `GodSystemUITheme.colors.border/button`。本机原版 `ISButton.lua` 的 `setEnable(false)` 用 `setBorderRGBA`／`setBackgroundRGBA` 原地改为红边黑底，导致全局主题污染。现改为每个窗口／按钮持有独立颜色副本；没有覆写全局原版类。测试模拟原版原地改色，旧实现复现 `0.7 ~= 0.271`，修复后主题和兄弟按钮互不影响。
2. 16:56:09 发生本 MOD 异常：`EquipmentInsufficientFunds`，堆栈 `EquipmentService.lua:344 → performAction:340 → action:448 → EquipmentClient:69 → EquipmentUI:182`。虽然外层 `pcall` 捕获了错误，Kahlua 仍记录红字。已知拒绝／核验失败改为正常返回错误码，保持退款、去重、修订号和 unknown 分支；真正抛出的引擎异常仍保留。新增 SP/MP 余额不足测试确认不调用 `error`、不抽随机数、不扣钱，重试只返回同一结果。
3. 文本解析原先先调用 `getText`，只要返回不等于 key 就直接使用；当中文文件缺失／被翻译包遮挡而原生回退到 EN 时，本 MOD 的中文 fallback 根本不会生效。现 CN/CH（及语言尚未就绪）优先自身中文字典，其他语言保留原生译文优先；用原版 `Translator.getLanguage():name()` 读取语言，不改全局 `getText` 或游戏设置。生成器同步完整 CN/CH `IG_UI.json`，保留 txt 和 Lua fallback，静态校验 JSON／txt 一致。此项修复覆盖代码确认的英文回退路径；尚未收到反馈玩家具体语言设置和截图，不能断言所有玩家均为同一原因。

日志中的 Bandits 动画、ShadowCatTacticsGuardian 模型和 `B42Trans_CN_As1/MapLabel_Fix.lua → ISWorldMap.initDataAndStyle` 的 `Invalid prefix found` 都在 f:0／进档时发生，早于本 MOD 的余额不足操作。它们不能据此归因于装备页；未修改第三方 MOD，也不声明那些报错已修复。

### 目标成功率与成长

- 输入框初始为空；0～100、最多两位小数。目标不高于自然成功率时不额外付费、不降低自然成功率。输入 100 得到精确的 100%。确认框锁定当时报价，编辑输入不改变已弹出的交易。
