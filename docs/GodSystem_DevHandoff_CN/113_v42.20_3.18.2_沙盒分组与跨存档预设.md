# v42.20_3.18.2 沙盒分组、跨存档预设与范围回收开关

日期：2026-09-24。基于当前 3.18.1 工作树开发，目标游戏 B42.20.4。开发后按用户后续明确授权部署 Workshop 测试副本；用户反馈当前测试通过并明确要求更新唯一滚动备份。**未发布、未提交，也未关机。**

## 改动

1. `sandbox-options.txt` 保持原有选项 ID 和数值，按装备、任务、商城、回收、银行等实际功能排列。每组首项使用 B42 原生 `title` 字段，CN/CH/EN 生成对应 `Sandbox_Title_*`。普通标签去除重复的 `[银行]` 等类别前缀，仅有明确扫描、处理或同步频率影响的选项标 `[性能]`。组名使用普通连字符，避免特殊线条字形缺失。
2. 新增默认开启的 `EnableRecycleListing`。关闭时隐藏回收并上架、仅上架及回收模式切换入口；客户端阻止操作，服务端拒绝新请求。已完成的同一交易操作 ID 仍先返回旧回执，保持重试幂等。普通回收和已有商城商品不受此开关删除或重置。
3. 物品配置预设库写入 Zomboid 共用文件 `GodSystem_ItemConfigPresets.txt`。SP 由本机读取；多人由所在服务器保存和读取，服务器管理员可在该服务器的其他存档中选择预设。不是跨电脑或跨不同服务器自动同步。用户实测发现首次创建的空文件会阻止保存，现把零字节文件识别为空库；界面改为“默认、预设 1～3”四个固定按钮。点击默认需确认后才应用默认配置，取消不修改当前配置；点击槽位弹出原有的“读取、覆盖、修改备注”，空槽禁用读取并说明原因，读取流程不变。旧的任意名称预设不再导入固定槽位，避免本次清空后被旧存档重新带回。文件读写只发生在打开或修改预设时。
4. 范围回收页新增“回收尸体：开/关”，默认开。偏好按玩家保存在本机文件，发起 MP 范围回收时附带布尔意图，服务端使用该次请求的值。关闭后该次作业跳过尸体物品和尸体本体两阶段，普通回收不变；运行中的作业仍按启动时选项执行。
5. 版本标记统一为 `42.20_3.18.2`，游戏内说明书和生成本地化同步更新。

## 预设内容和边界

预设是当前**管理员物品经济配置**的快照，包含：`itemOverrides`（逐物品购买价、回收价、分类等覆盖）、`shopVariantOverrides`（商城变体覆盖）、`conversionRelations`（自定义转换关系）、`conversionBuiltinOverrides`（内置关系改动）、`conversionBuiltinDisabled`（禁用标记）、`conversionBuiltinRemoved`（内置删除标记）和 `conversionSequence`（关系编号序列）。预设不包含沙盒设置、商品上架/隐藏目录、玩家余额、动态涨价层、任务或装备。保存快照并不会自动改动其他存档；在目标存档点击应用后才覆盖该存档上述七项配置，并更新经济版本。

共用文件只有预设 1、2、3 三个固定槽位，各自带独立备注。空槽可先编辑备注，但不能读取；“覆盖”保存当前管理员物品经济配置快照。零字节文件按空库恢复，非空且格式损坏的文件仍拒绝操作；写入失败时回滚本次预设修改。文件位于运行环境的 Zomboid `Lua` 目录，迁移其他设备时需连同该文件自行复制。本机原文件在用户实测后为 0 字节，按用户要求重置为仅含格式头的空库；这只清空预设槽位，不直接改动任何存档当前正在使用的物品价格。

## 待实机验收

在 SP 检查沙盒分组标题、无重复方括号、性能项标识；关掉回收上架后核对物品栏右键、终端/主界面及旧请求；两个不同存档依次保存、加载、应用物品经济预设；范围回收开关分别试尸体和尸体内物品。在房主与专服检查管理员预设跨世界读取、上架权限和范围回收请求。3.17 溅射与 3.18.1 水电原生接口仍沿用前述交接的实机验收边界。

用户报告的原版“大型工业水槽”是搬运后重新放置且尚未执行原版接管。B42.20.4 的放置脚本会留下 `canBeWaterPiped=true`，接管动作才清除该标记并启用外部水源；目前一体机遵循“先接通管道”规则，因此该对象被排除。用户确认维持此规则，本版没有改为自动接管。接管后让一体机保持启动且水账户有余额，等待下一次约 60 秒扫描再实测；若仍无水，再检查对象的原生水量与接口，不预先宣称供水兼容问题已解决。OrangeCommunityEconomy 同样把固定管道水槽与另行绑定的储水容器分成不同服务，后者不能直接等同于本功能的供水路径。
