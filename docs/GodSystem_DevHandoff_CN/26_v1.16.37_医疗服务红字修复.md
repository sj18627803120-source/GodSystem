# v1.16.37 医疗服务红字修复

时间：2026-06-28

## 玩家反馈

单人模式点击升级页医疗服务确认后，PZ 日志报 GodSystem 相关错误。

日志集中在：

- `GodSystem_Core.lua:1497`
- `GodSystem_Core.lua:1507`
- `gsSafeCall`
- `gsMedicalNumber`
- `gsMedicalIsInfected`
- `getMedicalStatus`
- `performMedicalService`

## 根因

医疗服务需要兼容 B42 不同身体/感染 API，所以会试探调用多个方法，例如：

- `getInfectionLevel`
- `getInfectionTime`
- `getInfectionMortalityDuration`
- `setInfectionLevel`

旧版 `gsSafeCall(object, methodName, fallback, ...)` 没有在调用前检查 `object[methodName]` 是否真的是函数。

当方法不存在时，`pcall` 虽然能让 Lua 流程继续，但 PZ/Kahlua 的错误收集器仍会记录 `Tried to call nil`，导致玩家看到红字。

此外，旧版 `gsSafeCall` 在带 `self` 调用失败或返回 nil 后，会再尝试一次不带 `self` 的调用。这对 Java/userdata 对象的 getter/setter 很容易产生额外红字，不适合作为常规安全调用兜底。

## 修复

`gsSafeCall` 改为：

- 先读取 `local method = object[methodName]`。
- 如果 `type(method) ~= "function"`，直接返回 fallback。
- 只执行一次 `method(object, ...)`。
- 方法成功但返回 nil 时返回 fallback。
- 不再做无 self 的第二次试探调用。

这样医疗服务在检查感染、治疗伤势、清除感染时，遇到 B42 当前对象不存在的方法会直接跳过，不再制造红字。

检查内容：

- `gsSafeCall` 必须有 `type(method) ~= "function"` 保护。

- `GodSystem.getMedicalStatus` 和 `GodSystem.performMedicalService` 仍存在。
- 版本必须为 `1.16.37`。
- Lua 文件无 `U+FFFD` 替换字符。

## 后续注意

- 不要以为 `pcall` 包住就不会被 PZ 记错误。对不存在的 Java/userdata 方法，必须先做函数存在性检查。
- 以后所有“兼容多个 B42 API 名称”的代码，都应优先使用这种先判断函数再调用的包装。
- 如果确实需要支持 table 函数和 Java 方法两种调用形式，应拆成两个明确 helper，而不是在同一个 helper 里失败后盲目无 self 重试。
