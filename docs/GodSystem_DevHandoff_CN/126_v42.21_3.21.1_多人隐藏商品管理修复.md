# GodSystem v42.21_3.21.1：多人隐藏商品管理修复

日期：2026-10-01。以3.21工作树为基线，保留尚未发布的全部修订。目标B42.21，版本42.21_3.21.1。备份仍为已验收3.20.1；不发布、不提交、不覆盖ZIP。

## 反馈与证据

玩家描述：此前上架商品隐藏后，商城和隐藏管理均不显示，重新上架失败。提供的Desktop/console.txt记录B42.21.0及多人连接，没有此次上架请求的结果、MOD精确版本或服务器账本；其中动画目录缺失异常不能当作此问题的证据。

当前代码已复现：服务端普通状态投影includeShopPayload=false，不再发unlockedShopItems；商城从ShopListingStore分块缓存读取，而隐藏管理getUnlockedShopItemsList与canContextListItem仍读玩家投影的旧表。即使完整缓存里有隐藏商品，旧管理方法返回0条，客户端认为未上架，服务端则返回hiddenListed。确认的是当前代码缺陷，不等于确认玩家存档物品记录完整或已实机修复。

## 最小修正

1. ClientRuntime_Economy新增getShopListingRows：SP读取存档表，MP读取现有分块缓存并保留ready。隐藏管理通过相同入口获取可见和隐藏记录；没有改变服务端存档、隐藏语义或成交验证。
2. ClientRuntime_Recycle上架预检使用相同入口，已隐藏/已上架/配置上架分别返回原原因；未同步完整返回catalogLoading。Moveables的worldSprite稳定键继续独立。
3. RecycleContext加载中不开放仅上架/回收并上架，普通回收仍允许。原已上架物品的“回收但不重复上架”规则保持；服务端重复检查仍生效。
4. HiddenWindow加载中显示提示，保留旧完成列表与选中ID，暂停隐藏、恢复及删除；初次未完成不显示“没有商品”。分块完整后原子刷新并按原选择恢复，已确认空结果才显示空提示。
5. Network在既有分块step前后比较ready，false→true时一次失效/合并刷新；解决回复触发刷新早于队列消费、最后一块完成后没有补刷的边界。ShopListingStore.request在队列仍在消费或末块已收到时不重复发送旧游标请求，新增窗口打开/刷新恰好落在末块消费前的回归。不增加监听、轮询或新的网络协议。

管理权限、价格、购买、上架收费、商品数据和账号身份不变；不清空现有商品，不自动恢复玩家主动隐藏的商品。恢复隐藏记录不会再次收费。禁售/强制上架/缺失物品仍遵循原过滤规则，不绕过管理员配置。
