# v1.16.33 独立抽奖页重制

## 背景

用户确认 v1.16.32 性能缓存路线在实测中问题太多，创意工坊已回滚，因此后续不再沿用 v1.16.32 作为功能基线。本次从 v1.16.31 备份恢复实时目录，再制作 v1.16.33。

## 本次目标

- 从商店中移除抽奖入口。
- 左侧导航新增独立“抽奖”页。
- 抽奖改为直接发放物品，不再只是解锁商店。
- 支持全种类抽奖、指定分类抽奖。
- 支持抽 1 次、抽 10 次、自定义次数。
- 默认自定义上限 50 次。
- 默认价格：
  - 全种类：100/次。
  - 低价分类：60/次。
  - 中价分类：90/次。
  - 功能分类：150/次。
  - 车辆分类：200/次。
  - 武器分类：400/次。
- 管理页可用中文配置抽奖开关、价格和自定义上限。
- 多人模式由服务端验证余额、扣币、发物品，并返回一次性结果弹窗。

## 主要改动

- `GodSystem_Config.lua`
  - 新增 `LotteryAllPrice`、`LotteryCustomMaxCount`、`LotteryCategoryPrices`。
  - 版本提升到 `1.16.33`。
- `GodSystem_Protocol.lua`
  - 新增 `lotteryDraw` 协议命令。
- `GodSystem_AdminConfig.lua`
  - 新增抽奖价格和次数上限管理项。
  - `EnableShopLottery` 保留为兼容键，但显示含义改为独立抽奖功能开关。
  - `applyLotteryCategoryPrices()` 把管理页的分组价格映射到具体物品分类。
- `GodSystem_Core.lua`
  - 新增抽奖候选池、价格、预览和单人抽奖执行函数。
  - 候选池包含已配置商店物品、已解锁物品、原版价格表物品；按 `fullType` 去重；受单物品覆盖 `lottery=1/0` 控制。
  - 单人抽奖使用现有统一支付逻辑，仍按活期优先、背包现金补足。
- `GodSystem_Server.lua`
  - 新增 `Commands.lotteryDraw`。
  - 多人服务端校验功能开关、次数上限、候选池、余额，成功后发放物品并扣费。
  - 旧 `shopLottery` 命令仅保留为兼容入口，转发到新抽奖逻辑，不再从商店 UI 暴露。
- `GodSystem_Network.lua`
  - 新增 `performLotteryDraw` 包装和 `pendingLotteryResult`。
  - 客户端收到服务端结果后暂存，由 UI 刷新后弹出抽奖结果。
- `GodSystem_UI.lua`
  - 左侧普通导航新增“抽奖”，导航项支持滚轮滚动。
  - 抽奖页提供分类按钮、抽 1 次、抽 10 次、自定义次数输入和结果/候选预览。
  - 修复导航滚轮里 `getAbsoluteX/getAbsoluteY` 可能不存在导致红字的风险。
  - 抽奖页复用输入框时用 `suppressSearchChange` 避免设置默认次数触发页面重建。
- `Translate/CN`、`Translate/CH` 和 `GodSystem_Localization_Override.lua`
  - 补齐抽奖页、抽奖结果、管理配置等中文文本。

## 注意事项

- v1.16.32 性能缓存思路已被用户废弃，后续不要直接恢复那批缓存改动。
- 当前抽奖候选池来自现有商店/价格体系，重复抽到同一物品是允许的。
- 多人抽奖不追求强反作弊，目标是兼容稳定：服务端只验证余额、候选池和真实发物品。
- 左侧导航滚动是普通按钮位移/显示隐藏方案，避免复用 `ISScrollingListBox` 做导航，降低之前长列表黑屏类问题复发概率。
- 如果后续反馈抽奖结果弹窗没出现，优先检查 `GodSystem_Network.pendingLotteryResult` 是否收到、UI 是否在 result 后触发 `populateList()`。
