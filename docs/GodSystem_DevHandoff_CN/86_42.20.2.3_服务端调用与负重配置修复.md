## 已修复问题

### 1. 多人自动回收重复红字

玩家日志的调用链为：

```text
Add -> refresh -> findAutoRecycler -> isTerminalOwnedByPlayer
```

旧服务端从 `object[methodName]` 取出 Java 方法，再按普通 Lua 函数调用。在 B42.20.2 中，`getContainingItem` 明确要求使用对象方法语法，旧写法会产生：

```text
Expected a method call but got a function call.
Correct syntax: InventoryItem obj:getContainingItem()
```

修复后，终端归属检查直接使用 `container:getContainingItem()`；医疗辅助调用也改为显式的对象方法映射，删除错误的无 `self` 重试分支。

该修复能消除已确认的错误来源。玩家反馈中的网络占用和 `Server is too busy` 可能由重复异常与日志压力放大，但在实机复测前不能断言它们完全由这一处造成。

### 2. 人物负重升级费用缺少配置

此前只有“空间减载每次费用”，它只控制系统空间终端的减载升级。人物负重升级一直固定使用首次 2000、每级 1.5 倍，且没有沙盒或管理项。

现在增加两项：

| 设置 | 默认值 | 只影响 |
|---|---:|---|
| 人物负重首次升级费用 | 2000 | 人物负重能力第 1 级升级 |
| 人物负重每级费用倍率 | 1.5 | 人物负重后续等级价格 |
| 空间减载每次费用 | 2000 | 系统空间终端的减载升级 |

人物负重价格公式保持为：

```text
下一次费用 = 向上取整(首次升级费用 × 每级费用倍率 ^ 当前等级)
```

这三项不会互相影响。

## 设置规则

- 沙盒选项只用于新世界首次建立系统管理配置。
- 已存在的单人世界和多人服务器，使用 `系统面板 → 管理` 修改当前运行值。
- SP 与 MP 都通过 `GodSystemCarryCapacity.getNextCost()` 计算报价；MP 服务端会重新计算后扣费，客户端显示不会决定最终金额。
- 修改费用只影响下一次升级价格，不修改已购买的负重等级，也不退还历史消费。

## B42.20 最小实测

1. 新世界中将人物负重首次费用设为 100、倍率设为 2；人物负重 1/2/3 级应显示并扣除 100/200/400。
2. 已有世界中在系统管理页修改这两项；重新打开升级页后下一次人物负重报价应立即更新。
3. 将“空间减载每次费用”设为 777；系统空间终端的减载升级应扣 777，人物负重报价不变。
4. MP 主机设置两项人物负重值，远程玩家升级时服务端应按相同价格扣费；重连和服务器重启后设置保留。
5. MP 装备系统空间终端后，连续出售背包、嵌套背包及尸体容器转入的物品；日志不得再出现 `getContainingItem` 或 `Expected a method call`。
6. SP/MP 分别触发感染检查、伤势治疗和病毒治愈；不应有同类 Java 调用红字，失败操作不得扣费。
