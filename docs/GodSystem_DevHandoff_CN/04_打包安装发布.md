## 标准 Workshop 结构

```text
GodSystem-main/
  workshop.txt
  preview.png
  Contents/mods/GodSystem/
    mod.info
    42/
      mod.info
      media/
```

游戏安装或 Workshop 上传使用 `workshop.txt`、`preview.png` 与 `Contents`。完整仓库备份可以额外包含 `docs`、`tools` 和仓库说明，但必须排除 `.git`、`.test-runtime`、缓存、日志、临时文件和已有 ZIP。

不要改动 `workshop.txt` 中玩家编写的介绍正文。版本迭代只更新明确的本地版本行、两个 `mod.info` 和运行配置版本。

在仓库根目录执行：

```powershell
& 'C:\Users\wan20\AppData\Local\Microsoft\WindowsApps\pwsh.exe' -NoProfile -File '.\tools\Test-GodSystem.ps1'
```

必须确认：

- 客户端命令均有服务端/SP 处理路径，功能开关不只存在于 UI。
- 实机结果按 SP、联机主机、独立服务器分别记录，不能用自动测试代替。

## 唯一滚动备份

用户明确要求备份时：

1. 在 `C:\APPS\Pzmodproject` 创建唯一临时候选 ZIP，不能直接写正式 ZIP。
2. 用 7-Zip 从 `GodSystem-main` 创建整仓库候选，排除 `.git`、`.test-runtime`、`__pycache__`、`*.pyc`、日志、临时文件和 ZIP。
3. 运行 `7z t`，再用 `7z l -slt` 核对归档根目录。
4. 验证 `workshop.txt`、`preview.png`、两个 `mod.info` 和 `Contents/mods/GodSystem/42/media`。
5. 读取压缩包内版本，确认条目数量、排除项与 SHA-256。
6. 全部通过后才替换 `GodSystem-main.zip`，并清理候选文件。

压缩成功不等于备份正确。多包/少包一层目录、遗漏元数据、打入 Git/测试缓存或嵌入错误版本都必须判失败。

## 本地游戏测试部署

部署前先确认当前 Windows 用户实际使用的 Zomboid Mod/Workshop 目录。只同步运行所需的 `Contents`、`workshop.txt` 和 `preview.png`，随后比较源文件与测试副本哈希。不要把 `docs`、`tools`、`.git` 或备份 ZIP 复制进游戏运行目录。

玩家仍遇到旧行号时，先检查重复订阅、本地 `mods` 副本、Workshop 缓存和启用顺序，再比较报错文件哈希；不要仅凭界面版本文字判断实际加载文件。

## GitHub 与 Workshop 发布

- 用户确认测试通过后，更新交接和版本记录，运行全部检查，再提交并合入 `main`。
- 推送前核对远程 URL、当前分支、待推提交范围和是否包含秘密/日志/第三方资源。
- 标签只在用户明确要求或项目发布流程明确需要时创建。
- 推送 GitHub `main` 不等于上传 Steam Workshop。Workshop 发布必须单独获得明确授权。
- 不上传备份 ZIP、测试运行时、Steam 缓存、参考 MOD、玩家日志、令牌或第三方受限资源。
