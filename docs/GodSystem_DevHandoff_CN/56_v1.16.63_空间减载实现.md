# v1.16.63 空间减载实现

## 目标

v1.16.62 的 Lua 容量方法包装无法覆盖 B42.19 Java 内部容量检查。本版删除该实验路线，终端原生容量恢复为 Lv.1-8/最高49，额外空间改为“空间减载”。

## 原生机制

`GodSystem.SystemTerminalRelief` 是隐藏、不可食用的 Food。脚本基线为 `Weight=1`、`HungerChange=-1`，运行时只修改该实例的 `hungChange=减载/100`。B42.19 的 Food 实际重量公式会得到对应负重量，而容器内容重量会累加该负值，因此 Java 原生放入判定仍然生效。

普通物品、共享 `ScriptItem` 和终端原生容量字段均不被改写。

## 数值与设置

- 默认每次费用：2000系统币。
- 默认每级减载：5点。
- 默认最大减载：2000点，共400级。
- 满级等效空间约为49+2000=2049。
- `TerminalReliefUpgradeCost`、`TerminalReliefPerLevel`、`TerminalReliefMaxOffset` 已加入71项管理/沙盒设置。
- 沙盒只提供新世界首次默认值；系统管理页是运行时权威。修改参数后保留等级，并按新参数重新计算和夹紧。

## 保护与性能

- 内部物品设置 `Hidden`、favorite、unwanted，并加入回收、自动上架和抽奖黑名单。
- 终端内只允许一个顶层内部物品；丢失会重建，重复会删除，逃逸到玩家其他容器会清理。
- 审计仅发生在领取/找回、终端查找、页面打开、升级、自动回收、SP启动、MP握手和显式刷新等边界。
- 不新增 `OnTick`、分钟事件、周期库存扫描或玩家更新轮询；v1.16.62 每300次玩家更新重注册容量的逻辑已删除。

## 多人事务

多人仍复用 `upgradeSystem`，升级类型为 `terminalRelief`。服务端重新读取设置和余额，先快照并应用减载，验证负重量后再扣费；扣费失败恢复等级和内部物品状态。内部物品新增、删除、属性和 ModData 使用现有容器/物品同步函数发送给客户端。

## 验证状态

- `Test-GodSystemV11663.ps1` 通过。
- 完整历史回归、参考研究和 UTF-8 编码检查通过。
- 28个 Lua 已通过 Lua 5.1 `luac -p`。
- B42.19 SP 升级减载主路径已由用户实测通过；MP同步、重连和扩展场景仍待测试。功能分支可以推送 GitHub，暂不合并主分支。

## 首轮实机修复

B42.19 的 favorite 与 unwanted 不是同一组签名：`isFavorite()` 可无玩家调用，但 `isUnwanted(player)` 和 `setUnwanted(player, value)` 必须携带对应 `IsoPlayer`。首轮测试因把二者共用为无玩家布尔接口而报参数数量错误；修复后 SP 使用本地玩家，MP 使用服务端权威玩家，并增加真实签名运行时回归测试。版本号保持 v1.16.63。

用户随后在 B42.19 单人环境重新测试“升级减载”，确认升级主路径正常且不再产生上述红字。该结论只覆盖当前 SP 主路径，不代替 MP、重连、极限容量和内部物品保护测试。
