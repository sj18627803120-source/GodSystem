# v42.20_3.19 拼音搜索、外部来源直接回收与性能诊断

日期：2026-09-28。目标补丁：Project Zomboid B42.20.4。基线：`42.20_3.18.5`。开发自动检查通过，已部署 Workshop 测试副本；游戏实机结果须单独填写。

## 已实现

- 中文搜索支持无声调全拼及首字母，并保留原文、英文及完整物品类型匹配。Unicode 17.0.0 Unihan 固定输入 SHA-256 为 `f7a48b2b545acfaa77b2d607ae28747404ce02baefee16396c5d2d7a8ef34b5e`；生成器为 `tools/localization/generate_godsystem_pinyin.py`。运行期只读取生成后的 Lua 表，不联网。默认读音不能覆盖所有多音词。
- 全物品目录在多人会话重置及游戏启动时清空行、构建和索引；旧构建对象失去共享引用。目录按 64 项形成有序块，再以有限工作量增量合并，避免完成读取后一次性全量排序。Lua 模拟 5000 行排序尾部最大单步约 1 毫秒、360 步；这是模拟值，不代表游戏帧耗时。
- 多人商品分块队列用游标消费，避免从数组头部反复移除。仍每步最多处理 50 条、约 2 毫秒，快照完成后原子切换；5000 条模拟规模回归通过。
- 仅对异常、发送失败、超时和状态不明交易向 `console.txt` 输出版本、运行端、功能、阶段、结果代码及操作 ID。每操作至多一条摘要，不记录完整请求和物品清单。没有经过 MOD 回调的反作弊踢出仍以服务器日志为准。
- 外部来源采用 `selectionVersion=2` 来源描述。地面物品、世界容器、尸体、车辆部件及其中的嵌套背包均可直接回收；服务端从地块对象／静态尸体对象／车辆 ID 和部件重新定位物品，核验同楼层、相邻距离、阻挡、安全屋、容器存在与移除许可、车辆部件访问权。地面物品处理世界对象及可能存在的 floor 容器；其余来源对原容器执行移除、同步和原位恢复。旧背包请求与旧指纹不变，新增来源完整参与回执指纹。重复操作沿用持久化回执。

## 直接回收验收边界

用户决定将上述外部来源一起放入测试版实测，未通过前不发布。适配器只枚举请求所指的已加载地块或车辆，不做后台世界扫描；对于来源消失、身份不符、锁定、无访问权或无法原位恢复的交易返回失败或状态不明。正常背包回收仍使用旧路径。原玩家反馈的“捡起后未回收”具体竞态仍需当次双端日志确认。

接口依据包括同补丁 `ISTransferAction.lua` 的 `DoRemoveItem`、世界物品移除与车辆部件更新，以及 `ISInventoryTransferAction.lua` 的 `isExistYet`、`isRemoveItemAllowed` 和安全屋判断；`ISInventoryPage.lua` 展示了地块普通容器、静态尸体容器和车辆部件的枚举方式。模拟测试不能证明所有原生对象的 SP／MP 同步，故这几类来源均纳入同一次实机验收。
