## 实现内容

### 商品与操作

- 新物品 `GodSystem.UtilityGenerator`，普通商城工具类，基础价 200 系统币；使用原版发电机图标、世界外观及脚本属性，不新增素材，动态涨价按普通商城商品处理。
- 放置时服务端/单人本地创建原生 `IsoGenerator` 对象。标记设备才被专用回调接管；普通原版发电机仍调用原版右键行为。发电机加油入口提示使用系统币充值。
- 所有人可查看、按水/电账户分别充值 100/500/1000 系统币、启停、维修（电子废料）和搬走；无个人或安全屋归属。两笔余额保存在世界 ModData 的设备记录，物品/世界对象只有设备 ID 标记；搬走再放置后沿用同一设备和两笔余额。旧共享余额在首次读取时全部转入水账户，已预付水/燃料保留原预存记录。
- MP 通过服务端命令与现有 opId/指纹/回执处理；服务端重新查玩家物品、设备标记、世界位置、距离、余额与运行状态。重复请求不重复扣款或创建第二台设备。SP 使用相同 `Utility.execute` 业务规则。

### 电力与水

- 主开关、水开关、电开关默认开启。按用户最新确认，公共电力正常时仍由设备运行原生发电机并计费；服务端每 30 秒核对燃料消耗，不逐帧结算。
- 电价默认 5 系统币/原版发电机燃料单位。先从电账户可用余额预留燃料费，再依据实际燃料减少结算；停机、价格调整或搬走时清除剩余虚拟燃料并退还电账户对应未用预留。
- 按用户最新确认，公共供水正常时设备仍供水并计费。只处理具有原版 `waterPiped` 标志、且能回读水量的固定对象；有原生流体容器时走 fluid API，无容器的固定水龙头经写后回读验证使用 `waterAmount` / `waterMaxAmount`。保留原有水量，已有外部水源优先；只对已核验的第三方水源控制标记避让。设备菜单的接水／饮水仍走权威端原生流体接口。
- 水价默认 20 系统币/100 L。固定设施最多预存 100 L，设备直接接水的水箱容量最多 50 L、空闲预存 10 L；费用只从水账户预留，后续按实际取水结算。停机、关闭功能或搬走时先移除本设备剩余的预付水，成功后才退回水账户；公共水恢复不再停供。价格变更不清空已预付水，仅后续补水按新价计费。
- 水/电账户分别判断余额不足，不互相借用、不透支。状态菜单分别显示两账户可用余额、预存费用与供给状态；水尚在扫描或范围内没有发现兼容管道设备时也会显示对应原因。
- 供水扫描限于发电机范围和已加载方块；设备维护表每秒最多处理一次，分帧扫描每帧最多 96 个方块且有约 2 ms 协作预算，供水范围按原生 `IsoGenerator.isPoweringSquare` 判断。水量/状态不会逐帧同步。世界切换时丢弃旧存档的临时扫描队列。
- 沙盒键：`EnableUtilityGenerator`、`EnableUtilityGeneratorWater`、`EnableUtilityGeneratorElectricity`、`UtilityGeneratorWaterPricePer100L`、`UtilityGeneratorElectricityPricePerFuelUnit`。服务器管理员从沙盒/服务器设置中调整；关闭对应开关会停止该项服务，保留设备和账户余额。

## 实机测试清单

1. 单人购买并放置：基础价应为 200（若同账号已购买过且动态涨价开启，则按商店当前报价）；物品只消耗一件，世界中只出现一个标记发电机。
2. 断电场景启用设备：确认同原版发电机范围内照明/电器供电、范围外不供电；观察余额按真实燃料消耗变化。停止后确认发动机燃料归零、未用预留回到账户。
3. 公共电力仍开启时启动设备：确认自备发电机也运行并按燃料消耗计费。分别关闭主开关/电开关，确认状态文案与供电停止。
4. 在公共供水正常和断水两种场景测试带原版管道接口的固定设施：确认初始水量保留、用水后按 20 币/100 L 扣费；余额不足不透支；停止或搬走后本设备剩余补水被清除并退款。同时测试接水到空容器和饮水，确认一次操作只产生一次消耗与效果。
5. 测试雨水/外部水源优先、范围内无管道设施和其他 MOD 水源标记；不兼容对象不能被注水或扣款。
6. 改变水价后确认已预付水不被移除，之后新补水使用新价格；改电价后确认只对未用燃料重新按新价预留。
7. 充值、维修、停机、搬走，再放置同一设备：确认余额和 ID 保持。模拟快速重复操作/网络重发，确认不重复扣款、不多造物品。
8. 房主联机和专用服分别由普通玩家操作，测试两名玩家相互查看/充值/启停、客户端与服务器对象同步、退出重连及服务器重启后设备和余额恢复。
9. 对照测试普通原版发电机加油、维修、启停和搬走没有被本功能拦截。
10. 破坏设备后确认余额随设备损失；若游戏中无法破坏原生发电机，记录为该环境不可测，不以脚本假设代替。

## 遗留与风险边界

- 必须确认 B42.20.4 实机中 `IsoGenerator.new` 与 `transmitCompleteItemToClients` 的构造/客户端可见性，以及固定水龙头 `waterAmount` / `waterMaxAmount` 的原生水量回读和多人同步。写入后不可回读的设施会失败关闭，不会按成功供水扣费。
- 公共水状态按原版沙盒断水时间推断；公共电力优先读取 `getWorld():isHydroPowerOn()`，无可读状态时按公共供应可用处理以避免收费。其他 MOD 的电力供应不一定能由此检测。
- 水只补已加载范围内被原版管道标记的设施，扫描完整度受地图加载和流体对象实际 API 影响。不同模组自定义水源可能使用不可识别的标记或接口，不保证支持。
- 现有 3.17 溅射的 SP、房主和专用服原生击杀归属/任务同步仍未实测，和本版水电一体机测试一起回归。
