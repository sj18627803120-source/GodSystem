# v1.16.71 仓库交互与核心容器修复

## 交付范围

本版从 `fix/v1.16.70-storage-core@e5d13bed` 建立
`fix/v1.16.71-storage-inventory-ui`，只修改系统仓库核心宿主、人物库存交互、
存取协议、连接标记和相应本地化/测试。未修改 `main`、v1.16.63 稳定包、
穿戴式空间终端、人物负重、商城、任务、机器人或经济数值。

当前结果仍是 B42.19 待实机测试版。自动验证通过后只同步运行时文件到本地
Workshop 测试目录，不推送 GitHub、不合并 `main`、不建立稳定标签。

## 核心宿主修复

- 安装系统仓库核心只要求目标是已标记、距离和权限合格的固定网络家具，不再
  要求家具为空，也不调用 `ItemContainer:setCapacity(0)`。
- 核心宿主保留每个储物格的原容量和已有物品。家具的每个储物格继续生成正常
  网络 link，参与索引、分类规则、自动路由、存入和取出。
- 核心身份继续保存到家具 ModData 和网络全局 ModData；核心宿主允许调整角色、
  优先级与分类规则，但管理器和 UI 均禁止取消标记或删除连接。
- `CoreHostVersion=2`、`capacityMode=networkStorage` 表示新宿主模式。v1.16.70
  已锁容量的旧宿主在区块加载、状态同步、核心解析或打开仓库时恢复记录的原容量，
  更新宿主版本后不再重复改写。
- 免费取回和付费找回只移除/失效核心身份，普通网络标记、宿主容量和已有物品均
  保留。区域未加载不会判定核心遗失；家具移动后旧位置身份失效并按既有恢复路线处理。

## 三栏仓库交互

- 仓库页使用人物库存、网络仓库、详情三栏。窗口默认最小 `1120x650`，列宽、
  列间距、列表高度和底部动作栏按当前窗口尺寸重新计算。
- 人物来源包括人物主负重、直属已装备容器、手持容器和钥匙圈。当前来源同时决定
  “存入全部”的直属枚举范围和仓库取出的目标容器，不递归清空其他背包。
- 人物列表按装备/内容分段并按物品组折叠；仓库列表继续使用快照组。两侧用稳定
  组键保存选择，支持 Ctrl 增减选择和 Shift 连选，筛选或刷新后只移除已失效选择。
- 单组右键提供一个、一半、全部，一半按可用数量向上取整；多组右键只处理全部
  当前选择。底部按钮始终处理全部当前选择。
- 详情栏保留类型、MOD、状态、来源、耐久和实例列表；选择具体实例后，统一的
  主取出按钮会切换为精确实例取出。独立“取出选中实例”按钮已删除，未加入拖拽存取。

## 存入保护与装备恢复

- 删除旧 `safeAll` 和递归人物库存收集。`sourceAll` 只枚举当前来源容器直属物品，
  跳过穿戴、手持、热键栏、收藏、钥匙和 GodSystem 保护物品。
- `selected` 手动存入允许收藏、钥匙和装备物品，但系统核心、空间终端及内部减载
  物品仍由统一保护判断拒绝。
- 手动选择装备物品时保存穿戴位置、主副手状态和热键槽，依次排队执行原版
  `ISUnequipAction`。完成屏障触发后再次解析当前来源并确认物品已经卸下，只有
  仍直属来源且未装备的实例才发送存入请求。
- 服务端或本地操作失败时，只恢复失败实例。恢复穿戴、主副手和热键前先检查原
  位置仍为空，不覆盖玩家等待期间换上的新物品。

## SP/MP 协议与事务

- `deposit` 只接受 `selected` 或 `sourceAll`，并携带 `sourceItemId`。服务端重新
  解析人物主库存或直属已装备/手持容器、钥匙圈，只接受仍直属该来源的真实实例。
- `withdraw` 接受多组 `{ groupKey, count }` 或精确 `{ groupKey, itemIds }` 请求，
  使用当前 `snapshotId`，按真实实例 ID 去重，并维持 20,000 件上限。
- 取出目标使用 `targetItemId`，服务端在每件转移前重新解析目标容器、人物库存链、
  原生接受规则和容量；目标消失或身份变化时失败并进入三级恢复，不落入错误容器。
- 操作指纹包含命令、核心身份、模式、快照、来源、目标以及排序去重后的实例/组请求。
  同一操作 ID 只能重试相同请求；`pending`、`done` 和 payload 不匹配分别处理。
- 存取结果 payload 区分 `successItemIds`、`skippedItemIds` 和带原因的 `failedItems`，
  供准确统计和装备恢复使用。
- 仓库 UI 在同类 MP 存取操作仍等待回包时拒绝重入，避免旧操作重试覆盖新选择的
  装备恢复状态；已有操作继续由原 operation ID 和服务端结果缓存结算。

## 连接标记

- 网络状态继续发布 `connectedObjectIds`；仓库容器摘要增加 `objectId` 和
  `isCoreHost`，用于颜色、详情和禁止解绑。
- 连接模式缓存附近已标记对象，同格对象按对象索引和贴图名稳定排序。绿色表示
  核心宿主，蓝色表示已连通普通网络容器，红色表示已标记但未连通容器。
- 世界标记不再绘制菱形数字；第一个对象居中，后续对象向左、向右交替展开，使用
  一至三层短上箭头表示低、中、高。两件家具的右键前缀为低/高，三件为低/中/高，
  更多对象回退到短编号。整组标记统一提高，不再按编号同时向右、向上漂移。
- 未标记家具不常驻绘制，但右键候选使用相同层级。菜单悬停按 B42.19 原版
  `ISContextMenu` 回调签名和 `menu.player` 对应的对象高亮重载临时染色；移开、
  菜单重建、关闭连接模式、断线或返回主菜单都会清理。
- `OnPreUIDraw` 只读取缓存并用 `GodSystem_WhitePixel.png + renderline()` 绘制轻量箭头，不逐帧扫描世界对象。

## 2026-07-27 实机反馈修复

- SP 存入链路调整为“真实事务结果”和“UI 展示回调”隔离。物品移动完成后，即使
  结果提示、装备恢复或列表重建抛错，也会记录诊断并继续启动新索引，避免出现
  “仓库实际增加，但窗口报错且快照不刷新”。新增客户端运行时回归模拟 UI 回调异常，
  同时覆盖选中存入和当前来源全部存入共用的刷新边界。
- MP 已完成操作 ID 的重放结果会重新启动索引；成功标记/取消标记网络容器后，SP/MP
  都从当前已安装核心立即重算并发布 `connectedObjectIds`，不再要求先打开仓库或手动刷新
  才把新连接从红色更新为蓝色。
- 容器管理页使用 `selectedLinkId` 绘制稳定选中背景，刷新后按 link ID 恢复；SP 隐藏
  “管理员接管”，MP 仅管理员可见。
- 来源筛选和详情使用“家具/储物格名称 + 短编号”，来源摘要最多显示两个截短名称和
  额外来源数量，不再展示完整对象 ID。
- 自动验证新增 `Test-GodSystemV11671ClientRuntime.lua`，并扩展连接摘要、箭头层级和
  管理/取出 UI 静态约束。
