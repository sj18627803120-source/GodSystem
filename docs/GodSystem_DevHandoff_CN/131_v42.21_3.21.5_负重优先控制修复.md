# v42.21_3.21.5 负重优先控制修复

日期：2026-10-10。开发基线为用户已验收的 `42.21_3.21.4`；本版仅修复负重控制、交易边界和相关同步/显示。目标为本机 B42.21.0。开发检查通过后部署 Workshop 测试副本，等待实机验收；不发布、不提交/推送Git，不替换3.21.4滚动ZIP。

## 规则和实际变化

等级大于零才接管。每级仍为2000系统币、基础负重+2，目标基础固定为 `8 + 等级×2`。最终值由原版 `BodyDamage.UpdateStrength()` 计算，保留力量和身体惩罚；原版特质倍率按 Strong 1.5 → Weak 0.75 → Feeble 0.8999999761581421 → Stout 1.25 → 无特质1的优先级选择。不再接受其他MOD写入的同字段基础/倍率/最终值，不把力量等级改掉，不增加容器容量或新的沙盒开关。

健康且无相关特质、力量因子1.58时，三级基础14，原生最终22；饥饿/受伤时最终值仍可下降，最终零也是合法结果。零级角色保留其他MOD效果；受控角色降为零时撤销本模块控制，并发送一次退出投影，不持续心跳。

已购账号等级、SP旧档迁移、Mod ID、Workshop ID与存档键不变。UCWF不再自动接管已升级角色；仅移除能通过对象身份确认属于本模块的修饰器，未知或其他MOD贡献不删除。没有50上限，但原生float/int安全范围仍会阻止极大数值购买。

## 修复证据及接口

旧源码和隔离测试确认：不明外部基础值触发 `externalConflict` 拒购/停止恢复，连续基础重置触发越来越长的冷却，最终值单独被改小可能未检查。新测试替换这三类旧保护断言，验证持续重置100次可恢复且继续升级。

同补丁原生依据：`IsoGameCharacter` 的 `get/setMaxWeightBase`、`get/setMaxWeightDelta`、`get/setMaxWeight`、`getWeightMod`、`getCharacterTraits`、`isDead`、`getOnlineID`，`CharacterTraits.get(CharacterTrait)`，以及 `BodyDamage.UpdateStrength`。基础setter只写字段，不能代替原版最终重算。Java内部调用不会使用Lua替换的力量getter；本版不做这种包装。原版伤害网络包可直接更新final字段，客户端不会每帧反写旧final。

最终Carry源码 SHA-256：`b3b2d1e9d4d53e5ccd7b05db4f1f0bb3acb3201ec11be69c6a258408d8d21e9d`。游戏JAR SHA-256：`e1a69eb743ede60b213a0fe7f8b83d4fcab773036d256cc4543a336f3b058a33`。原生探针通过本机Java/Kahlua执行实际字段、实际特质对象与实际UpdateStrength；构造、力量输入及moodles使用隔离夹具，不加载世界或网络，不能称为多人实测。Feeble写入0.9后读回实际为float值，采用标准值避免持续纠正。

## 实现路径

- `shared/GodSystem_CarryCapacity.lua` 保留原公开接口。成员查找和调用均受pcall保护，false不会被当成nil或调用失败。实际实例方法表及继承链定位setter；受控角色基础/倍率写入重定向，外部final setter忽略，其他角色直接透传。应用、投影和回滚带异常安全的内部绕过。每个入口只包装一次；后装的其他包装不反复抢占，退出只恢复仍由本模块占有的入口。无法完整安装时明确显示“字段纠正”。
- 临时OnTick工作器按真实时间100ms节流，仅持有已激活角色。SP/服务器发现基础、倍率或final变化时调用原版重算，接受合法身体变化；稳定每角色每步四次读取（存活、基础、倍率、final），不写字段、不重算、不扫背包、不读取账号、不发网络消息。最后角色退出即移除工作器。真实帧率决定实际恢复时机。
- 真正接口失败时每5秒尝试，等待期跳过失效对象读取，30秒汇总；不因外部覆盖退让或拒购。数值预留256的float/int转换余量，检查中间 `base×factor` 及最终乘积，避免饱和截断。低频账号维护检查等级/特质/力量因子；稳定时不建立多余交易快照。
- 购买先检查旧字段可完整回滚，无法读取旧字段时不做临时修改；再原生应用核验，随后扣款并提交等级/统计/回执。失败扣款恢复精确基础、倍率、final、标记、保护参与与可确认的框架贡献；首次购买失败无免费加成。服务端成功回执先确保持久化，再通知；通知失败保留成功并重同步，真正持久化失败进入原unknown路径，不自动退款/重买。其余交易分支不重构。
- `CarryState` 为 `policyVersion=2` / `mode=priority`，含等级、基础、标准化倍率、实际final、身份/token、业务revision和pushSequence。相同revision可接受更高发送序列；旧序列/旧token/错误身份不能覆盖。完整状态只在已清理的会话建立token，连旧完整状态也不能切换已初始化的会话。新客户端收到旧策略提示两端更新。
- 服务器沿用1秒在线维护，连续纠正合并每角色最多每秒一次，稳定5秒心跳，仅本人、仅升级角色。完整状态/购买/手动恢复照原路立即发送。客户端按投影控制基础/倍率，仅收到新投影时应用final，不持续调用本地UpdateStrength，不与合法伤害包争抢。死亡、角色替换、断线、退出和会话重置清理引用和比较状态。
