# v1.16.63 多人终端穿戴修复

## 问题

多人玩家反馈刚领取或升级后的系统空间终端无法穿戴；部分玩家重登后终端实际已穿上，但随后终端及其他衣物都可能无法正常穿脱。本机历史日志曾出现 `ISTimedActionQueue:tick: bugged action, cleared queue ISWearClothing`。

## 根因与修复

- v1.16.54 旧独立槽只完成了 registry ID 与物品脚本字段，漏掉 `BodyLocations.getGroup("Human"):getOrCreateLocation()`，因此不能据此判定完整独立槽不可用。
- 当前终端重新使用 `GodSystem:SystemSpaceTerminal`，在 registry、Human Group、`BodyLocation`、`CanBeEquipped` 四处保持一致，并复用原版透明 `AthleticCup` ClothingItem。
- MP 客户端查找和展示终端改为只读，不再本地改写容量、减重、名称、ModData 或减载核心。
- 服务端终端应用改为差异写入；无变化时不调用 setter，也不发送外层终端 stats/ModData。
- 后台刷新和终端自动回收避让原版 Timed Action、库存拖拽与选择，并按一秒间隔重试。
- 旧 `base:necklace` 槽中的终端登录时只解除到主库存，保留内容和等级，由玩家使用原版流程重新穿戴。

## 验证状态

- `Test-GodSystemV11663TerminalWear.ps1` 覆盖四步注册、原版透明 ClothingItem、MP 客户端只读、差异同步和交互避让。
- v1.16.63 运行时测试覆盖连续两次减载审计，确认第二次不调用 setter、不生成变化报告。
- 统一 `tools/Test-GodSystem.ps1` 已通过全部专项、历史回归、参考研究、编码检查和 29 个 Lua 的 Lua 5.1 编译。
- B42.19 主机、远程玩家、重登、其他装备穿脱及战斗后稳定性仍待用户实机验证。
