# v1.16.72 系统自动装填机实现与验证

## 交付范围

本版从 `fix/v1.16.71-storage-inventory-ui@420eba0` 建立
`feat/v1.16.72-auto-loader`，新增一个独立的随身弹药数字化工具。仓库实机反馈修复
已经包含在基线提交中，本版没有重写仓库、任务、银行、空间终端或人物负重。

本版在开发期间先作为 B42.19 待实机测试版，仅同步运行时文件到本地 Workshop。
用户于 2026-07-28 确认最新版已经发布并可作为正式版；正式 Git 基线为 `main` / 标签 `v1.16.72`。

## 已确认玩法规则

- 新物品为 `GodSystem.SystemAutoLoader`，中文名“系统自动装填机”，重量 `0.5`，
  商城默认售价 `1000` 系统币。
- 装填机自身不是容器。账本保存在该物品实例的 ModData 中，每个弹药 `fullType`
  独立计数，默认每种上限 `2000`，不同弹种不能互相支付。
- “存入全部散装弹药”只接受 B42 注册标签 `ItemTag.AMMO`。人物主库存先扫描，
  随身嵌套容器再按容器与物品稳定 ID 排序；原版收藏弹药会跳过。
- 单次快照最多检查 `20,000` 个候选，存入每批结算 `500` 发；显示动作时长按
  `1 + ceil(数量/100) * 0.5` 秒计算并封顶 `15` 秒，会话最长保留 `60` 秒。
- 手动装填扫描随身独立弹匣，按当前装填量从高到低处理，优先补满最接近满的弹匣。
  枪械本体和枪内弹仓不会被直接修改。
- 弹种匹配使用 B42.19 原版同路线 `magazine:getAmmoType():getItemKey()`，再用返回的
  完整物品类型读取对应账本余额。setter 抛错或写入后复验失败时，精确退回从各台
  装填机预扣的数量。
- 携带多台装填机时，快速装填按当前弹种余额从低到高消耗，同余额再按物品 ID
  稳定排序。快速换弹真正排入原版动作队列后，在队尾增加一次装填动作。
- UI 显示弹药图标、名称、当前数量、每种容量和缺失 MOD 状态；选中一行可一次
  取出 `1-500` 发。缺失 MOD 的账本记录保留且不可取出，MOD 恢复后可继续使用。

## 商城、设置与排除规则

- 默认商城条目 ID 为 `system_auto_loader`，三条购买路径都重新检查
  `featureKey = EnableAutoLoaderShop`：SP 购买、商城列表和 MP 服务端结算。
- `EnableAutoLoaderShop=false` 只隐藏并禁止商城购买，不影响已经持有的装填机。
- `AutoLoaderAmmoCapacity` 默认 `2000`，管理员/沙盒范围 `100-10000`。降低容量不会
  删除已有超额数字弹药；该弹种停止继续存入，直到取出或装填使余额低于新上限。
- 装填机加入抽奖、自动上架和回收黑名单；按已确认业务规则不加入任务物品黑名单。
- CN、CH、ASCII-only Lua fallback、原版 JSON 物品名/Tooltip 和沙盒设置均由 UTF-8
  YAML 同源生成。本版预期 `795` 个 UI 键、`13` 个物品键、`73` 项管理员设置。

## SP/MP 与存档边界

- SP 的查看、存入、手动装填、取出和快速换弹后置装填直接调用共享结算，不依赖
  `sendClientCommand` 或 SP 环境不一定加载的服务端文件。
- MP 查看和即时操作由 `GodSystemAutoLoader` 命令模块处理；服务端按真实物品 ID
  重找仍由该玩家携带的装填机、散装弹药和弹匣，再执行删除、创建、字段/ModData 同步。
- 网络 Timed Action 位于 `media/lua/shared/TimedActions`。构造参数与序列化字段原样
  对应；服务端 `getDuration()` 只读取自身会话保存的真实总数与批数重算耗时，不信任
  客户端序列化数量。客户端 `perform()` 只处理进度显示。
- 开始存入、手动装填、取出和快速换弹后置动作使用操作 ID 与规范化指纹。
  同一 ID 只能重放相同请求；持久记录中的未完成 `processing` 在重载后转为 `unknown`。
- 数字账本保存在装填机实例 ModData，随物品存档。多人并发最终仍以服务端持有的
  实例为准；会话内每批只结算仍存在、类型未变化、仍非收藏的真实弹药。

## 2026-07-27 首轮实机反馈修复

首轮 B42.19 SP 测试确认了三个客户端问题：普通物品右键的“回收 / 回收并上架 /
仅上架”不显示并抛出 `Object tried to call nil in canContextRecycleItem`；同一右键事件链
中的自动装填机菜单也因此没有执行；仓库人物物品列表向上滚动时，行内容会画入上方
人物容器来源区域。

根因与处理：

- `GodSystem_Core.lua` 和 `GodSystem_Server.lua` 共六处仍调用 v1.16.70 已退役的
  `GodSystemStorage.isController(item)`。现统一改为当前共享接口
  `GodSystemStorage.isProtected(item)`，同时保留空间终端、仓库核心、内部减载物品及
  现有回收黑名单保护。
- 回收处理器的异常会中断 `OnFillInventoryObjectContextMenu` 监听器序列，因此装填机
  自身没有产生第二个独立错误；修复前置异常后，装填机的“打开 / 存入全部散装弹药 /
  装填全部弹匣”子菜单可继续加入同一个右键菜单。
- 仓库自定义列表行原先覆盖 `ISScrollingListBox.doDrawItem` 后没有保留原版的滚动可见区
  判断。现按 B42.19 原版 `y + getYScroll()` 计算行的可见范围：完全越界行不绘制，
  部分可见行使用逐行 stencil 裁剪，并在每行后恢复列表自身 stencil，避免文字、图标、
  选中背景画到上方来源列表。

新增 `Test-GodSystemV11672ContextRuntime.lua` 与 `Test-GodSystemV11672UIRuntime.lua`：
前者覆盖普通物品三个菜单、核心/终端/装填机保护及回收后装填机处理器继续执行；后者
覆盖顶部/底部越界跳过、顶部部分行裁剪和 stencil 恢复。本节修复仍需用户重新实机确认
右键菜单与仓库滚动表现，不能据自动测试标记稳定。

## 2026-07-27 第二轮仓库界面与连接模式修复

第二轮 SP 测试确认右键菜单与自动装填机均恢复正常，但人物主库存的物品行全部不可见；
切换到内容较少的钥匙圈等来源时才会出现部分内容。上一轮逐行裁剪在绘制结束后再次调用
`setStencilRect()` 试图恢复整个列表范围，但 B42 的嵌套 stencil 会继续求交集而不会扩宽，
导致第一行以后逐步被裁成空区域。

本轮按同版本原版 `ISItemsListTable` 的做法改为每行绘制后调用 `clearStencilRect()`，并补齐
B42 可复现的两个列表复用边界：

- 每次重建来源、人物库存、网络仓库或详情列表时，同时重置 `YScroll`、滚动高度、
  `smoothScrollTargetY` 和 `smoothScrollY`，避免 `clear()` 后保留旧滚动位置。
- 所有四个列表在 `prerender()` 前后重新同步 `vscroll.x` 与 `vscroll.height`，避免窗口
  缩放后长列表使用旧滚动条宽度计算 stencil，出现长列表黑屏而短列表可见。
- 运行时测试用“新 stencil 只能与旧 stencil 求交”的模型连续绘制两行，确认清除第一行
  stencil 后第二行仍能绘制；同时覆盖旧滚动重置和滚动条几何同步。

连接模式新增独立的轻量连通摘要刷新：开启时立即刷新，此后每 `5000ms` 刷新一次；关闭、
断线或返回主菜单后停止并清除计时。SP 直接读取 `networkSummaryForPlayer()`，MP 新增只读
`networkState` 命令，由服务端重新计算 `connectedObjectIds`；不会每 5 秒重建仓库物品索引。

系统快捷栏末尾新增动态“开启连接模式 / 关闭连接模式”按钮，固定追加在回家、返回、腰包
回收和存入现金等已有动作之后。点击后立即切换高亮模式并刷新按钮文字，不会抢占第一个位置。

第二轮修复仍需实机确认人物主库存长列表、钥匙圈/背包来源切换、滚动顶部裁剪，以及快捷栏
按钮顺序和绿/蓝/红连接状态在 5 秒内更新；当前仍不是稳定版。

## 2026-07-27 第三轮仓库存入路由修复

第三轮 B42.19 SP 测试确认仓库取出正常，但存入在
`GodSystem_Storage.linkRoleAccepts()` 抛出 `Object tried to call nil`。实际失败点是分类白名单判断直接调用
全局 `next(allow)`；标准 Lua 5.1 提供该函数，因此旧运行时回归没有暴露问题，但 B42.19 的 Kahlua
环境中该全局函数不可用。

本轮只替换这一项不兼容判断：使用该路由调用链已经正常工作的 `pairs()` 检查白名单是否包含规则，
保持空白名单允许自动路由、匹配白名单允许存入、不匹配白名单拒绝存入以及角色分类逻辑不变。
新增 `Test-GodSystemV11672StorageRoleRuntime.lua`，测试会临时将全局 `next` 设为 `nil`，覆盖空白、
匹配和不匹配三种规则。修复前该测试稳定复现第 991 行 nil 调用，修复后通过；统一测试、压力检查、
编码检查及 42 个 Lua 文件的 Lua 5.1 编译同时通过。仓库存入仍需 B42.19 SP 实机复验，MP 路由
使用同一共享函数，也需后续并发门槛测试确认。
