## 根因与证据边界

玩家日志已确认的错误是：

```text
getContainingItem: Expected a method call but got a function call
Add -> refresh -> findAutoRecycler -> isTerminalOwnedByPlayer
```

确定结论：B42.20 Java bridge 不接受把 Java userdata 方法取出后当普通 Lua 函数调用。`ItemContainer:getContainingItem()` 用于从嵌套容器反查拥有该容器的物品，旧调用失败会让自动回收终端无法确认“终端仍属于该玩家”，并持续产生红字。

静态审计结论：终端同步、升级、自动装填、仓库、属性、维修和物品识别还存在同型调用写法。它们没有全部被玩家日志逐一证实已报错，因此只能称为同类风险；本版按相同 B42 调用规则统一消除。

## 实现边界

- 新增 `GodSystem_B42JavaCalls.lua`：只对白名单方法使用 `target:method(...)`；未知方法只允许普通 Lua `table` 走动态调用，Java userdata 不允许任意方法名执行。
- 自动回收归属使用 `GodSystemB42JavaCalls.getContainingItem(container)`。
- 服务端终端状态、客户端权威写回、终端升级和回滚使用明确的容量/减重 helper，并保留写前读取、写后验证和失败回滚。
- 自动装填、仓库、属性、医疗、维修、经济转换索引和物品配置继续使用原业务函数，只替换底层 Java 调用方式。
- 同伴光源的 Java 实例调用改为闭包中的显式冒号调用；Lua 回调、`ModData`、工厂静态方法和其他静态 API 不套用 userdata 规则。
- 翻译 YAML 中的显示百分号统一写为 `%%`；CN/CH 和 Sandbox 生成文件保持 `%%`，Lua 回退在编码前恢复成单个 `%`，避免界面显示双百分号。

本版没有改变任务、银行、商城/回收定价、终端等级/价格、人物负重价格、协议命令、存档字段或权限。终端容量最大值仍为 49。
