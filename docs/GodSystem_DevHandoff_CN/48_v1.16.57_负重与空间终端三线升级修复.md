# v1.16.57 负重与空间终端三线升级修复

## 基线与范围

- 开发分支：`feature/v1.16.57-carry-recycle`。
- 接续基线：`b2fecba`。
- 版本保持 `1.16.57`，未合并 `main`，未覆盖稳定包。
- 本轮修复人物负重倍率错误，将系统空间终端拆为容量、减重、压缩三条升级线，并处理家具变体、任务错字和库存扫描热路径。

## 人物负重修复

`getMaxWeightDelta()` 在当前游戏行为中作为基础负重的倍率参与最终值，不能直接写入“等级 × 2”。新实现会先移除 GodSystem 上一次记录的倍率，读取不含本 Mod 的最终基础，再用 `等级 × 2 / getMaxWeightBase()` 换算需要写入的倍率。写入后最多进行三次小范围校正，并验证最终负重等于“外部基础 + 等级 × 2”；仍不准确则恢复旧值且不扣币。

旧版错误存档若保存了 `GodSystemCarryAppliedBonus=6`、`GodSystemCarryAppliedDelta=6`，刷新、读档或重新握手时会识别为旧倍率写法。基础 14、等级 3 的目标结果为 20，不重置等级，也不再得到 98。

## 终端三条升级线

- 容量：`10、15、20、25、30、35、42、49`。
- 减重：`50%、55%、60%、65%、70%、80%、90%、99%`，只写终端 `ItemContainer:setWeightReduction()`。
- 压缩：`0%、15%、30%、45%、60%、75%、85%、90%`，只写终端内真实 `InventoryItem` 实例的 `setActualWeight/setCustomWeight`。
- 旧 `autoRecyclerLevel` 首次迁移到容量和减重，压缩从 1 级开始；恢复费用取三条等级中的最高等级。
- 腰部空间页保留出售、自动回收和模式开关，并新增三个独立升级按钮。多人命令等待时底部动作按钮统一禁用，压缩按钮显示“正在压缩”。

压缩管理器保存原始实际重量、原自定义重量状态、最后应用重量、终端 ID 和压缩版本。重复升级始终从原重计算，不在压缩结果上继续相乘；最低重量为 `0.01`。递归最大深度 32，使用访问集合防循环，内部按 32 个实例分组处理。原本已有第三方自定义重量、且没有 GodSystem 标记的实例会跳过并计数。

物品移出终端、终端移交或掉落时，只由原终端恢复自己拥有的标记。单人使用容器变更事件及时校准，并保留每 300 次玩家更新一次的缓存兜底；多人由服务端缓存真实终端，按真实实例修改和同步，客户端只显示状态。死亡和退出路径会恢复缓存中的实例。未调用任何全局 `ScriptItem:DoParam()` 或脚本重量修改。

## 家具、文本与性能

- 自动商城身份从单一 `fullType` 改为 `fullType + worldSprite`。床（1）与床（2）可分别上架；购买 Moveable 时通过 `InventoryItemFactory.CreateItem()` 创建实例，再用 `ReadFromWorldSprite()` 恢复准确组件。创建或贴图核验失败时不扣币，已发放部分走原有回滚。
- 右键“仅上架/回收并上架”的客户端预筛和 SP/MP 服务端复验都使用家具变体键；普通回收仍按真实选中实例处理。
- “区域踏查”已统一修正为“区域调查”。新增文本从 UTF-8 YAML 生成 CN、CH 和 ASCII-only Lua fallback。
- 顶部货币显示改为一次递归库存遍历并缓存 250ms；多人优先读服务端余额。玩家更新不再每 60 次全库存搜索和排序终端，只校准已缓存终端并低频兜底。
