# v42.21_3.23：银行模拟股市开发技术方案与交接

日期：2026-10-20。基线为用户已验收、已覆盖滚动备份的42.21_3.22.1。本版依用户确认的完整方案和两轮复审执行；开发完成后仅部署Workshop测试副本，不发布、不提交/推送、不覆盖3.22.1备份。当前游戏内SP/房主/专服均等待用户测试，自动回归不等于实机通过。

## 1. 功能与经济规则

- 银行下方“模拟股市”打开独立窗口，行情/持仓/资讯三页，支持全拼和首字母搜索、1/3/7日图表及数量快捷按钮。窗口沿用终端配色和三档字号，保持唯一实例，关闭释放订阅。
- 8行业各3家公司，共24支，稳定ID为`tool/security/biotech/food/medical/energy/industry/logistics`加`_01..03`；初始价80/100/120，波动及经营敏感系数0.8/1/1.2。固定目录，不做公司编辑器。
- 存档内所有玩家共享价格，账号各自持仓；只使用银行活期，T+0。死亡保留持仓，不跨存档。无杠杆、做空、分红、退市或玩家撮合。
- 分价为整数。买入总额向上取整、卖出向下取整，买卖各收默认0.5%，非零费率最低1币；费率转基点，以0.01个百分点为精度，0不收最低费用。持仓成本包含买入费，部分卖出整数分摊，清仓带走成本余数。
- 不设置永久1币底价；价格不可安全表示则暂停该股票，保留最后安全值和持仓。

## 2. 模型与实现入口

共享模块`GodSystem_StockDefinitions/StockMarket/StockNews/StockTrading/StockActivity/StockService`分离金额、模型、新闻、账本及游戏适配。`GodSystem_OperationLedger`提供纯回执原语，旧服务端回执保持原有读取/迁移/裁剪行为，仅复用兼容的操作ID检查。

客户端`GodSystem_StockClient/StockMarketUI`管理SP适配、MP会话及独立窗口；服务端`GodSystem_ServerRuntime_Stocks`通过现有installer装配。后台复用每秒在线维护入口及其玩家循环，按需启动约2ms的临时结算工作器，完成即移除。无世界、背包或全账号扫描。

### 自然参考与市场价格

- 每公司扩张/平稳/承压概率30/40/30%，默认阶段72–168在线游戏小时。
- 阶段目标相对自然参考：扩张+4%至+12%，平稳对数±log(1.02)，承压对应负向4%至12%；每小时对数按0.025靠近目标。
- 有效参考为`F × [1+公司系数×行为倍率×(S+L)] × exp(情绪偏移)`。自然F不混入旧行为加成，避免重复复利。
- 价格对数每小时按0.06靠近有效参考；大盘噪声±0.002、行业±0.004，公司噪声为两个均匀数平均后的±0.02乘公司系数。随机倍率只影响噪声。默认小时简单收益截断±6%，倍率>1同比扩展。
- 净买卖影响`0.002×clamp(净股数×本期公开单价/(初始价×2000),-1,1)×交易倍率`，期末只应用一次，等量买卖净影响为零。
- Park–Miller随机流按大盘/行业/公司阶段/公司噪声/事件/新闻排期/文案分离并持久化。UI、新闻开关不能消费行情随机流。固定数组顺序迭代。

### 行业贡献

默认24小时热度四档：常规消费1000/3000/10000/30000；安保击杀50/150/400/1000；生物正面特质消费2000/8000/20000/60000。

工具购买→工具；原生击杀有效增量→安保；正面特质购买→生物；食品/饮料/农业→食品；医疗购买及成功治疗/治病→医疗；电子及一体机购买→能源；材料及家具变体→工业；车辆/容器购买和成功收费传送→物流。检查病毒、特质移除、退款、失败和股票交易均不贡献。

普通解锁商品也有variantKey，因此不能据此判断家具；只使用非空worldSprite识别家具。组合商品按内容参考价值分配实际支付金额，最后一项承接整数余数，总分摊不得超过支付额。

- 短期目标0/0.1/0.2/0.35/0.5%在阈值节点线性插值，每小时0.25靠近。
- 最高档长期值每小时0.125靠近1.5%。退出后12小时半衰期；最高档期间24小时内至少3个小时各贡献≥T1/4，标记持续经营，退出后改36小时半衰期。单次大额也可进入最高档。
- 长期值低于0.000001且已退出最高档时归零并清持续标记。默认三家公司充分经营偏移约1.6/2/2.4%，不是保证收益。

## 3. 时钟、结算和新闻

市场逻辑时间仅在有玩家在线且银行/股市开启时累计世界时间差；保留小数，首次、重连及重启重设运行锚点，不补算离线，时间倒退不回滚价格。

封存小时输入后使用临时随机副本和价格结果分批计算，新贡献进入未封存小时。提交时一起更新价格、随机状态、已结算小时、新闻及输入消费标记。取消任务丢弃所有临时结果，不推进正式随机状态；配置变化以签名取消旧任务。交易在结算期间返回“更新中”，不扣钱。重启重算已存输入，不保存原生对象或运行工作器。

最多168小时积压；达到后暂停市场逻辑时钟和股票交易，其他系统继续，贡献合并到固定8行业缓冲。积压降至24小时内后恢复，缓冲计入首个未封存小时，不补行情、不伪造净成交量。异常贡献达到数值上限采用饱和保护并诊断。恢复规则只适用于异常积压，不是日常跳过行情。

事件每24–72小时：80%经营事件，20%传闻；真实事件修改当前阶段目标一次，幅度约±2–6%。每公司一个活动事件，全市场最多一个未核实传闻。传闻70%属实，12–36小时核实；情绪目标±0.5–2%，按0.25靠近，核实后回归0。属实增加一次真实目标影响，不实不改F。未曾发布且已解决的传闻不补发过期消息。

每天随机1至上限条，默认最多3；发布槽8/16/24小时，第24小时先归属旧日再换日。核实结果优先，行业报告每天最多一条；无事件可给市场观察。0新闻不停止事件或价格。候选16/历史64，键和参数本地化，不泄露真实性、隐藏参考和种子。

## 4. 交易、贡献与存储边界

全局市场在`GodSystem_CN_StockMarket`，个人持仓在既有账号`bank.stocks`。普通状态投影排除stocks；专用订阅只发送公开24行情、本人账户和选中股169点历史，最多50成交和64回执。

交易请求包含opId、股票ID、方向、整数股数、报价/配置版本和账号下一序列。先查回执，再核对序列；前置拒绝不消耗序列，正式交易开始后成功或完整回滚都关闭本序列。已淘汰回执的旧序列仍拒绝。相同操作不同内容拒绝；同一账号一个待完成客户端交易。

正式变更为同一不让出执行权的调用：保存意图/快照→更新余额/持仓/成本/净股数→核验→回执和提交标记→通知。异常完整回滚才能返回失败；恢复失败保留unknown，仅暂停股票。提交后通知失败不退款。

**重启绝不拿旧余额快照覆盖当前银行余额**：存取款、利息和其他消费可能已发生；只凭一致的回执/序列/提交标记确定结果，不明就隔离。ModData按游戏保存周期写盘，不提供跨表数据库级断电原子性，不宣称每笔强制落盘。

经营贡献使用账号8行业单调累计计数作有界outbox，全局市场保存对应消费水位。成功业务阶段记录，原操作重复回执不重复记录；迟到计数进入当前未封存小时，不改历史价格。消费输入和推进水位之间无回调/让出；失败下次维护重试。分类/记录异常只计诊断，不把成功购买改失败。不可分类异常不会猜测行业，需要日志定位；此处不能承诺未知代码异常下的贡献永不丢失。

MP窗口会话校验token、客户端代次和独立pushSequence；同一价格版本的旧余额包也不能覆盖新账户。旧交易结果可结束同op等待，但不能用旧视图覆盖更新快照。普通快照无全局模型、回执、outbox或他人持仓。

阶段时长仅新阶段生效；噪声/经营/交易影响下一结算生效；费用和开关更新交易配置版本，使旧报价失效。新闻和文字变更不改变价格随机流。关闭保留账户和输入，不清仓。CN/CH/EN和fallback由YAML生成，说明书由terminal_guide.json生成。
