# v1.16.66 控制器运行时与仓库动作栏修复

## 实机证据

B42.19.0、单人模式点击背包右键“安装系统仓库控制器”后连续出现：

```text
attempted index: start of non-table: null
GodSystem_StorageContext.installController(GodSystem_StorageContext.lua:117)
```

对应源码第117行是：

```lua
GodSystemStoragePlacement.start(payload.playerNum or 0, payload.item)
```

因此可以确定点击时 `GodSystemStoragePlacement` 为 `nil`。源码仓库虽然包含独立 `GodSystem_StoragePlacement.lua` 和 `require`，但当前设备无法读取玩家实际加载的 Workshop 目录，所以不能把“安装包漏文件”和“实机加载顺序没有执行文件”中的任一种推测写成确定根因。可以确定的设计缺陷是：已加载的右键入口依赖另一个文件创建的可变全局。

同一张实机截图还确认仓库页在“控制器已领取”状态下，右侧重新显示了空间终端页面遗留的“一键出售全部”。`populateStorageNetwork()` 先隐藏次按钮，随后又把 `secondary` 无条件传给 `setActionBar()`；而 `setActionBar()` 会把传入的控件重新设为可见，因此旧标题被恢复。

## 修复

- 删除独立 `GodSystem_StoragePlacement.lua`。
- `GodSystem_StorageContext.lua` 直接加载原版 `BuildingObjects/ISBuildingObject`，并在文件内定义局部 `ControllerPlacement`。
- 背包安装回调直接调用同一文件内的 `ControllerPlacement.start()`，不再使用 `GodSystemStoragePlacement` 全局。
- 不增加 `nil` 保护、`pcall(require)` 或通用“暂不支持”提示；如果必需的原版类或内部实现再次异常，开发测试仍保留真实红字和调用栈。
- 仓库动作栏默认只传入主按钮；仅当 `storageSecondaryAction` 为强制找回时才加入次按钮。

安装、收回、首次免费、2000付费找回、操作ID、防复制和服务端事务均未修改。

## 项目调试规则

从本版起，必须存在的内部模块、函数和数据不再为了阻挡红字而随意增加 `nil` 判断、`pcall` 或静默跳过。正常业务拒绝、可选外部接口、多人验证和货币/物品回滚仍按原规则处理，因为它们是功能边界而不是掩盖编程错误。
