# v1.16.70 仓库核心设计

## 基线与目标

- 开发分支：`fix/v1.16.70-storage-core`
- 基线：`fix/v1.16.69-custom-controller@151b0fc`
- 游戏目标：Project Zomboid Build 42.19
- 稳定兼容基线仍为已经发布的 v1.16.63；本分支通过 B42.19 SP/MP 实测前不是稳定发布版。

本版撤销 v1.16.65-v1.16.69 的独立世界控制器路线。`GodSystem.StorageController`
内部物品 ID 为兼容旧存档继续保留，但玩家可见身份改为“系统仓库核心”，不再是
Moveable 家具。核心安装到一个已经标记且完全为空的网络家具后，该家具成为仓库入口
和物理网络根节点。

## 核心宿主

- 安装前验证核心实例、网络、家具对象 ID、距离、安全屋权限及全部储物格为空。
- 安装时保存每个储物格的原容量，将容量写为 0 并读回验证；失败完整回滚。
- 核心不作为普通容器物品保存，而是转换为宿主对象和网络 ModData 中的令牌状态。
- 核心宿主不参与索引或物品路由，只作为同格堆叠及四方向紧贴网络的桥接节点。
- 正常取回免费：恢复各储物格原容量、返还核心，家具继续保留普通网络容器标记。
- 每个安全屋或个人网络只能有一个有效核心。

## 卸载、遗失和迁移

- 家具顶层 ModData 保存网络标记、对象 ID、核心令牌及原容量；全局仓库 ModData 保存
  网络、宿主位置和核心状态。
- 区域未加载时保持 installed 状态，不把暂时无法解析的对象当作删除。
- 宿主重新进入加载范围时重新校准容量 0；已失效宿主恢复原容量并清除核心字段。
- 只有目标方格已经加载且对象 ID 不存在时，才把宿主判定为拆除、移动或替换。
- 付费找回固定 2000 系统币，生成新令牌；已加载旧宿主立即解锁，未加载宿主在下次
  解析时解锁。
- v1.16.69 背包控制器转换成核心；已安装旧控制器失效并迁移为可重新安装的核心；
  已有网络容器标记和真实物品不变。

## 清理边界

删除自制 Moveable 控制器的贴图包、tiledef、构建脚本、放置/拾取/世界对象解析、
旧右键打开/收回及对应测试。只保留一次性旧存档迁移所需的旧字段读取，不继续暴露
旧控制器命令或 UI。

连接模式关闭主系统窗口后继续保持，直到玩家手动关闭、断线或退出世界。蓝色符号表示
普通网络容器，绿色符号表示有效核心宿主；绘制只读取状态变化时缓存的坐标，不增加
逐帧场景扫描。

## 发布门槛

自动化需覆盖空家具安装、多储物格锁定、失败回滚、免费取回、2000 找回、未加载区域、
旧存档迁移、物理桥接、MP 并发与幂等。完成后运行统一历史回归、编码检查、参考研究
检查和全部 Lua 5.1 编译。B42.19 实机仍需验证真实家具容量 0、存档重载、区块卸载、
SP/MP 容器同步及旧控制器迁移。
