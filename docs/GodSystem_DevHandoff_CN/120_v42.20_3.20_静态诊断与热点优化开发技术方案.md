# v42.20_3.20 静态诊断与热点优化交接

日期：2026-09-29。目标游戏 B42.20.4；源码基线为尚待实机验收的 3.19，保留全部现有玩法、价格与存档身份。3.18.4 仍是已验收滚动备份。本版开发后只同步 Workshop 测试副本。

## 问题与修复

玩家未提供编译器名称或原始诊断，无法复现其报告。开发初检的 140 个运行包 Lua 文件均通过 Lua 5.1 和目标 Kahlua 编译；LuaLS 3.19.1 在缺少类型声明时提示 1 处多传参数、80 条未使用局部变量／参数以及大量 PZ 注入 API 未定义。这些静态提示不等于游戏编译错误。

- 外部直接回收：修正原生调用桥将合法 `false` 吞为默认允许的错误；`SafeHouse.isSafeHouse` 按安全屋对象／空值判断，`haveThisKeyId` 按钥匙物品／空值判断。身份、访问、物品存在和移除权限读取失败时拒绝交易。读取对象成员也经受保护路径。删除前重新验证身份、来源、距离与权限；事务回执和失败恢复沿用 3.19。
- 地面散落物：一次请求按地块建立物品 ID 索引，重复 ID 标为不可用；每个地块只遍历一次来定位。索引不跨请求保存，成功删除后更新，失败恢复后重新核对。原生删除、同步与删除后验证仍可能随同格数量增加，不能据此声称整个回收交易为线性时间。
- 静态缺陷：删除 `canRecycleItem(item, false)` 的多余实参；按原版签名修正一处 `ISLabel:setColor` 多余 alpha 参数；移除确实无用的私有参数／状态和重复价格、协议及桥接键；修复 Lua 点号模式。回调和公开接口的必要参数位置保留，刻意忽略的参数改以 `_` 命名。配置有效值和协议表与原版基线一致。
- 搜索：说明书、医疗／特质、转换关系、回收和旧商城列表复用字段拼音索引；查询词只规范化一次。原字段变化时重建对应索引；金额等动态字段不读旧缓存。缓存按用途设置条数及 2 MiB 文本上限，关窗／切换会话释放。
- 全物品目录：读取仍每步最多 64 条，归并最多 128 次，两者在记录之间检查约 2 ms 时间预算；语言变化在私有快照分批改名和排序，完成后一次切换。过期代次或旧会话结果不得覆盖新目录；保留已显示的选择、页码与滚动。当前 64 条初始 `table.sort` 是不可中断的原生调用，极端游戏帧耗时仍需实机观察。

## 开发期诊断工具

`python tools/analysis/setup.py` 将锁定的 LuaLS 3.19.1 与 Umbrella 42.20.0 下载至忽略的 `.test-runtime/analysis` 并校验 SHA-256；运行包不包含分析器。`python tools/analysis/check.py` 输出完整诊断到 `.test-runtime/analysis/summary.json`。`pwsh tools/Test-GodSystem.ps1` 调用同一检查，工具缺失明确失败。Umbrella 只提供邻近补丁类型线索；B42.20.4 原生语义以本地游戏类签名、原版脚本及行为测试为准。

`tools/analysis/reviewed-parameters.json` 对剩余参数提示逐条记录原因，新增未归类的参数提示会令检查失败；多余参数、重复表索引、错误转义和语法诊断必须清零。刻意保留的 `_参数` 属于事件／UI 回调或多返回值占位；静态分析器仍提示，详见完整报告。其他 PZ 注入字段、空值收窄、旧类型声明的提示作为待核查报告，不视作全部排除。没有全局关闭这些诊断。

LuaLS 复跑的参数类型提示在 13–15 条之间波动，已出现的 8 种签名均逐项核对：继承窗口的具体类型、动态特质令牌、异构终端控件、原版清除光标的 `nil` 参数，以及经 `finite()` 检查的可选数字。59 条未使用局部均为带 `_` 的事件参数或返回值占位；发现新的非 `_` 未使用局部或未使用私有函数会令检查失败。其余 1,000 余条提示中，原版运行环境注入字段与 Umbrella 42.20.0 类型不符者继续列在完整 JSON 中，未经逐项证实的不宣称已修复。

## 性能对比与局限

以下均为本机 Lupa Lua 5.1 **合成对象模拟**，不代表游戏中的 Java 删除或网络帧耗时。基线 3.19 同格 2,000 件的定位遍历 4,000,000 项、约 2,262 ms；本版定位遍历 2,000 项、约 29 ms。同格 5,000 件定位约 75 ms，但模拟删除与同步核对遍历 12,502,500 项、约 744 ms，失败恢复约 960 ms，仍是下一步可能需要优化的热点。模拟网络只计消息数，不模拟传输耗时。

5,000 行连续三次搜索的重建索引约 148 ms，热缓存约 12 ms；20,000 行分别约 546 ms 与 62 ms。20,000 行目录首次累计构建约 434 ms，最大单步约 2.1 ms；语言重排累计约 426 ms，最大单步约 2.3 ms。预算是在记录之间检查，GC 和单次原生调用可使单步超过 2 ms。数据文件为 `.test-runtime/v320-performance.json`（仅开发机临时产物）。
