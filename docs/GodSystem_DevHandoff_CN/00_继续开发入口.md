## 当前运行结构

```text
Bootstrap / Composition
├─ Platform：PZ 事件、命令、ModData、库存、场景对象适配
├─ Services：结果、操作 ID、日志、通知、时间等稳定能力
├─ Features：独立业务模块
│  ├─ Wallet / Bank / Tasks / Shop / Recycle
│  ├─ Attributes / Upgrades / Medical / Home
│  ├─ Terminal / Storage / AutoLoader / Maintenance
│  └─ Companion / Admin / System
├─ Runtime：统一用例调度、SP 本地执行、MP 远程执行
└─ UI：Facade、ReadModel、页面注册和动作适配
```

依赖只能从启动器流向平台/服务、功能、视图模型和 UI 外壳，不允许功能模块直接读取另一个功能模块的内部状态。

## 开发硬规则

- 核心只装配依赖和生命周期，不实现具体业务。
- 功能模块使用 `create(dependencies)`、`start(runtime)`、`stop(reason)`、`health()`。
- 跨模块调用使用显式注入的窄接口，禁止直接引用另一个功能实现文件。
- SP 和 MP 复用同一业务用例；MP 只增加远程执行和服务端结果同步。
- 当前协议只接受完全一致的 `42.20.1.2`，不支持混合版本。
- 只保留 `42.20.1.1 → 42.20.1.2` 迁移；未发布中间版本不保留兼容代码。
- 事务回滚、操作防重、有限数校验和物品生命周期复验属于运行安全，不能当成历史兼容代码删除。
- 不恢复旧 `GodSystem_Server.lua`、`GodSystem_Network.lua`、`GodSystem_Protocol.lua`、`GodSystem_RuntimeMode.lua`、`GodSystem_StorageManager.lua` 或旧 `safeAll` 路线。
- 不恢复 v1.16.69 Moveable 控制器、v1.16.70 容量锁宿主或已经废弃的压缩路线。
- 不主动增加防作弊体系；服务端逻辑只保证运行稳定、事务一致和不复制/不丢失物品。

## 验证与交付

每次提交前运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\Test-GodSystem.ps1
```

自动测试通过不等于实机通过。最终发布前至少完成：

- B42.20 新档和 `42.20.1.1` 旧档迁移。
- SP 退出重进、死亡重生及全部主要页面。
- MP 两名玩家、重连、服务器重启及重复请求。
- 商城/回收/银行/任务/升级等付费与发物事务。
- 终端、仓库网络、自动装填和机器人绘制。
- 单模块故障时其他独立模块仍可打开并在诊断页显示原因。

Workshop 测试目录只是部署副本；开发和提交必须以 Git 工作树为准。
