# v1.16.64 系统仓库网络实现

## 版本边界

- 基线：`main@9aa9f09`（v1.16.63 已发布兼容基线）。
- 分支：`feature/v1.16.64-storage-network`。
- 本版不修改现有系统空间终端、负重、商城、回收、机器人、任务或经济数值。
- 首版不接入原版合成、实体线路、车辆、便携背包、尸体、地面物品栏、后台自动整理或空间终端远程访问。

## 核心结构

| 模块 | 职责 |
|---|---|
| `GodSystem_Storage.lua` | 稳定身份、世界容器解析、分类/状态、冷藏判定、路由、有界索引、单件搬运与三级恢复 |
| `GodSystem_StorageManager.lua` | 全局 ModData、网络/令牌/连接、权限、快照缓存、SP/MP 共用业务事务、操作ID缓存 |
| `GodSystem_StorageServer.lua` | 独立多人协议、服务端命令、分组分包和真实物品权威移动 |
| `GodSystem_StorageClient.lua` | SP直接调用与MP命令桥接、快照拼装、详情按需加载 |
| `GodSystem_StorageUI.lua` | 独立大型仓储/容器管理窗口、客户端组合筛选和排序 |
| `GodSystem_StorageContext.lua` | 地面控制器、连接模式、具体容器选择、库存所选物品存入 |

主服务文件只新增 `require "GodSystem_StorageServer"`，避免继续逼近 Lua 5.1 单 chunk 200 个顶层 local 上限。

## 身份与持久化

- 控制器物品：`GodSystem.StorageController`，`base:normal`，没有容量字段，复用系统空间终端图标与原版 `CarBatteryCharger` 世界模型。
- 全局存储键：`GodSystem_CN_Data_StorageNetworkV1`。
- 网络保存 `networkId`、范围、连接上限、控制器令牌、控制器最后位置、连接表和修订号。
- 连接保存 `linkId`、父对象 `objectId`、固定坐标、具体容器槽位、贴图、名称、角色、优先级和分类允许/拒绝规则。
- 父对象 ModData 保存按槽位区分的连接标识；解析时必须同时匹配 `objectId + linkId + slotIndex`。同坐标放置的新家具没有旧标识，因此只能保持离线。
- 找回控制器只轮换令牌并生成新物品；旧控制器失效，网络和真实物品不删除。

## 权限

- 安全屋内按安全屋稳定键限制一套网络。
- 安全屋主人、成员和管理员可存取；创建者/主人和管理员可管理。
- 安全屋控制器移到外部时不改写原网络身份，只临时退化为创建者/管理员可用；搬回原安全屋后恢复成员共享。
- 个人网络只允许创建者和管理员使用。
- 管理员可在每套网络内把半径限制到1—60、连接上限限制到1—128，并可接管网络。

## 索引与界面

- 只在打开、手动刷新、连接变化和总控事务后启动索引；没有 `OnPlayerUpdate`、分钟级或小时级仓库扫描。
- 每个 Tick 最多推进两个索引任务；每个任务单批最多250件或约2毫秒。
- 递归深度最大32，按容器对象访问集合防循环；默认最多索引20,000个实例。
- 服务端按物品类型聚合，分组每100条回传；实例详情只有选中分组时才请求。
- 客户端搜索和筛选只读取当前快照，支持名称、fullType、MOD、标签、分类、状态和来源容器；支持名称、数量、重量、耐久、腐烂时间和来源排序。
- 容器管理支持名称搜索、在线/离线/已满/冷藏筛选、角色、优先级、分类规则、离线清理和管理员参数。

## 存取和恢复

- 安全存入全部跳过穿戴、手持、快捷栏、收藏、钥匙、控制器、系统空间终端和内部减载核心。
- 选中存入通过原版库存右键菜单提交真实 `item:getID()`。
- 易腐物优先真实通电的冰箱/冰柜；没有可用冷柜时降级到食品/通用容器并计数，不写温度、年龄或腐烂字段。
- 取出默认按快照中的优先顺序：易腐物较早腐烂优先、装备高耐久优先、消耗品高剩余量优先。
- 批量取出先对请求中的实例ID执行一次最多20,000件的有界实时查找，不对每件物品重复扫描整座仓库；每件搬运仍会复验真实来源和目标接受规则，再执行“移除并确认、加入并确认”。失败时依次尝试原容器、玩家背包、控制器所在方格。
- MP 同一时刻的命令由服务端顺序执行；第二名玩家取同一物品时会因来源复验失败而跳过。
- 付费无关但具有复制风险的变更命令仍使用 `opId + fingerprint`；完成结果缓存一小时，重复请求只回放结果。
