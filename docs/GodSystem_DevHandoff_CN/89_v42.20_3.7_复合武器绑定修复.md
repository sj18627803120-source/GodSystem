# 3.7 复合武器绑定修复（2026-09-14）

用户明确反馈：带头部耐久、锋利度的武器被拒绝绑定；绑定与特效不应依赖旧属性读取。修改留在正式 GodSystem-main，版本仍为 42.20_3.7，未部署、发布或替换 ZIP。

## 代码确认的原因

- EquipmentItems.durability 调用 getMaxSharpness，但 B42JavaCalls 缺少显式包装。普通 Lua table 会走 fallback，实际 Java userdata 不会，造成锋利度快照失败。
- EquipmentService 把完整耐久快照和 ConditionMax <= 127 当作绑定前提；即使 3.6 已移除伤害等原始参数，这个旧门槛仍然存在。
- 本机 B42.20.4 projectzomboid.jar 的 InventoryItem.getMaxSharpness 确实存在；有头部时返回头部耐久比例，否则为主体耐久比例。setSharpness 受此动态上限约束，不能简单替换成固定 1。

## 本次改变

- 补齐 getMaxSharpness 显式 Java 包装。
- 耐久快照允许缺省；合法物品身份、归属、具体物品 ID、有效槽位与代次仍负责绑定和特效授权。保留现有枪械绑定行为，不按武器类别标签数量限制近战武器。
- 绑定、特效培养、改名和解绑不因无法读取耐久或耐久上限超过 127 而失败。缺省耐久也不会使重载后的装备档案无效；已有但损坏的耐久快照仍严格校验。
- 修复和找回仍要求安全耐久快照，不支持时在收费前拒绝；不会凭空生成未知耐久。当前物品失去耐久读取能力时清除旧快照，避免依赖过期数据重建。
- 非耐久操作回滚只恢复其标记和名称，不调用耐久 setter；修复失败仍完整恢复耐久。
- CN/CH/fallback 绑定失败说明已从“属性或耐久不受支持”改为档案建立失败，并统一生成。
