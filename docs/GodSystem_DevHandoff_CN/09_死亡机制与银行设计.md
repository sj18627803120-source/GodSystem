# 死亡机制与银行设计笔记

更新时间：2026-06-18

## 死亡机制必须作为长期检查项

Project Zomboid 死亡后可能创建新的角色对象，角色总击杀数、身上物品、天赋、部分角色状态都会变化。后续新增或修改 GodSystem 功能时，必须先判断数据属于“账号级”还是“角色级”。

账号级建议保留：系统数据、任务列表、家园点、临时点、解锁项、升级、银行账户、历史记录。

角色级需要特别处理：身上实体系统币、系统腰包实体物品、当前角色天赋、击杀计数基线、移动距离基线、出发点、存活类任务语义。

## 当前功能的死亡风险

- 实体系统币会随游戏死亡机制留在尸体或掉落容器里，看起来像“系统币莫名没了”。代码层面 v1.16.8 已加固扣币回滚，但不能阻止游戏本身移动尸体物品。
- 击杀任务不能只用 `player:getZombieKills() - task.startKills`。v1.16.8 已改为 `task.killProgress` 独立累计，并在 MP 死亡前 flush `pendingKillDelta`。
- 单人模式仍要注意：如果击杀后马上死亡，而 `OnPlayerUpdate` 尚未跑到下一次 60 tick，理论上仍可能漏记临死前少量击杀。后续若继续加固，可给 SP 也加 `OnPlayerDeath` flush/normalize。
- 移动距离任务死亡重生后坐标可能大跳。当前 `distance < 80` 才累计，大跳会被忽略并刷新基线，方向基本安全。
- v1.16.18 起，角色死亡会让当前所有进行中任务失败，不再只处理存活任务。
- 天赋改造属于角色级。死亡创建新角色后，购买过的天赋大概率不会自动继承，除非另做账号级已购天赋列表并在 `OnCreatePlayer` 重套。
- 家园出发点 `home.returnPoint` 当前会保留。若玩家传回家后死亡，出发点可能指向危险地点或尸体附近；后续可考虑死亡时自动清空，或传送前加死亡风险提示。
- 系统腰包是实体物品。死亡后可能留在尸体上；账号数据仍记录已领取/等级/开关。现有找回逻辑需要继续测试死亡后是否符合预期。
- 多人网络状态死亡后应检查 `sentHello`、pending 命令、kill baseline、UI state 是否需要重置，避免新角色沿用旧角色对象相关状态。

## v1.16.8 对两条 MP 反馈的定位

反馈 1：多人模式天赋改造没反应，但不扣钱。

当前最新 v1.16.8 仍可能遇到。服务端 `Commands.trait` 使用 `player:getCharacterTraits():add/remove(traitType)`，其中 `traitType` 是客户端传来的字符串。B42 参考 `TraitsPurchaseSystem` 会先通过 `CharacterTraitDefinition.getTraits()` 找到 trait，再传 `trait:getType()` 给 `getCharacterTraits():add/remove()`。如果 GodSystem 传入字符串不被接受，就会失败并退款，表现为“没反应但不扣钱”。

反馈 2：多人模式家园传送扣钱但没传送。

当前最新 v1.16.8 仍可能遇到。服务端 `Commands.home` 在传送动作中先调用 `spendHomeCostCode()` 扣钱并写历史，再执行 `player:setX/setY/setZ`。如果 MP 中服务端直接改坐标没有推动客户端，或被位置同步拉回，就会出现扣钱但人没动。

建议下一轮 v1.16.9 优先修：

- MP 天赋：服务端按 B42 参考方式解析 `CharacterTraitDefinition`，用 `trait:getType()` 修改；失败时返回明确中文提示。
- MP 传送：改为服务端校验钱够/落点安全后，发 S2C 批准给客户端执行本地 `teleportTo` 或坐标移动；客户端确认后服务端再扣费和保存出发点，避免“扣了但没动”。
- 死亡事件：统一清理/重置需要按角色对象重建的运行态，例如 pending、击杀基线、移动基线；是否清空出发点等待设计确认。

## 银行功能设计草案

银行适合解决“死亡后实体系统币丢在尸体上”的体验问题。推荐把银行余额做成账号级 GodSystem 数据，和实体系统币分开。

基础规则：

- 存款：从玩家真实背包移除实体系统币，增加银行余额。
- 取款：减少银行余额，向玩家背包发放实体系统币。
- 活期：随时存取，不计或低利息。
- 死期：创建固定存单，记录本金、开始时间、到期时间、利率、提前取出惩罚。
- 死亡惩罚：死亡时只扣银行活期 30%，死期不直接扣；需要防止一次死亡重复扣罚。
- 任务失败惩罚：失败、超时、手动放弃、死亡失败都先扣银行活期，不足再扣身上实体系统币；扣款不允许出现负数，余额不足也不阻止任务判定失败。
- UI 必须清楚显示：实体现金、活期余额、死期本金/到期收益、提前取出损失、死亡惩罚规则。

多人实现建议：

- 客户端负责 UI 和输入金额。
- 服务端验证存款时确实有足够实体系统币，验证取款时银行余额足够，验证后修改实体物品和银行数据。
- 利息按游戏世界小时计算更贴合 PZ；如果要防挂机刷利息，可限制每日/每档利息上限。
- 死亡惩罚可由客户端 `OnPlayerDeath` 通知服务端执行；当前项目防作弊不是优先级，但要加死亡时间/序号冷却防重复扣。

## 银行与死亡规则当前结论

1. 银行默认开放。
2. 死亡只扣活期，v1.16.18 起比例为 30%，不会扣到负数。
3. 死期按游戏时间计算。
4. 死期档位为 1 / 3 / 7 天。
5. 提前取死期无利息，并扣一部分本金。
6. 暂不限制最低存款额和最高存单数量。
7. 死亡暂不自动清空家园出发点，仍由玩家手动删除。
8. v1.16.18 起死亡会让所有当前进行中任务失败。
9. 已购买天赋仍按当前角色一次性消费处理，不在死亡后自动继承。
