# 3.8 验收修复与多人传送

日期：2026-09-15。源码仍为 GodSystem-main，版本 42.20_3.8，目标 B42.20.4。
本轮修复已进入用户实机测试阶段。没有提交、部署、发布、修改游戏启动参数或替换备份。交接 91、92 保留为历史实现与失败验收记录，本文件说明本轮最终状态。

## 多人传送的最终选择

用户要求保持纯 Lua，不增加服务端原生组件，并尽可能支持普通玩家。

实现流程：普通玩家请求家园/临时点/返回点 → 服务端从自己的档案读取目标并检查功能、车辆、余额 → 查找在线执行者 → 预扣费用 → 向执行者发送限定的传送请求 → 执行者调用原版 `SendCommandToServer('/teleportto "目标用户名" x,y,z')` → 游戏服务器执行原生传送 → MOD 观察目标玩家的服务器位置并完成结算。

执行者优先为申请者本人（已有原版坐标传送权限）；否则选择同时拥有 `TeleportToCoordinates` 和 `TeleportPlayerToAnotherPlayer` 权限的在线管理员。普通目标玩家不获得管理员权限。MOD 不接受客户端指定的目标坐标、执行者或任意管理员指令。用户名禁止引号、反斜杠和控制字符，坐标必须是有限数。

**明确限制：必须有具备相应原版权限的执行者在线。** 无人可执行时立即提示、不位移、不扣费。尚未证明普通玩家在无管理员在线的纯 Lua 专用服上可以安全传送；不把此情况列为已解决。房主是否具备所需能力取决于实际原版角色权限，不能仅凭“房主”称呼推断。

每个目标账号只有一个进行中的传送。客户端保留最近 64 个执行回执防止重复发送原版命令；服务器只接受被选中执行者的回执，且回执不代表已到达。服务器最多等待 15 秒，真实坐标到达后才记消费和返回点；失败退还原始银行/现金来源。目标离线时，将预扣金额完整退入该账号银行，避免向离线背包发货。服务器重启后遗留预扣在账号下次上线时取消退款。

本轮未开启 debug、未关闭任何反作弊规则，也没有写入 Workshop 或游戏目录。

## 其他修复

- 装备候选不再使用始终返回拒绝码的 Lua `and nil or` 表达式。缺失本体、头部、锋利度资料分别说明；旧档案详情和锋利度判定补空值保护，培养等级与身份不迁移。
- 原版弹窗按 target/button/quote 顺序处理；单人也先确认批量实际总价，多人旧报价刷新后重新确认。关闭涨价仍能正常报价、确认和购买。
- 在线时钟使用进程内会话基线；离线、重连、重启不补算世界时间间隔。单人在线心跳独立于银行理财。账号保留累计时钟与层数，服务器对重生/新玩家实例重新取基线。
- 世界级配置代次记录关闭操作，离线账号下次读取时清除旧层。涨幅、持续时间、启用状态和代次纳入报价配置版本。
- 一个账号保留一个待确认报价；单次购买最多处理 1000 份以限制单请求开销，不限制累计玩法层数。拒绝非有限数与安全金额/计数溢出。到期在整分钟的下一边界执行，最多晚一个游戏分钟，不提前失效。
- 冷门商品按每次最多 8 个商品分批清理，在线后台每 30 秒触发，不增加逐帧全商店扫描。多人投影包含价格记录，不同步私有报价令牌。
- 多人消费回执包含报价身份；失败回滚货物并按来源退款。任务奖励检查返回值，部分发放失败回滚已发物品，正常失败保留领取资格，已成功的奖励回执防重复。结果不明的原生异常标记为 unknown，不盲目补发。
- 任务超时检查不扫描交物任务背包；非交物任务完成时记录 completedAt。移动按实际采样间隔限制步行距离，重连/换角色/传送重设基线，不计车内位移。
- 实际终端接入涨价详情和负重诊断；负重详情本地低频更新倒计时。修复格式化函数名称，已确认 UCWF 来源与未知来源分开显示。收藏、最近购买及分类/搜索/选中商品偏好保留，搜索同步合并为停止输入后约 1 秒一次。

## 交给用户的简短测试

1. 管理员在线时，普通玩家分别测试回家、临时点和返回；确认目标玩家移动、管理员位置不变、不被踢，每次只扣一次费用。
2. 管理员离线后再次申请，确认提示无人执行且不扣费；管理员重新上线后恢复可用。传送中断线后确认预扣金额已退入银行。
3. 商店同商品连买/批量买 3 份，核对确认总价、扣款和下一份价格；取消、余额不足不增加层数。
4. 买出涨价层后下线，让另一位玩家在线推进游戏时间；重连确认离线期间未减少剩余在线时长。关闭涨价可正常买，重新开启从零层开始。
5. 普通及头部/锋利度复合武器测试绑定、修复、找回；任务手动/自动领取不重复发奖；重开商店确认偏好保留。
