# GodSystem 参考 MOD 研究库设计

## 目标

在 GodSystem GitHub 仓库中建立一套自包含、可检索、可追溯的 Project Zomboid 参考 MOD 研究库。另一台没有本地参考 MOD 文件的设备只需克隆仓库，即可了解各参考 MOD 的实现机制、适用版本、接口证据、联机边界和采用风险，并将稳定经验用于后续 GodSystem 开发。

## 范围

本轮覆盖 `File` 目录中的 11 个参考来源：

1. `1299328280`（More Traits 及其可选模块）
2. `CAExtendedCategories`
3. `CaiGou's Shop`
4. `CultivationStorageArtifacts`
5. `damnlib`
6. `DebugMenu`
7. `PsionicAwakeningB41`
8. `RuinBazaar`
9. `Server Shop`
10. `TraitsPurchaseSystem`
11. `YeseMarket`

同一来源存在多个历史版本时，以本地最新可用版本为主要研究对象。旧版本只记录会影响 B42.19 判断的接口差异、兼容变化或已废弃实现，不重复逐文件描述。

## 信息架构

新增目录 `docs/reference-mod-research/`：

- `README.md`：研究库入口、证据规则、主题索引和使用方法。
- `catalog.md`：来源名称、MOD ID、作者、版本、目标游戏版本、研究状态和联网搜索关键词。
- `mods/*.md`：每个参考来源一份独立报告。

每份来源报告统一包含：

1. 身份与版本
2. 主要功能和目录结构
3. 关键文件与符号证据
4. 单人/多人数据流
5. 可复用机制
6. 不应直接照搬的实现
7. 对 GodSystem 的具体启发
8. 仍需官方文件或实机验证的内容
9. 联网搜索关键词

现有文件同步更新：

- `docs/GodSystem_DevHandoff_CN/08_参考MOD研究笔记.md` 改为快速索引和 GodSystem 已采用结论入口，不继续无限扩张为单体长文档。
- `tools/codex/skills/pz-mod-dev/references/pz-b42-patterns.md` 接收跨 MOD、可复用且已有证据的稳定规则。
- `tools/codex/skills/pz-mod-dev/SKILL.md` 只保留工作流级规则和研究库入口，不复制全部来源细节。
- `docs/GodSystem_DevHandoff_CN/00_继续开发入口.md` 增加研究库入口，确保另一台 Codex 能发现资料。

## 证据标准

每项关键结论必须标注以下一种证据等级：

- `代码确认`：已在本地参考源码中找到明确文件、函数、事件或字段。
- `作者声明`：只来自 `mod.info`、Workshop 描述或作者注释，尚未通过运行验证。
- `合理推断`：根据调用链得出的工程判断，必须说明推断依据，不能写成已发生的问题。
- `待实机验证`：静态代码不足以确认，必须在目标游戏版本或多人服务器中测试。

版本可信度单独标注：

- `B42.19 同版本证据`
- `旧 B42 参考`
- `B41 弱参考`

社区 MOD 的实现不能高于当前 B42.19 原版脚本和已验证实机结果。没有玩家报告的问题不得直接表述为已知 BUG；例如客户端直接转移物品应记录为潜在事务风险，而不是断言必然不同步。

## 内容边界

- 不上传参考 MOD 源码、贴图、音效、模型或完整配置文件。
- 不复制大段第三方代码；只记录相对文件路径、符号名、接口签名、短小伪代码和行为摘要。
- 不把第三方作者声明当作 GodSystem 的兼容承诺。
- 不依赖 `C:\Users\Admin` 等本机绝对路径；报告中的来源文件使用参考 MOD 内部相对路径。
- 对许可不明确或禁止再分发的 MOD，只做事实性研究摘要。
- 研究工作不修改 GodSystem 运行代码、Workshop 测试文件或当前 MOD 版本号。

## 提炼方法

每个来源按以下顺序审计：

1. 读取最新 `mod.info`、依赖、版本目录和翻译结构。
2. 建立 Lua、物品脚本、沙盒设置和资源入口清单。
3. 使用关键词定位事件注册、网络命令、库存变化、ModData、UI、计时器和动态脚本修改。
4. 只读取关键调用链上下文，不将文件数量当作研究质量。
5. 将结论写入来源报告，并标注证据等级和版本可信度。
6. 与 B42.19 原版或 GodSystem 已验证实现冲突时，明确降级为旧版本参考。
7. 只有至少一个明确源码证据且具有跨项目价值的结论，才写入便携版技能。

## 重点主题

研究库必须能够按以下主题检索：

- SP/MP 入口隔离、命令分发、状态同步和服务端权威
- 商店、回收、发货、退款、审计和离线队列
- 容器容量、穿戴槽、嵌套容器、重量减免和物品恢复
- 天赋、动态特质、技能 XP 和 MOD Perk 枚举
- 物品分类、隐藏/debug 过滤、ItemType 和脚本兼容
- UI 生命周期、选择恢复、滚动列表和上下文菜单
- 车辆、物品生成、Debug 接口和原版功能复用
- 事件频率、递归扫描、缓存、全局脚本修改和性能风险
- B41 到 B42 的弱兼容模式与不可继续使用的旧接口

## 验证

新增文档专项检查，至少验证：

- 11 个来源均有报告并被总目录引用。
- 每份报告包含身份、证据、可采用、风险和待验证部分。
- 新研究库不包含本机绝对路径、替换字符或明显乱码。
- 目录链接有效，MOD ID 和目标版本与本地 `mod.info` 一致。
- `pz-b42-patterns.md` 中新增规则能够追溯到至少一份来源报告。
- 仓库没有新增第三方 Lua、贴图、模型或大体积参考 MOD 文件。
- GodSystem 运行目录和版本号没有变化。

## Git 规则

- 文档研究继续在 `feature/v1.16.57-carry-recycle` 上进行，不合并 `main`。
- 研究库使用独立、聚焦的文档提交；必要时按来源批次提交，便于审阅和回滚。
- 完成静态验证后推送当前功能分支到 GitHub，供另一台 Codex 直接读取。
- 本轮不覆盖 Workshop 目录，因为没有运行时文件变化。

## 完成标准

另一台没有本地参考 MOD 的 Codex 能够仅根据 GitHub 仓库：

1. 找到全部 11 个来源的版本和功能地图。
2. 查询某个 PZ 开发主题对应的参考实现和风险。
3. 分辨已确认事实、作者声明、工程推断和待测试内容。
4. 遵循更新后的 `pz-mod-dev` 规则实现 GodSystem 功能，而不需要复制第三方源码。
